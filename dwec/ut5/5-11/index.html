5.11 Funciones recursivas

Hasta ahora hemos utilizado funciones que realizan una tarea y devuelven un resultado. También hemos aprendido a pasarles argumentos, trabajar con variables locales y utilizar funciones como valores.

Sin embargo, existe una técnica de programación en la que una función puede llamarse a sí misma para resolver un problema. Esta técnica recibe el nombre de recursividad.

La recursividad resulta especialmente útil cuando un problema puede dividirse en otros problemas más pequeños que tienen la misma estructura que el original.

En este apartado aprenderemos cómo funcionan las llamadas recursivas, por qué es imprescindible establecer una condición de finalización y cómo aplicar esta técnica a problemas habituales de programación.

📌 Importante

Una función recursiva es una función que se llama a sí misma, directa o indirectamente, para resolver un problema mediante versiones más pequeñas de ese mismo problema.

Para que funcione correctamente, debe existir una condición que permita detener las llamadas.

Qué es la recursividad

Imagina que queremos mostrar los números desde 5 hasta 1. Una forma de hacerlo sería utilizar un bucle.

JavaScript — Solución con un bucle 
for (let numero = 5; numero >= 1; numero--) {
  console.log(numero);
}

Este programa comienza en 5 y reduce el valor de numero en cada iteración, hasta llegar a 1.

También podemos resolverlo mediante una función que muestre un número y después se llame a sí misma con el número anterior.

JavaScript — Primera función recursiva 
function cuentaAtras(numero) {
  if (numero === 0) {
    return;
  }

  console.log(numero);

  cuentaAtras(numero - 1);
}

cuentaAtras(5);
Resultado en consola 
5
4
3
2
1

Observa que dentro de cuentaAtras() aparece una llamada a la propia función:

JavaScript — Llamada recursiva 
cuentaAtras(numero - 1);

Cada llamada recibe un valor más pequeño. Cuando el valor llega a 0, la función termina y no realiza nuevas llamadas.

💻 Ejemplo DAW

La recursividad puede utilizarse para recorrer estructuras jerárquicas, como categorías y subcategorías de una tienda online, carpetas que contienen otras carpetas o comentarios que tienen respuestas anidadas.

Estructura de una función recursiva

Aunque las funciones recursivas pueden resolver problemas muy diferentes, normalmente contienen dos elementos fundamentales:

  1. Caso base: condición que permite terminar la función sin realizar otra llamada recursiva.
  2. Caso recursivo: parte de la función que vuelve a llamarse para resolver una versión más pequeña del problema.

Podemos representar su estructura general así:

JavaScript — Estructura general 
function funcionRecursiva(valor) {
  // Caso base
  if (condicionDeFinalizacion) {
    return resultadoBase;
  }

  // Caso recursivo
  return funcionRecursiva(valorMasPequeno);
}

Este código representa únicamente un esquema. Las condiciones, los parámetros y los resultados dependerán del problema que queramos resolver.

El caso base

El caso base establece cuándo debe finalizar la recursividad. Es el punto en el que el problema ya puede resolverse directamente.

En el ejemplo de la cuenta atrás, el caso base es:

JavaScript — Caso base 
if (numero === 0) {
  return;
}

Cuando numero vale 0, se ejecuta return, finaliza esa llamada y no se vuelve a invocar la función.

El caso recursivo

El caso recursivo realiza una nueva llamada utilizando datos que acercan el problema al caso base.

JavaScript — Caso recursivo 
cuentaAtras(numero - 1);

En este caso, cada llamada reduce numero en una unidad.

⚠️ Atención

No basta con incluir un caso base. También debemos asegurarnos de que cada llamada recursiva se aproxima a él.

Si el argumento no cambia o cambia en la dirección equivocada, la función puede continuar llamándose hasta agotar la pila de ejecución.

Primer ejemplo: cuenta atrás

Vamos a analizar con detalle el ejemplo anterior.

JavaScript — Cuenta atrás 
function cuentaAtras(numero) {
  if (numero === 0) {
    return;
  }

  console.log(numero);

  cuentaAtras(numero - 1);
}

cuentaAtras(3);

La primera llamada recibe el argumento 3.

Como 3 !== 0, se muestra el número 3 y se realiza una nueva llamada con 2.

La segunda llamada muestra 2 y vuelve a llamar a la función con 1. Después ocurre lo mismo con 1.

Finalmente, la llamada que recibe 0 cumple el caso base y termina.

Resultado en consola 
3
2
1

¿Qué sucede si no establecemos el caso base?

Considera el siguiente ejemplo incorrecto:

JavaScript — Ejemplo incorrecto, no ejecutar 
function cuentaAtras(numero) {
  console.log(numero);

  cuentaAtras(numero - 1);
}

// No ejecutar:
// cuentaAtras(3);

Esta función no contiene ninguna condición de finalización. Por tanto, continuaría llamándose con valores cada vez menores.

En algún momento, JavaScript interrumpiría la ejecución porque se habría superado el espacio disponible para las llamadas.

📌 Importante

Toda función recursiva debe tener un caso base alcanzable. Además, el caso recursivo debe modificar los datos de forma que se llegue a él.

Seguimiento de las llamadas recursivas

Una de las principales dificultades al aprender recursividad es comprender qué sucede durante las distintas llamadas.

Para ello, resulta útil seguir paso a paso los argumentos que recibe la función.

JavaScript — Seguimiento de llamadas 
function mostrar(numero) {
  if (numero === 0) {
    console.log("Fin");
    return;
  }

  console.log("Número:", numero);

  mostrar(numero - 1);
}

mostrar(3);
Llamada Valor recibido Acción
1 3 Muestra 3 y llama con 2.
2 2 Muestra 2 y llama con 1.
3 1 Muestra 1 y llama con 0.
4 0 Muestra «Fin» y termina.
Resultado en consola 
Número: 3
Número: 2
Número: 1
Fin

En este ejemplo, las instrucciones console.log() aparecen antes de la llamada recursiva. Por eso los números se muestran mientras se van realizando las llamadas.

¿Y si mostramos el número después de la llamada?

Observa este pequeño cambio:

JavaScript — Instrucción después de la llamada 
function mostrar(numero) {
  if (numero === 0) {
    return;
  }

  mostrar(numero - 1);

  console.log(numero);
}

mostrar(3);
Resultado en consola 
1
2
3

Ahora los números aparecen en orden ascendente. ¿Por qué?

Porque cada llamada queda esperando a que termine la siguiente. Cuando se alcanza el caso base, las llamadas comienzan a finalizar en orden inverso.

📌 Importante

La posición de las instrucciones respecto a la llamada recursiva influye en el resultado.

Una instrucción situada antes se ejecuta al avanzar en las llamadas. Una instrucción situada después se ejecuta cuando esas llamadas van terminando.

Cálculo del factorial de un número

Uno de los ejemplos clásicos para comprender la recursividad es el cálculo del factorial.

El factorial de un número entero no negativo se obtiene multiplicando ese número por todos los enteros positivos menores que él.

Por ejemplo:

  • 3! = 3 × 2 × 1 = 6
  • 4! = 4 × 3 × 2 × 1 = 24
  • 5! = 5 × 4 × 3 × 2 × 1 = 120

Por definición, el factorial de cero también es igual a uno: 0! = 1.

Resolución mediante recursividad

Observa que podemos expresar el factorial de 5 de la siguiente manera:

5! = 5 × 4!

Del mismo modo:

4! = 4 × 3!

Es decir, el cálculo de un factorial depende del factorial del número anterior. Esta relación permite utilizar una función recursiva.

JavaScript — Factorial recursivo 
function factorial(numero) {
  if (numero === 0) {
    return 1;
  }

  return numero * factorial(numero - 1);
}

console.log(factorial(4));
Resultado en consola 
24

La función contiene los dos elementos fundamentales de la recursividad:

  • Caso base: si el número es 0, devuelve 1.
  • Caso recursivo: devuelve el número multiplicado por el factorial del número anterior.

Seguimiento del factorial de 4

Para comprender cómo se obtiene el resultado, podemos desarrollar las llamadas:

Desarrollo de las llamadas 
factorial(4)
= 4 * factorial(3)
= 4 * 3 * factorial(2)
= 4 * 3 * 2 * factorial(1)
= 4 * 3 * 2 * 1 * factorial(0)
= 4 * 3 * 2 * 1 * 1
= 24

Primero se realizan las llamadas hasta alcanzar factorial(0). Después se van calculando los resultados pendientes.

Validación de los argumentos

El ejemplo anterior presupone que recibe un entero no negativo.

Sin embargo, una función destinada a utilizarse en una aplicación debe comprobar los valores recibidos para evitar comportamientos incorrectos.

JavaScript — Factorial con validación 
function factorial(numero) {
  if (!Number.isInteger(numero) || numero < 0) {
    return NaN;
  }

  if (numero === 0) {
    return 1;
  }

  return numero * factorial(numero - 1);
}

console.log(factorial(5));
console.log(factorial(0));
console.log(factorial(-3));
console.log(factorial(2.5));
Resultado en consola 
120
1
NaN
NaN

Utilizamos Number.isInteger() para comprobar que el argumento sea un entero y verificamos que no sea negativo.

⚠️ Atención

Esta validación evita valores negativos y decimales, pero no elimina las limitaciones de la recursividad ni de la precisión numérica.

Por ejemplo, los factoriales crecen muy deprisa. En JavaScript, 171! supera el rango finito del tipo Number y produce Infinity.

La pila de ejecución y las llamadas recursivas

Para comprender completamente la recursividad, debemos conocer cómo gestiona JavaScript las llamadas a funciones.

Cuando se invoca una función, JavaScript necesita conservar información sobre esa llamada, como sus parámetros, variables locales y el punto al que debe regresar cuando termine.

Esta información se organiza mediante una estructura denominada pila de llamadas o call stack.

Podemos imaginarla como una pila de platos: el último que colocamos es el primero que retiramos.

Ejemplo de funcionamiento

JavaScript — Entrada y salida de llamadas 
function explorar(numero) {
  console.log("Entrando:", numero);

  if (numero === 0) {
    return;
  }

  explorar(numero - 1);

  console.log("Saliendo:", numero);
}

explorar(2);
Resultado en consola 
Entrando: 2
Entrando: 1
Entrando: 0
Saliendo: 1
Saliendo: 2

El programa comienza ejecutando explorar(2), que llama a explorar(1). Esta, a su vez, llama a explorar(0).

Cuando se alcanza el caso base, la última llamada termina. Después se reanuda explorar(1) y, finalmente, explorar(2).

Momento Qué sucede
1 Comienza explorar(2).
2 Se llama a explorar(1).
3 Se llama a explorar(0).
4 explorar(0) termina.
5 Se reanuda y termina explorar(1).
6 Se reanuda y termina explorar(2).

Desbordamiento de la pila

La pila de llamadas tiene una capacidad limitada. Si una función realiza demasiadas llamadas anidadas, puede producirse un error.

En muchos navegadores, el mensaje será similar a:

Posible mensaje de error 
RangeError: Maximum call stack size exceeded

Este error puede producirse cuando no existe un caso base adecuado, cuando no se alcanza o cuando la recursividad es demasiado profunda.

📌 Importante

Cada llamada recursiva necesita recursos. Por eso, una solución recursiva no siempre es la más adecuada, especialmente si puede necesitar una cantidad muy elevada de llamadas.

Ejemplo: sumatorio recursivo

Vamos a resolver otro problema: calcular la suma de todos los números enteros desde 1 hasta un número dado.

Por ejemplo, si el número es 4, el resultado será:

1 + 2 + 3 + 4 = 10

Podemos observar que:

suma(4) = 4 + suma(3)

Por tanto, podemos construir una función que se llame a sí misma con el número anterior.

JavaScript — Sumatorio recursivo 
function sumarHasta(numero) {
  if (numero === 0) {
    return 0;
  }

  return numero + sumarHasta(numero - 1);
}

console.log(sumarHasta(4));
console.log(sumarHasta(6));
Resultado en consola 
10
21

Para sumarHasta(4), el proceso es:

Desarrollo del cálculo 
sumarHasta(4)
= 4 + sumarHasta(3)
= 4 + 3 + sumarHasta(2)
= 4 + 3 + 2 + sumarHasta(1)
= 4 + 3 + 2 + 1 + sumarHasta(0)
= 4 + 3 + 2 + 1 + 0
= 10

El caso base devuelve 0 porque es el valor que no modifica una suma.

⚠️ Atención

Esta implementación está pensada para enteros no negativos.

Si utilizamos un valor negativo, la función se alejará de 0 y no alcanzará el caso base. En una aplicación real debemos validar el argumento antes de iniciar el cálculo.

Recursividad con arrays

La recursividad no se utiliza únicamente para realizar operaciones matemáticas. También puede aplicarse a estructuras de datos, como los arrays.

Vamos a crear una función que calcule la suma de los elementos de un array.

Sumar elementos utilizando un índice

JavaScript — Suma recursiva de un array 
function sumarArray(numeros, indice = 0) {
  if (indice === numeros.length) {
    return 0;
  }

  return numeros[indice] +
         sumarArray(numeros, indice + 1);
}

const cantidades = [10, 20, 30, 40];

console.log(sumarArray(cantidades));
Resultado en consola 
100

En esta función intervienen dos parámetros:

  • numeros: array cuyos elementos queremos sumar.
  • indice: posición del elemento que estamos procesando. Su valor inicial es 0.

El caso base se alcanza cuando indice === numeros.length. En ese momento ya hemos procesado todos los elementos y devolvemos 0.

En cada llamada sumamos el elemento actual al resultado de procesar los elementos restantes.

Índice Elemento Operación pendiente
0 10 10 + sumarArray(..., 1)
1 20 20 + sumarArray(..., 2)
2 30 30 + sumarArray(..., 3)
3 40 40 + sumarArray(..., 4)
4 — Devuelve 0.

¿Qué sucede si el array está vacío?

Si llamamos a la función con un array vacío, su longitud es 0. Como el índice inicial también es 0, se cumple inmediatamente el caso base.

JavaScript — Array vacío 
console.log(sumarArray([]));
Resultado en consola 
0

Este comportamiento es correcto: la suma de los elementos de un array vacío es 0.

💻 Ejemplo DAW

En una aplicación de gestión de pedidos, podríamos utilizar una función de este tipo para calcular el importe total de un array de cantidades.

No obstante, para sumar un array sencillo normalmente resultaría más directo utilizar un bucle o reduce(). La recursividad se vuelve especialmente interesante cuando los datos contienen estructuras anidadas.

Cómo plantear un problema recursivo

Antes de escribir una función recursiva, conviene analizar el problema y responder a varias preguntas.

  1. ¿Cuál es el problema más sencillo? Debemos identificar una situación que podamos resolver directamente.
  2. ¿Cuál será el caso base? Necesitamos una condición que detenga las llamadas.
  3. ¿Cómo reducimos el problema? Cada llamada debe trabajar con una versión más pequeña o más próxima al caso base.
  4. ¿Qué devuelve cada llamada? Debemos decidir cómo combinar los resultados.
  5. ¿Podemos garantizar que terminará? Es necesario comprobar que el caso base se alcanzará con las entradas admitidas.

Por ejemplo, para calcular el factorial:

Pregunta Respuesta
¿Cuál es el caso más sencillo? Calcular 0!.
¿Cuál es el caso base? Si numero === 0, devolver 1.
¿Cómo se reduce el problema? Calculando el factorial de numero - 1.
¿Cómo se combinan los resultados? Multiplicando el número por el resultado recursivo.
¿Cuándo termina? Cuando el argumento llega a cero.
📌 Importante

Para diseñar correctamente una función recursiva, no debemos pensar solamente en que «la función se llama a sí misma».

Debemos identificar qué problema más pequeño resuelve cada llamada y cómo se obtiene la solución del problema original.

Recursividad frente a iteración

Muchos problemas pueden resolverse tanto mediante recursividad como mediante estructuras repetitivas, como for y while.

Vamos a comparar ambas técnicas utilizando el factorial.

Solución iterativa

JavaScript — Factorial con un bucle 
function factorialIterativo(numero) {
  let resultado = 1;

  for (let i = 2; i <= numero; i++) {
    resultado *= i;
  }

  return resultado;
}

console.log(factorialIterativo(5));
Resultado en consola 
120

Solución recursiva

JavaScript — Factorial recursivo 
function factorialRecursivo(numero) {
  if (numero === 0) {
    return 1;
  }

  return numero * factorialRecursivo(numero - 1);
}

console.log(factorialRecursivo(5));
Resultado en consola 
120

Ambas funciones producen el mismo resultado para el valor utilizado.

Sin embargo, existen diferencias importantes:

Aspecto Iteración Recursividad
Funcionamiento Repite instrucciones mediante un bucle. Realiza nuevas llamadas a funciones.
Finalización Depende de la condición del bucle. Depende del caso base.
Memoria Puede necesitar poca memoria adicional. Las llamadas anidadas ocupan espacio en la pila.
Legibilidad Suele ser clara para recorridos lineales. Puede ser más clara para estructuras jerárquicas.
Riesgos Bucles que no terminan. Llamadas sin fin o desbordamiento de pila.

Por tanto, no debemos pensar que la recursividad es siempre mejor que un bucle, ni al contrario. La elección depende de las características del problema.

⚠️ Atención

La recursividad no hace automáticamente que un programa sea más eficiente.

Para recorrer una secuencia muy larga, un bucle suele ser más adecuado si no necesitamos llamadas anidadas.

Errores frecuentes y buenas prácticas

1. Olvidar el caso base

Si no existe una condición de finalización, las llamadas continuarán indefinidamente hasta producir un error.

JavaScript — Incorrecto, no ejecutar 
function repetir(numero) {
  repetir(numero - 1);
}

// No ejecutar:
// repetir(5);

2. No avanzar hacia el caso base

Aunque exista una condición de finalización, la función puede no alcanzarla.

JavaScript — Incorrecto, no ejecutar 
function cuentaAtras(numero) {
  if (numero === 0) {
    return;
  }

  cuentaAtras(numero + 1);
}

// No ejecutar:
// cuentaAtras(5);

En este ejemplo, el número aumenta, por lo que se aleja del caso base.

3. Olvidar devolver el resultado recursivo

Cuando necesitamos obtener un resultado, es habitual que debamos utilizar return para propagarlo.

JavaScript — Ejemplo incorrecto 
function sumar(numero) {
  if (numero === 0) {
    return 0;
  }

  numero + sumar(numero - 1);
}

console.log(sumar(3));
Resultado en consola 
undefined

El problema es que se calcula una expresión, pero no se devuelve su resultado.

La versión correcta sería:

JavaScript — Ejemplo corregido 
function sumar(numero) {
  if (numero === 0) {
    return 0;
  }

  return numero + sumar(numero - 1);
}

console.log(sumar(3));
Resultado en consola 
6

4. No validar los argumentos

Una función diseñada para trabajar con enteros no negativos puede fallar si recibe números negativos, decimales o valores que no son numéricos.

Conviene validar las entradas utilizando, cuando corresponda, Number.isInteger(), Number.isFinite() u otras comprobaciones.

5. Utilizar recursividad innecesariamente

Si una operación puede expresarse claramente mediante un bucle sencillo, no es obligatorio convertirla en una función recursiva.

La recursividad debe ayudarnos a resolver y comprender el problema, no complicarlo.

📌 Importante

Antes de dar por terminada una función recursiva, comprueba siempre:

  • Que tiene un caso base.
  • Que ese caso base puede alcanzarse.
  • Que los argumentos se modifican correctamente.
  • Que devuelve los resultados necesarios.
  • Que las entradas están validadas.
  • Que la profundidad de llamadas es razonable.

Ejemplo práctico completo: categorías de una tienda online

Vamos a aplicar la recursividad a un ejemplo relacionado con el desarrollo web.

Imagina una tienda online de productos informáticos que organiza su catálogo mediante categorías y subcategorías.

Algunas categorías contienen productos, pero también pueden contener otras categorías. Por ejemplo:

Estructura del catálogo 
Informática
├── Ordenadores
│   ├── Portátiles
│   └── Sobremesa
└── Periféricos
    ├── Teclados
    └── Ratones

El objetivo es mostrar todas las categorías, independientemente del nivel de profundidad en el que se encuentren.

1. Representación de los datos

Utilizaremos un objeto que contiene el nombre de la categoría y un array de subcategorías.

Cada subcategoría tiene la misma estructura que la categoría principal. Esta característica hace que la recursividad resulte especialmente apropiada.

JavaScript — Datos del catálogo 
const catalogo = {
  nombre: "Informática",
  subcategorias: [
    {
      nombre: "Ordenadores",
      subcategorias: [
        {
          nombre: "Portátiles",
          subcategorias: []
        },
        {
          nombre: "Sobremesa",
          subcategorias: []
        }
      ]
    },
    {
      nombre: "Periféricos",
      subcategorias: [
        {
          nombre: "Teclados",
          subcategorias: []
        },
        {
          nombre: "Ratones",
          subcategorias: []
        }
      ]
    }
  ]
};

2. Crear la función recursiva

Vamos a escribir una función que muestre el nombre de una categoría y, a continuación, recorra sus subcategorías.

Para indicar visualmente la profundidad, utilizaremos un segundo parámetro llamado nivel, cuyo valor inicial será 0.

JavaScript — Función recursiva 
function mostrarCategorias(categoria, nivel = 0) {
  const sangria = "  ".repeat(nivel);

  console.log(sangria + categoria.nombre);

  for (const subcategoria of categoria.subcategorias) {
    mostrarCategorias(subcategoria, nivel + 1);
  }
}

La función realiza tres operaciones:

  1. Calcula una sangría según el nivel de profundidad.
  2. Muestra el nombre de la categoría actual.
  3. Recorre sus subcategorías y llama a la propia función para cada una.

En este ejemplo, el caso base es implícito: cuando una categoría tiene el array subcategorias vacío, el bucle no realiza ninguna iteración y no se producen nuevas llamadas recursivas.

3. Ejecutar el programa completo

JavaScript — Ejemplo completo 
const catalogo = {

  subcategorias: [

      nombre: "Ordenadores",
      subcategorias: [

4. ¿Por qué es útil la recursividad en este caso?

La función no necesita conocer de antemano cuántos niveles de subcategorías existen.

Si añadimos una categoría dentro de Portátiles, por ejemplo Gaming, la misma función podrá mostrarla sin modificar su lógica.

Esto es posible porque cada elemento tiene una estructura semejante y la función vuelve a aplicarse a sus elementos hijos.

💻 Ejemplo DAW

Esta técnica puede utilizarse en aplicaciones web para procesar menús multinivel, categorías de comercio electrónico, estructuras de carpetas o comentarios con respuestas anidadas.

En una interfaz real, la información obtenida podría utilizarse para construir elementos HTML y mostrarlos en la página. Esa interacción con el documento se estudiará al trabajar con el DOM.

⚠️ Atención

Este ejemplo supone que los datos forman una jerarquía válida y que cada categoría contiene un array subcategorias.

Si los objetos contuvieran referencias circulares —por ejemplo, una categoría que vuelve a apuntar a una categoría anterior—, necesitaríamos controles adicionales para evitar llamadas repetidas indefinidamente.

function calcular(numero) {
  if (numero === 0) {
    return 0;
  }

  return numero + calcular(numero - 1);
}

function mostrar(numero) {
  if (numero === 0) {
    console.log("Fin");
    return;
  }

  console.log("Inicio:", numero);

  mostrar(numero - 1);

  console.log("Final:", numero);
}

Ver solución razonada

1. Funciones recursivas. Tanto calcular() como mostrar() son recursivas, porque ambas se llaman a sí mismas.

2. Caso base de calcular(). Se alcanza cuando numero === 0. En ese momento devuelve 0 y no realiza nuevas llamadas.

3. Resultado de calcular(3). Devuelve 6.

Desarrollo del cálculo 
calcular(3)
= 3 + calcular(2)
= 3 + 2 + calcular(1)
= 3 + 2 + 1 + calcular(0)
= 3 + 2 + 1 + 0
= 6

4. Eliminar el caso base. La función continuaría realizando llamadas recursivas sin alcanzar una condición de finalización. Finalmente, se produciría un error por desbordamiento de la pila.

5. Caso base de mostrar(). Se alcanza cuando numero === 0. En ese momento muestra "Fin" y ejecuta return.

6. Número de llamadas. Se realizan tres llamadas: mostrar(2), mostrar(1) y mostrar(0).

7. Orden de los mensajes "Final:". Estos mensajes aparecen después de la llamada recursiva. Por tanto, se ejecutan cuando las llamadas pendientes van terminando, empezando por la más reciente.
