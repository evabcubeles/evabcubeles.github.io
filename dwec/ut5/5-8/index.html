5.8 Expresiones de función y funciones flecha

Hasta ahora hemos aprendido a crear funciones mediante la palabra function, a utilizar parámetros y argumentos, a devolver resultados mediante return y a trabajar con parámetros por defecto y rest.

Sin embargo, JavaScript permite definir funciones de diferentes maneras. No siempre necesitamos escribir una declaración tradicional: también podemos guardar una función en una variable o utilizar una sintaxis más breve mediante las funciones flecha.

Estas formas de escribir funciones son muy habituales en el desarrollo web moderno. Las encontraremos al procesar datos, trabajar con arrays, responder a eventos de una página y organizar el comportamiento de una aplicación.

📌 Importante

Una expresión de función permite crear una función como parte de una expresión, por ejemplo, para asignarla a una variable. Una función flecha utiliza el operador => y ofrece una sintaxis más compacta.

Aunque pueden realizar muchas de las mismas tareas, las declaraciones, las expresiones y las funciones flecha no son completamente equivalentes.

Diferentes formas de definir funciones

Comencemos recordando una declaración tradicional. Esta es la forma de crear funciones que hemos utilizado principalmente en los apartados anteriores.

JavaScript 
function sumar(a, b) {
  return a + b;
}

console.log(sumar(10, 5));

Salida por consola:

Consola 
15

Podemos obtener exactamente el mismo resultado escribiendo la función de estas otras dos formas:

JavaScript 
// Expresión de función.
const sumarExpresion = function(a, b) {
  return a + b;
};

// Función flecha.
const sumarFlecha = (a, b) => {
  return a + b;
};

console.log(sumarExpresion(10, 5));
console.log(sumarFlecha(10, 5));

Salida por consola:

Consola 
15
15

Observa que las tres funciones reciben dos argumentos, realizan la misma suma y devuelven el mismo resultado. Lo que cambia es la forma de definirlas.

Declaración function sumar(a, b)
Expresión const sumar = function(a, b)
Flecha const sumar = (a, b) =>

Expresiones de función

Una expresión de función es una expresión de JavaScript que crea una función. Podemos asignar esa función a una variable para utilizarla posteriormente.

En el siguiente ejemplo, la variable calcularDoble contiene una función que recibe un número y devuelve su doble.

JavaScript 
const calcularDoble = function(numero) {
  return numero * 2;
};

console.log(calcularDoble(8));
console.log(calcularDoble(15));

Salida por consola:

Consola 
16
30

Cómo se interpreta esta expresión

  1. const calcularDoble declara una variable.
  2. function(numero) crea una función que recibe un parámetro.
  3. El bloque entre llaves contiene las instrucciones que ejecutará la función.
  4. return numero * 2 devuelve el resultado.
  5. calcularDoble(8) invoca la función almacenada en la variable.

La variable no contiene el número 16 ni el resultado de una llamada concreta. Contiene la propia función, que podremos ejecutar tantas veces como necesitemos.

⚠️ Atención

No confundas guardar una función con guardar el resultado de ejecutarla.

const operacion = function() { ... }; guarda una función.

const resultado = operacion(); ejecuta la función y guarda el valor que devuelve.

Por qué utilizamos const

Es habitual declarar las expresiones de función mediante const cuando no necesitamos asignar otra función a esa misma variable.

Esto impide reasignar la variable, pero no significa que la función solo pueda ejecutarse una vez. Podemos invocarla repetidamente.

JavaScript 
const aplicarDescuento = function(precio, porcentaje) {
  return precio - precio * porcentaje / 100;
};

console.log(aplicarDescuento(100, 10));
console.log(aplicarDescuento(80, 25));
console.log(aplicarDescuento(50, 0));

Salida por consola:

Consola 
90
60
50

Funciones anónimas

Una función anónima es una función que no tiene un nombre escrito después de la palabra function.

Las expresiones de función pueden utilizar funciones anónimas, como ocurre en este ejemplo:

JavaScript 
const saludar = function(nombre) {
  return "Hola, " + nombre;
};

console.log(saludar("Ana"));

Salida por consola:

Consola 
Hola, Ana

La función no tiene un nombre explícito en su declaración, pero podemos utilizarla mediante la variable saludar.

Expresiones de función con nombre

Una expresión de función también puede tener un nombre propio.

JavaScript 
const calcularCuadrado = function cuadrado(numero) {
  return numero * numero;
};

console.log(calcularCuadrado(6));

Salida por consola:

Consola 
36

En este caso, cuadrado es el nombre interno de la función y calcularCuadrado es la variable desde la que la invocamos.

El nombre interno puede ser útil para identificar una función durante la depuración o para que la propia función se refiera a sí misma. No crea automáticamente una función llamada cuadrado accesible desde el exterior.

Diferencias entre declaración y expresión de función

Aunque ambas permiten crear funciones, existe una diferencia importante relacionada con el momento en que podemos utilizarlas.

Las declaraciones y el hoisting

Como estudiamos en el apartado 5.2, las declaraciones tradicionales de función pueden utilizarse antes de su posición en el código, dentro del ámbito en el que están disponibles.

JavaScript 
console.log(sumar(4, 6));

function sumar(a, b) {
  return a + b;
}

Salida por consola:

Consola 
10

Esto ocurre porque JavaScript procesa las declaraciones de función durante la preparación de su ámbito de ejecución. Este comportamiento se conoce como hoisting.

Las expresiones asignadas a const

Una expresión de función asignada a const no puede utilizarse antes de que se ejecute su inicialización.

JavaScript 
// Este código produce un error.

console.log(sumar(4, 6));

const sumar = function(a, b) {
  return a + b;
};

Al ejecutar la primera línea, la variable sumar todavía no está inicializada. Por tanto, se produce un ReferenceError.

📌 Importante

Una declaración tradicional de función suele poder invocarse antes de aparecer en el código. En cambio, una expresión de función almacenada mediante const debe inicializarse antes de utilizarse.

Esto no significa que las variables declaradas con const no participen en el hoisting: existen desde la preparación del ámbito, pero permanecen sin inicializar hasta llegar a su declaración.

Ejemplo comparativo

Característica Declaración Expresión con const
Forma habitual function saludar() {} const saludar = function() {};
Nombre Se declara un nombre para la función Puede ser anónima o tener nombre interno
Uso antes de su posición Generalmente sí, dentro de su ámbito No, antes de inicializar la variable
Invocación saludar() saludar()

Introducción a las funciones flecha

Las funciones flecha, también conocidas como arrow functions, se incorporaron a JavaScript con ECMAScript 2015 (ES6).

Su característica más visible es el operador =>, que separa los parámetros del cuerpo de la función.

Observa estas dos versiones de una función que calcula el triple de un número.

JavaScript 
// Expresión de función tradicional.
const triple1 = function(numero) {
  return numero * 3;
};

// Función flecha.
const triple2 = (numero) => {
  return numero * 3;
};

console.log(triple1(7));
console.log(triple2(7));

Salida por consola:

Consola 
21
21

En la segunda versión desaparece la palabra function y aparece la flecha =>.

Las funciones flecha también pueden tener parámetros, ejecutar varias instrucciones y devolver resultados.

⚠️ Atención

La flecha se escribe con el signo igual seguido del signo mayor que: =>.

No debemos confundirla con >=, que es el operador de comparación «mayor o igual que».

Sintaxis de las funciones flecha

La sintaxis de una función flecha depende del número de parámetros y de las instrucciones que necesitamos ejecutar.

Funciones flecha sin parámetros

Cuando una función no recibe parámetros, debemos escribir los paréntesis vacíos antes de la flecha.

JavaScript 
const mostrarBienvenida = () => {
  console.log("Bienvenido a la aplicación");
};

mostrarBienvenida();

Salida por consola:

Consola 
Bienvenido a la aplicación

Funciones flecha con un parámetro

Cuando existe un único parámetro simple, podemos escribirlo entre paréntesis o prescindir de ellos.

JavaScript 
const cuadrado1 = (numero) => {
  return numero * numero;
};

const cuadrado2 = numero => {
  return numero * numero;
};

console.log(cuadrado1(5));
console.log(cuadrado2(5));

Salida por consola:

Consola 
25
25

Ambas funciones son válidas. La posibilidad de omitir los paréntesis se limita a un único parámetro que sea un identificador simple.

Funciones flecha con varios parámetros

Si una función recibe dos o más parámetros, los paréntesis son obligatorios.

JavaScript 
const calcularArea = (base, altura) => {
  return base * altura;
};

console.log(calcularArea(8, 4));

Salida por consola:

Consola 
32
📌 Importante

Recuerda estas tres formas básicas:

  • () => { ... }: sin parámetros.
  • numero => { ... }: un parámetro simple.
  • (a, b) => { ... }: varios parámetros.

Retorno implícito y retorno explícito

Una de las ventajas de las funciones flecha es que permiten escribir de forma muy breve las funciones que simplemente calculan y devuelven un resultado.

Retorno explícito

Cuando escribimos el cuerpo entre llaves, necesitamos utilizar return si queremos devolver un valor.

JavaScript 
const sumar = (a, b) => {
  return a + b;
};

console.log(sumar(10, 20));

Salida por consola:

Consola 
30

Retorno implícito

Si el cuerpo de la función consiste en una única expresión, podemos omitir las llaves y la palabra return. JavaScript devolverá automáticamente el resultado de esa expresión.

JavaScript 
const sumar = (a, b) => a + b;

console.log(sumar(10, 20));

Salida por consola:

Consola 
30

Esta segunda versión es más breve, pero realiza exactamente el mismo cálculo.

Comparación de las dos formas

JavaScript 
// Retorno explícito.
const mitad1 = numero => {
  return numero / 2;
};

// Retorno implícito.
const mitad2 = numero => numero / 2;

console.log(mitad1(20));
console.log(mitad2(20));

Salida por consola:

Consola 
10
10

Un error frecuente: utilizar llaves sin return

Observa el siguiente ejemplo:

JavaScript 
const multiplicar = (a, b) => {
  a * b;
};

console.log(multiplicar(4, 5));

Salida por consola:

Consola 
undefined

La multiplicación se evalúa, pero su resultado no se devuelve. Al utilizar llaves, hemos creado un bloque de instrucciones y necesitamos escribir return.

⚠️ Atención

Con llaves: debemos escribir return para devolver un resultado.

Sin llaves y con una expresión: se produce un retorno implícito.

El retorno implícito no significa que todas las funciones flecha devuelvan automáticamente cualquier operación que aparezca en su cuerpo.

Parámetros por defecto y rest en funciones flecha

Las funciones flecha pueden utilizar los parámetros por defecto y los parámetros rest que estudiamos en el apartado 5.7.

Parámetros por defecto

JavaScript 
const saludar = (nombre = "Invitado") => {
  return "Hola, " + nombre;
};

console.log(saludar("Laura"));
console.log(saludar());

Salida por consola:

Consola 
Hola, Laura
Hola, Invitado

Aunque solo tenemos un parámetro, utilizamos paréntesis porque contiene un valor por defecto.

Parámetros rest

JavaScript 
const sumarNumeros = (...numeros) => {
  let total = 0;

  for (const numero of numeros) {
    total += numero;
  }

  return total;
};

console.log(sumarNumeros(5, 10, 15));
console.log(sumarNumeros(20, 30));
console.log(sumarNumeros());

Salida por consola:

Consola 
30
50
0

El parámetro ...numeros reúne los argumentos recibidos en un array, igual que ocurría con las funciones tradicionales.

Combinar parámetros por defecto y rest

JavaScript 
const registrarAcciones = (
  usuario = "Invitado",
  ...acciones
) => {
  console.log("Usuario: " + usuario);
  console.log("Total: " + acciones.length);
};

registrarAcciones("Ana", "entrar", "consultar");
registrarAcciones();

Salida por consola:

Consola 
Usuario: Ana
Total: 2
Usuario: Invitado
Total: 0
📌 Importante

Las reglas de los parámetros por defecto y rest también se aplican a las funciones flecha. El parámetro rest debe ser el último y no puede tener un valor por defecto propio.

Devolver objetos con funciones flecha

En desarrollo web es habitual crear funciones que devuelven objetos. Por ejemplo, podemos construir un objeto con los datos de un producto.

Con un cuerpo entre llaves, podemos escribir una función flecha de la siguiente manera:

JavaScript 
const crearProducto = (nombre, precio) => {
  return {
    nombre: nombre,
    precio: precio
  };
};

console.log(crearProducto("Teclado", 35));

Salida por consola:

Consola 
{ nombre: "Teclado", precio: 35 }

Si queremos utilizar retorno implícito para devolver un objeto literal, debemos envolverlo entre paréntesis.

JavaScript 
const crearProducto = (nombre, precio) => ({
  nombre: nombre,
  precio: precio
});

console.log(crearProducto("Ratón", 20));

Salida por consola:

Consola 
{ nombre: "Ratón", precio: 20 }

Los paréntesis indican que las llaves forman parte de un objeto que queremos devolver, y no de un bloque de instrucciones de la función.

Utilizar la sintaxis abreviada de propiedades

Cuando el nombre de una propiedad coincide con el de una variable, JavaScript permite escribirlo una sola vez.

JavaScript 
const crearProducto = (nombre, precio) => ({
  nombre,
  precio
});

const producto = crearProducto("Monitor", 180);

console.log(producto.nombre);
console.log(producto.precio);

Salida por consola:

Consola 
Monitor
180
⚠️ Atención

Para devolver directamente un objeto literal mediante una función flecha de retorno implícito, utiliza la forma () => ({ ... }).

Si escribes () => { ... }, las llaves se interpretan como el cuerpo de la función.

Una diferencia importante: el comportamiento de this

Las funciones flecha no son simplemente una forma abreviada de escribir funciones. También presentan diferencias en su comportamiento.

Una de las más importantes está relacionada con la palabra clave this, que utilizaremos al trabajar con objetos y programación orientada a objetos.

En una función tradicional, el valor de this depende de cómo se invoque la función. En cambio, una función flecha no crea su propio this: utiliza el del contexto léxico exterior.

Un ejemplo con métodos de objetos

JavaScript 
const producto = {
  nombre: "Teclado",

  mostrarNombre: function() {
    console.log(this.nombre);
  }
};

producto.mostrarNombre();

Salida por consola:

Consola 
Teclado

En esta llamada, this hace referencia al objeto producto, porque el método se invoca mediante producto.mostrarNombre().

Si definiéramos ese método como una función flecha, no recibiría automáticamente el objeto producto como valor de this.

📌 Importante

Como regla inicial, utiliza métodos tradicionales cuando necesites que this haga referencia al objeto que invoca el método.

Las funciones flecha resultan muy útiles cuando no necesitamos un this propio. Estudiaremos este comportamiento con mayor profundidad en la unidad de programación orientada a objetos.

Errores frecuentes y buenas prácticas

1. Olvidar return al utilizar llaves

Si escribimos un cuerpo con llaves, necesitamos return para devolver un valor.

JavaScript 
// Incorrecto si queremos devolver la suma.
const sumar1 = (a, b) => {
  a + b;
};

// Correcto: retorno explícito.
const sumar2 = (a, b) => {
  return a + b;
};

// Correcto: retorno implícito.
const sumar3 = (a, b) => a + b;

2. Omitir paréntesis cuando son necesarios

Con cero parámetros o varios parámetros debemos utilizar paréntesis. También son necesarios cuando el parámetro incluye un valor por defecto o rest.

JavaScript 
const iniciar = () => "Inicio";

const sumar = (a, b) => a + b;

const saludar = (nombre = "Invitado") => nombre;

const contar = (...valores) => valores.length;

3. Confundir la función con su resultado

El nombre de una variable que contiene una función representa la propia función. Los paréntesis permiten invocarla.

JavaScript 
const obtenerPrecio = () => 25;

const funcion = obtenerPrecio;
const resultado = obtenerPrecio();

console.log(typeof funcion);
console.log(resultado);

Salida por consola:

Consola 
function
25

4. Intentar utilizar una expresión antes de inicializarla

Una función guardada en una variable declarada con const debe inicializarse antes de invocarla.

5. Utilizar funciones flecha para todos los métodos

Las funciones flecha no tienen un this propio. No debemos sustituir automáticamente todos los métodos tradicionales por funciones flecha.

6. Abreviar demasiado el código

Una función flecha de una sola expresión puede resultar muy clara. Sin embargo, si la operación necesita validaciones, condiciones o varios cálculos, suele ser más comprensible utilizar un cuerpo con llaves.

💻 Ejemplo DAW

En una aplicación web, una función flecha breve puede servir para calcular un precio con IVA o transformar un dato. Para registrar un pedido, validar campos o realizar varias operaciones, puede ser preferible escribir una función con un cuerpo más desarrollado.

La mejor opción no es siempre la que ocupa menos líneas, sino la que permite comprender y mantener el código con mayor facilidad.

Comparación entre las distintas formas de función

Vamos a reunir las principales diferencias entre las declaraciones, las expresiones y las funciones flecha.

Característica Declaración Expresión tradicional Función flecha
Sintaxis function nombre() {} const f = function() {}; const f = () => {};
Palabra function Sí Sí No
Parámetros Sí Sí Sí
Retorno explícito Sí Sí Sí
Retorno implícito de una expresión No No Sí
Uso antes de su definición o inicialización Generalmente posible No si está asignada a const No si está asignada a const
this propio Sí Sí No
📌 Importante

Las tres formas permiten escribir funciones reutilizables, recibir argumentos y devolver resultados.

Para elegir entre ellas debemos considerar la legibilidad, el momento en que se inicializa la función y si necesitamos un comportamiento particular de this.

Ejemplo práctico completo: gestión de productos de una tienda online

Vamos a aplicar lo aprendido en un pequeño programa relacionado con una tienda tecnológica.

Queremos crear productos, calcular sus precios con IVA y obtener el importe de una compra. Para ello utilizaremos distintas formas de definir funciones.

El programa realizará las siguientes operaciones:

  1. Crear objetos que representen productos.
  2. Calcular el precio de cada producto con IVA.
  3. Calcular el importe de varias unidades.
  4. Mostrar un pequeño resumen por consola.
JavaScript 
// Declaración tradicional.
function mostrarTitulo() {
  console.log("RESUMEN DE COMPRA");
}

// Función flecha que devuelve un objeto.
const crearProducto = (nombre, precio, unidades = 1) => ({
  nombre,
  precio,
  unidades
});

// Función flecha con retorno implícito.
const aplicarIVA = (precio, iva = 21) =>
  precio + precio * iva / 100;

// Expresión de función tradicional.
const calcularImporte = function(producto) {
  const precioFinal = aplicarIVA(producto.precio);
  return precioFinal * producto.unidades;
};

// Creamos los productos.
const teclado = crearProducto("Teclado", 40, 2);
const raton = crearProducto("Ratón", 20, 1);

// Calculamos los importes.
const importeTeclado = calcularImporte(teclado);
const importeRaton = calcularImporte(raton);

const totalCompra = importeTeclado + importeRaton;

// Mostramos el resumen.
mostrarTitulo();

console.log(
  teclado.nombre + ": " +
  importeTeclado.toFixed(2) + " €"
);

console.log(
  raton.nombre + ": " +
  importeRaton.toFixed(2) + " €"
);

console.log(
  "TOTAL: " + totalCompra.toFixed(2) + " €"
);

Salida por consola:

Consola 
RESUMEN DE COMPRA
Teclado: 96.80 €
Ratón: 24.20 €
TOTAL: 121.00 €

Análisis paso a paso

  1. mostrarTitulo() es una declaración tradicional de función. Su objetivo es mostrar el encabezado del resumen.
  2. crearProducto() es una función flecha con retorno implícito. Devuelve un objeto con el nombre, el precio y las unidades.
  3. El parámetro unidades = 1 permite crear productos sin indicar una cantidad específica.
  4. aplicarIVA() utiliza una función flecha de una sola expresión para calcular el precio con IVA.
  5. calcularImporte() es una expresión de función tradicional. Obtiene el precio con IVA y lo multiplica por las unidades.
  6. El teclado cuesta 40 € por unidad. Con un 21 % de IVA, cada unidad cuesta 48,40 €. Como compramos dos, su importe es 96,80 €.
  7. El ratón cuesta 20 €. Con el IVA aplicado, su importe es 24,20 €.
  8. La suma de ambos importes produce un total de 121,00 €.
💻 Ejemplo DAW

En una aplicación real de comercio electrónico, podríamos utilizar funciones semejantes para construir productos, calcular importes y mostrar información en el carrito.

Separar estas responsabilidades permite reutilizar los cálculos y facilita la modificación del programa cuando cambian los requisitos.

};

const teclado = crearProducto("Teclado", 100);

const precioDescuento = calcularPrecio(teclado.precio, 20);
const precioFinal = calcularIVA(precioDescuento);

mostrarProducto(teclado);

console.log("Descuento: " + precioDescuento);
console.log("Final: " + precioFinal.toFixed(2));

  6. ¿Se modifica el precio original del objeto teclado? Justifica tu respuesta.

Ver una posible solución

1. calcularPrecio está definida mediante una declaración tradicional porque utiliza function calcularPrecio(...).

2. calcularIVA y crearProducto son funciones flecha, ya que utilizan el operador =>.

3. mostrarProducto es una expresión de función tradicional: se crea mediante function y se asigna a una variable declarada con const.

4. calcularIVA utiliza retorno implícito. Al no tener llaves y contener una sola expresión, devuelve automáticamente el resultado de precio * 1.21.

5. Los paréntesis de crearProducto indican que las llaves pertenecen al objeto literal que se devuelve, y no al cuerpo de instrucciones de la función.

6. No se modifica el objeto original. calcularPrecio recibe el número 100, calcula un nuevo valor y lo devuelve. El objeto teclado sigue teniendo precio: 100.

7. La salida completa será:

Consola 
Producto: Teclado
Precio: 100
Descuento: 80
Final: 96.80

Primero se crea el objeto teclado con un precio de 100 €. Después se aplica un descuento del 20 %, obteniendo 80 €. Finalmente se calcula el IVA del 21 % sobre esos 80 €, obteniendo 96,80 €.

La llamada a mostrarProducto(teclado) sigue mostrando el precio original, porque ninguna instrucción ha modificado su propiedad precio.
