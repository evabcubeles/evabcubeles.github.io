5.12 Organización modular de un programa

A lo largo de esta unidad hemos aprendido a crear funciones, pasarles argumentos, devolver resultados y reutilizar instrucciones. También hemos visto que las funciones permiten dividir un problema en tareas más pequeñas.

Sin embargo, cuando desarrollamos una aplicación web, el programa puede llegar a contener decenas o cientos de funciones. Si colocamos todo el código en un único archivo, mantenerlo y comprenderlo puede resultar cada vez más difícil.

Para evitarlo, debemos aprender a organizar el programa en partes relacionadas, independientes en la medida de lo posible y con responsabilidades bien definidas.

En este apartado estudiaremos cómo organizar el código utilizando funciones, archivos y los módulos de JavaScript. Aprenderemos también a compartir funciones entre archivos mediante export e import.

📌 Importante

La organización modular consiste en dividir un programa en partes que realizan tareas concretas y que pueden desarrollarse, comprenderse y mantenerse por separado.

En JavaScript moderno, los módulos ES permiten distribuir el código en distintos archivos y compartir únicamente las funciones o valores que necesitamos.

Por qué necesitamos organizar el código

Imagina que estamos desarrollando una aplicación para gestionar los pedidos de una tienda online.

El programa debe realizar diferentes tareas:

  • Calcular el importe de los productos.
  • Aplicar descuentos.
  • Calcular impuestos.
  • Validar los datos introducidos.
  • Mostrar mensajes al usuario.
  • Preparar la información del pedido.

Podríamos escribir todas estas operaciones directamente en un único bloque de código. Sin embargo, esa solución resultaría difícil de ampliar y mantener.

Ejemplo de código poco organizado

JavaScript — Todo en un mismo bloque 
const precio = 50;
const cantidad = 3;
const descuento = 10;

const subtotal = precio * cantidad;
const importeDescuento = subtotal * descuento / 100;
const baseImponible = subtotal - importeDescuento;
const iva = baseImponible * 0.21;
const total = baseImponible + iva;

console.log("Subtotal:", subtotal);
console.log("Descuento:", importeDescuento);
console.log("IVA:", iva);
console.log("Total:", total);

El código funciona, pero mezcla los cálculos con la presentación de los resultados. Además, si necesitamos realizar el mismo cálculo para otro pedido, tendríamos que repetir instrucciones o modificar directamente las variables.

Una primera mejora consiste en utilizar funciones con responsabilidades concretas.

JavaScript — Código organizado en funciones 
function calcularSubtotal(precio, cantidad) {
  return precio * cantidad;
}

function aplicarDescuento(importe, porcentaje) {
  return importe - importe * porcentaje / 100;
}

function calcularIVA(importe) {
  return importe * 0.21;
}

function mostrarTotal(total) {
  console.log("Total:", total);
}

const subtotal = calcularSubtotal(50, 3);
const base = aplicarDescuento(subtotal, 10);
const total = base + calcularIVA(base);

mostrarTotal(total);
Resultado en consola 
Total: 163.35

Ahora cada función tiene una tarea concreta. Podemos reutilizar los cálculos en otros pedidos y modificar una operación sin tener que reescribir todo el programa.

⚠️ Atención

Dividir el código en funciones no significa automáticamente que estemos utilizando módulos ES.

Primero aprendemos a separar responsabilidades mediante funciones. Después podemos distribuir esas funciones entre diferentes archivos y conectarlos utilizando el sistema de módulos.

Qué es la modularidad

La modularidad es una forma de organizar el software que consiste en dividir una aplicación en componentes o módulos especializados.

Cada módulo agrupa elementos relacionados y ofrece determinadas funcionalidades al resto del programa.

Por ejemplo, una aplicación de comercio electrónico podría organizarse en tres áreas:

Productos Precios y cálculos
Validación Comprobación de datos
Pedidos Preparación de resultados

Esta separación aporta varias ventajas.

Ventaja Explicación
Organización El código se agrupa según la tarea que realiza.
Reutilización Una función puede utilizarse desde diferentes partes del programa.
Mantenimiento Los cambios pueden localizarse en el módulo correspondiente.
Legibilidad Es más sencillo comprender la finalidad de cada archivo.
Pruebas Las funciones pueden comprobarse de forma aislada cuando sus dependencias lo permiten.
Trabajo en equipo Diferentes desarrolladores pueden trabajar en partes distintas del proyecto.
📌 Importante

Un módulo debe tener una responsabilidad clara. No conviene agrupar funciones sin relación simplemente para reducir el número de archivos.

Separar responsabilidades mediante funciones

Antes de distribuir un programa en archivos, debemos decidir qué tareas realizará cada función.

Una buena práctica consiste en que una función tenga un objetivo principal y un nombre que permita comprender su comportamiento.

Funciones que calculan y funciones que muestran

Observa el siguiente ejemplo:

JavaScript — Separación de tareas 
function calcularPrecioFinal(precio, iva) {
  return precio + precio * iva / 100;
}

function mostrarPrecio(precio) {
  console.log("Precio final:", precio.toFixed(2), "€");
}

const resultado = calcularPrecioFinal(100, 21);

mostrarPrecio(resultado);
Resultado en consola 
Precio final: 121.00 €

La función calcularPrecioFinal() realiza un cálculo y devuelve el resultado.

La función mostrarPrecio() se encarga de presentarlo.

Gracias a esta separación, podemos cambiar la forma de mostrar los precios sin modificar la función que los calcula.

💻 Ejemplo DAW

En una aplicación web real, una función podría calcular el precio de un producto y otra mostrarlo en la interfaz.

Si más adelante cambiamos el diseño visual de la página, la función matemática podría mantenerse exactamente igual.

Evitar funciones que realizan demasiadas tareas

Una función que valida datos, calcula importes, actualiza la interfaz y muestra mensajes puede resultar difícil de mantener.

En muchos casos será preferible utilizar varias funciones pequeñas que colaboren entre sí.

⚠️ Atención

No es necesario crear una función distinta para cada instrucción.

El objetivo es conseguir una organización comprensible, no fragmentar el código de forma innecesaria.

Organizar el código en varios archivos

Cuando un programa crece, podemos distribuir sus funciones entre distintos archivos JavaScript.

Por ejemplo, podemos separar las funciones matemáticas de las relacionadas con mensajes.

Estructura de archivos 
proyecto/
├── index.html
└── js/
    ├── calculos.js
    └── mensajes.js

Una posibilidad tradicional consiste en incluir varios archivos mediante etiquetas <script>.

HTML — Carga de varios scripts clásicos 
<script src="js/calculos.js"></script>
<script src="js/mensajes.js"></script>

En este caso, ambos archivos se cargan como scripts clásicos. Las declaraciones globales pueden ser accesibles desde otros scripts, según cómo estén definidas.

Sin embargo, esta forma de organizar el código presenta limitaciones:

  • Puede depender del orden de carga de los archivos.
  • Es posible que aparezcan conflictos entre nombres globales.
  • No se indican explícitamente las funciones que necesita cada archivo.
  • Las dependencias pueden resultar difíciles de identificar.
📌 Importante

Utilizar varios archivos JavaScript no equivale necesariamente a utilizar módulos.

Los módulos ES proporcionan un mecanismo específico para compartir valores y declarar dependencias entre archivos.

Los módulos ES de JavaScript

JavaScript dispone de un sistema de módulos conocido como ECMAScript Modules, también denominado ES Modules o simplemente módulos ES.

Este sistema permite escribir código en archivos separados y decidir qué funciones, constantes o valores pueden utilizar otros módulos.

Para ello se utilizan principalmente dos palabras clave:

  • export: permite compartir elementos definidos en un módulo.
  • import: permite utilizar elementos exportados por otro módulo.

Activar los módulos desde HTML

Para cargar un archivo JavaScript como módulo en el navegador, utilizamos el atributo type="module".

HTML — Cargar un módulo 
<script type="module" src="js/main.js"></script>

Con esta instrucción, el navegador interpreta main.js como un módulo y puede resolver sus importaciones.

⚠️ Atención

Para probar módulos ES en el navegador, es recomendable utilizar un servidor web local, por ejemplo mediante la extensión Live Server de Visual Studio Code.

Si abrimos directamente el archivo HTML con una dirección file://, las restricciones de seguridad del navegador pueden impedir la carga de los módulos.

Características de los módulos

  • Cada módulo tiene su propio ámbito.
  • Las declaraciones no pasan automáticamente al ámbito global.
  • Las dependencias se expresan mediante import.
  • Las funciones y valores compartidos se indican mediante export.
  • Los módulos se ejecutan en modo estricto.
  • Los scripts de tipo módulo se procesan de forma diferida por defecto.
📌 Importante

Una función definida dentro de un módulo no está disponible automáticamente para todos los archivos de la aplicación.

Para utilizarla desde otro módulo, normalmente debemos exportarla e importarla explícitamente.

Exportar funciones y valores

La palabra clave export permite indicar qué elementos de un módulo pueden utilizar otros archivos.

Exportación con nombre

Vamos a crear un archivo llamado matematicas.js.

JavaScript — matematicas.js 
export function sumar(a, b) {
  return a + b;
}

export function restar(a, b) {
  return a - b;
}

export const PI = 3.14159;

Hemos exportado dos funciones y una constante. Otros módulos podrán importarlas utilizando sus nombres.

También podemos declarar primero los elementos y exportarlos al final del archivo.

JavaScript — Otra forma de exportar 
function sumar(a, b) {
  return a + b;
}

function restar(a, b) {
  return a - b;
}

export { sumar, restar };

Ambas formas permiten realizar exportaciones con nombre.

Exportación por defecto

JavaScript también permite establecer una exportación por defecto mediante export default.

JavaScript — saludo.js 
export default function saludar(nombre) {
  return "Hola, " + nombre;
}

Un módulo puede tener varias exportaciones con nombre, pero solamente una exportación por defecto.

Tipo Sintaxis Características
Con nombre export function sumar() {} Se importa mediante el nombre exportado.
Por defecto export default ... Se importa sin llaves y puede elegirse un nombre local.
⚠️ Atención

export default no significa que una función se ejecute automáticamente.

Solamente indica que ese valor es la exportación por defecto del módulo.

Importar funciones y valores

La palabra clave import permite utilizar elementos exportados por otros módulos.

Importaciones con nombre

Supongamos que tenemos el archivo matematicas.js con las funciones sumar() y restar().

Podemos utilizarlas desde main.js:

JavaScript — main.js 
import { sumar, restar } from "./matematicas.js";

console.log(sumar(8, 3));
console.log(restar(8, 3));
Resultado en consola 
11
5

Las llaves indican que estamos importando exportaciones con nombre.

El texto "./matematicas.js" representa una ruta relativa al archivo que realiza la importación.

Importación de una exportación por defecto

Si un módulo utiliza export default, lo importamos sin llaves.

JavaScript — main.js 
import saludar from "./saludo.js";

console.log(saludar("Lucía"));
Resultado en consola 
Hola, Lucía

Cambiar el nombre local de una importación

Podemos utilizar as para asignar un nombre local diferente a una exportación con nombre.

JavaScript — Importación con alias 
import { sumar as realizarSuma } from "./matematicas.js";

console.log(realizarSuma(4, 6));
Resultado en consola 
10

Importar todas las exportaciones con nombre

También podemos agruparlas bajo un mismo identificador.

JavaScript — Importación mediante namespace 
import * as matematicas from "./matematicas.js";

console.log(matematicas.sumar(2, 3));
console.log(matematicas.restar(9, 4));
Resultado en consola 
5
5
📌 Importante

En las importaciones relativas del navegador, debemos escribir correctamente la ruta del archivo, incluida normalmente la extensión .js.

./ indica el directorio actual del módulo que importa. ../ permite acceder al directorio superior.

Estructura de un proyecto modular

Vamos a organizar una pequeña aplicación que utiliza funciones matemáticas y muestra sus resultados en consola.

El proyecto tendrá tres archivos:

Estructura del proyecto 
mi-aplicacion/
├── index.html
└── js/
    ├── operaciones.js
    └── main.js

1. Archivo operaciones.js

Este módulo contiene las funciones que realizan los cálculos.

JavaScript — js/operaciones.js 
export function multiplicar(a, b) {
  return a * b;
}

export function dividir(a, b) {
  if (b === 0) {
    return NaN;
  }

  return a / b;
}

2. Archivo main.js

Este archivo importa las funciones y coordina la ejecución del programa.

JavaScript — js/main.js 
import { multiplicar, dividir } from "./operaciones.js";

const producto = multiplicar(6, 4);
const cociente = dividir(20, 5);

console.log("Producto:", producto);
console.log("Cociente:", cociente);

3. Archivo index.html

Finalmente, cargamos main.js como módulo desde el documento HTML.

HTML — index.html 
<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Mi aplicación modular</title>
</head>
<body>

  <h1>Ejemplo de módulos JavaScript</h1>

  <script type="module" src="js/main.js"></script>

</body>
</html>

4. Resultado de la ejecución

Si iniciamos el proyecto desde un servidor local y abrimos la consola del navegador, obtendremos:

Resultado en consola 
Producto: 24
Cociente: 4

El navegador carga el módulo principal y resuelve su dependencia de operaciones.js.

No necesitamos añadir una segunda etiqueta <script> para cargar manualmente operaciones.js.

💻 Ejemplo DAW

Esta organización es habitual en aplicaciones web modernas: un archivo principal coordina la aplicación y utiliza funciones importadas desde otros módulos especializados.

Dependencias entre módulos

Cuando un módulo necesita utilizar una función definida en otro, decimos que existe una dependencia.

Por ejemplo, si main.js importa una función desde operaciones.js, el primero depende del segundo.

Relación entre módulos 
index.html
    |
    v
  main.js
    |
    | import
    v
operaciones.js

Esta relación permite comprender qué partes del programa necesitan funcionalidades de otras.

Dependencias claras

Una buena organización procura que cada módulo tenga dependencias fáciles de identificar.

Por ejemplo, un módulo de cálculos no debería depender innecesariamente de funciones encargadas de mostrar mensajes en la interfaz.

Evitar dependencias circulares innecesarias

Una dependencia circular aparece cuando dos o más módulos se importan entre sí formando un ciclo.

Ejemplo de dependencia circular 
moduloA.js
    |
    v
moduloB.js
    |
    v
moduloA.js

JavaScript admite determinadas dependencias circulares, pero pueden complicar la comprensión y la inicialización de los módulos.

⚠️ Atención

Las dependencias circulares no producen siempre un error, pero pueden provocar problemas si se intenta utilizar una declaración antes de que esté inicializada.

En proyectos sencillos, es recomendable diseñar dependencias claras y evitar ciclos innecesarios.

Buenas prácticas de organización modular

La modularidad debe facilitar el desarrollo del programa. Para conseguirlo, conviene aplicar una serie de recomendaciones.

1. Utilizar nombres descriptivos

Los archivos y las funciones deben indicar qué responsabilidad tienen.

Nombre poco descriptivo Nombre más claro
funciones.js calculos.js
cosas.js validaciones.js
hacer() calcularTotal()
comprobar() validarCorreo()

2. Agrupar funciones relacionadas

Un archivo calculos.js podría contener funciones para calcular subtotales, impuestos y descuentos.

Un archivo validaciones.js podría encargarse de comprobar los datos recibidos.

3. Exportar solamente lo necesario

No todas las funciones de un módulo tienen que estar disponibles para el resto de la aplicación.

Algunas pueden utilizarse exclusivamente como funciones auxiliares internas.

JavaScript — Función auxiliar privada al módulo 
function calcularDescuento(importe, porcentaje) {
  return importe * porcentaje / 100;
}

export function calcularPrecioConDescuento(
  importe,
  porcentaje
) {
  return importe - calcularDescuento(
    importe,
    porcentaje
  );
}

La función calcularDescuento() se utiliza dentro del módulo, pero no se exporta.

En cambio, calcularPrecioConDescuento() sí está disponible para otros módulos que la importen.

4. Evitar repetir código

Si varias partes de la aplicación necesitan realizar la misma operación, conviene centralizarla en una función reutilizable.

5. Mantener separada la lógica de la presentación

Siempre que resulte adecuado, las funciones que calculan datos deben mantenerse separadas de las que los muestran.

Esto facilita las pruebas, el mantenimiento y los cambios en la interfaz.

📌 Importante

Una buena organización modular busca que el programa sea fácil de comprender, modificar, probar y reutilizar.

No existe una cantidad ideal de archivos o funciones: la estructura debe adaptarse a la complejidad real del proyecto.

Errores frecuentes al trabajar con módulos

1. Olvidar type="module"

Si utilizamos import en un script clásico del navegador, se producirá un error de sintaxis.

HTML — Incorrecto para main.js con import 
<script src="js/main.js"></script>

La forma correcta es:

HTML — Correcto 
<script type="module" src="js/main.js"></script>

2. Escribir una ruta incorrecta

Las importaciones deben indicar la ubicación correcta del archivo.

JavaScript — Ruta relativa 
import { sumar } from "./matematicas.js";

Si el archivo no existe en la ruta indicada, el navegador no podrá cargarlo.

3. Importar una función no exportada

Si una función no se exporta, no podemos importarla mediante una importación con nombre.

JavaScript — matematicas.js 
function sumar(a, b) {
  return a + b;
}

// Falta exportar sumar.

Para solucionarlo, añadimos export a la declaración o utilizamos una exportación al final.

4. Confundir importaciones con nombre y por defecto

JavaScript — Comparación de sintaxis 
// Exportación con nombre:
import { sumar } from "./matematicas.js";

// Exportación por defecto:
import saludar from "./saludo.js";

Las llaves se utilizan para importar exportaciones con nombre. La exportación por defecto se importa sin llaves.

5. Abrir el proyecto directamente con file://

Cuando trabajamos con módulos, debemos tener en cuenta las restricciones de seguridad y carga de recursos del navegador.

Para los ejercicios de esta unidad, utilizaremos preferentemente un servidor local.

6. Esperar que una función importada sea global

Los módulos tienen su propio ámbito. Importar una función en main.js no hace que aparezca automáticamente como propiedad de window.

⚠️ Atención

Los módulos ES son diferentes de los scripts clásicos. Debemos prestar especial atención a las rutas, las exportaciones, las importaciones y el ámbito de las declaraciones.

Ejemplo práctico completo: gestión de pedidos

Vamos a construir una pequeña aplicación que calcule el importe final de un pedido de una tienda online.

El objetivo es aplicar los conocimientos de funciones y modularidad a una situación relacionada con el desarrollo de aplicaciones web.

El programa realizará las siguientes operaciones:

  1. Validar el precio y la cantidad de productos.
  2. Calcular el subtotal.
  3. Aplicar un descuento.
  4. Calcular el IVA.
  5. Mostrar el resultado final.

1. Organización de los archivos

Estructura del proyecto 
gestion-pedidos/
├── index.html
└── js/
    ├── validaciones.js
    ├── calculos.js
    └── main.js

Cada archivo tendrá una responsabilidad:

  • validaciones.js: comprobar que los datos son válidos.
  • calculos.js: realizar las operaciones económicas.
  • main.js: coordinar la ejecución y mostrar resultados.

2. Módulo de validaciones

Comenzamos creando una función que compruebe si un valor es un número finito y no negativo.

JavaScript — js/validaciones.js 
export function esNumeroNoNegativo(valor) {
  return typeof valor === "number" &&
         Number.isFinite(valor) &&
         valor >= 0;
}

export function esCantidadValida(cantidad) {
  return Number.isInteger(cantidad) &&
         cantidad > 0;
}

La primera función comprueba que el valor sea numérico, finito y no negativo.

La segunda comprueba que la cantidad sea un entero positivo.

3. Módulo de cálculos

Este archivo contiene las funciones necesarias para calcular el importe del pedido.

JavaScript — js/calculos.js 
export function calcularSubtotal(precio, cantidad) {
  return precio * cantidad;
}

export function aplicarDescuento(importe, porcentaje) {
  return importe - importe * porcentaje / 100;
}

export function calcularIVA(importe, porcentaje = 21) {
  return importe * porcentaje / 100;
}

export function calcularTotal(base, iva) {
  return base + iva;
}

Cada función realiza una operación específica y devuelve un resultado.

Observa que calcularIVA() utiliza un parámetro por defecto, una característica estudiada anteriormente en esta unidad.

4. Módulo principal

Ahora creamos main.js, que importa las funciones de los dos módulos anteriores.

JavaScript — js/main.js 
import {
  esNumeroNoNegativo,
  esCantidadValida
} from "./validaciones.js";

import {
  calcularSubtotal,
  aplicarDescuento,
  calcularIVA,
  calcularTotal
} from "./calculos.js";

const precio = 80;
const cantidad = 2;
const descuento = 10;

if (
  esNumeroNoNegativo(precio) &&
  esCantidadValida(cantidad) &&
  esNumeroNoNegativo(descuento) &&
  descuento <= 100
) {
  const subtotal = calcularSubtotal(precio, cantidad);

  const base = aplicarDescuento(subtotal, descuento);

  const iva = calcularIVA(base);

  const total = calcularTotal(base, iva);

  console.log("Subtotal:", subtotal.toFixed(2), "€");
  console.log("Base con descuento:", base.toFixed(2), "€");
  console.log("IVA:", iva.toFixed(2), "€");
  console.log("Total:", total.toFixed(2), "€");
} else {
  console.log("Los datos del pedido no son válidos.");
}

El módulo principal no necesita conocer los detalles internos de cada cálculo. Simplemente importa las funciones y las utiliza en el orden adecuado.

5. Documento HTML

El documento HTML carga el módulo principal.

HTML — index.html 
<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Gestión de pedidos</title>
</head>
<body>

  <h1>Gestión de pedidos</h1>

  <script type="module" src="js/main.js"></script>

</body>
</html>

6. Resultado del programa

Para un producto de 80 euros, una cantidad de 2 unidades y un descuento del 10 %, el resultado será:

Resultado en consola 
Subtotal: 160.00 €
Base con descuento: 144.00 €
IVA: 30.24 €
Total: 174.24 €

El cálculo se realiza de la siguiente manera:

Operación Cálculo Resultado
Subtotal 80 × 2 160,00 €
Descuento 160 × 10 / 100 16,00 €
Base con descuento 160 - 16 144,00 €

7. Ventajas de esta organización

El programa está dividido en tres módulos con responsabilidades claramente diferenciadas.

Si necesitamos modificar las validaciones, trabajaremos principalmente en validaciones.js.

Si queremos añadir un nuevo cálculo, podremos incorporarlo a calculos.js.

Y si necesitamos cambiar el flujo de ejecución o la forma de presentar resultados, podremos modificar main.js.

💻 Ejemplo DAW

En una aplicación profesional, esta organización podría ampliarse con módulos para gestionar usuarios, productos, pedidos y comunicación con el servidor.

El principio seguiría siendo el mismo: dividir la aplicación en partes con responsabilidades definidas y dependencias comprensibles.

⚠️ Atención

Este ejemplo es didáctico y utiliza operaciones con números de tipo Number.

En aplicaciones económicas reales, deben considerarse también las reglas de redondeo, la precisión decimal y el tratamiento adecuado de importes monetarios.

Ver una posible solución

1. Número de archivos JavaScript. El proyecto contiene dos archivos: operaciones.js y main.js.

2. Módulo principal. Es main.js, porque el documento HTML lo carga mediante type="module". Desde él se importan las funciones necesarias.

3. Funciones exportadas. operaciones.js exporta sumar(), multiplicar() y calcular().

4. Uso de duplicar(). La función duplicar() está declarada dentro de operaciones.js. Por eso otras funciones del mismo módulo pueden utilizarla, aunque no esté exportada.

5. Importación de duplicar(). No podemos importarla directamente mediante una importación con nombre porque no está exportada. Para permitirlo, tendríamos que añadir export a su declaración o exportarla posteriormente.

6. Resultado de la suma. sumar(4, 6) devuelve 10.

7. Resultado de la multiplicación. multiplicar(3, 5) devuelve 15.

8. Resultado de calcular(7). La función llama primero a duplicar(7), que devuelve 14. Después suma 5, por lo que el resultado final es 19.

9. Resultado completo en consola.

Resultado en consola 
Suma: 10
Multiplicación: 15
Cálculo: 19

10. Función de type="module". Indica al navegador que debe interpretar main.js como un módulo JavaScript, permitiendo utilizar las importaciones.

11. Ruta incorrecta. Si la ruta no apunta al archivo correcto, el navegador no podrá cargar el módulo importado y la ejecución del módulo principal fallará.

12. Nueva función restar(). Podemos añadir la siguiente función a operaciones.js:

JavaScript — operaciones.js 
export function restar(a, b) {
  return a - b;
}

Después, desde main.js, podemos importar las cuatro funciones:

JavaScript — main.js 
import {
  sumar,
  multiplicar,
  calcular,
  restar
} from "./operaciones.js";

console.log(restar(10, 4));
