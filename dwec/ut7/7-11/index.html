7.11 Objeto history: historial de navegación

En el apartado anterior hemos utilizado location para consultar direcciones y navegar entre páginas. Ahora estudiaremos cómo desplazarnos por el historial de navegación mediante el objeto history del navegador.

Esta funcionalidad resulta útil para incorporar botones de «Volver» o «Avanzar» en una aplicación web, aunque debemos conocer sus limitaciones.

📌 Importante

window.history permite solicitar desplazamientos entre entradas del historial de la pestaña o ventana actual. No permite consultar libremente las direcciones de las páginas visitadas.

El objeto history

El objeto history pertenece al entorno del navegador y puede utilizarse como window.history o simplemente history. Representa la interfaz para trabajar con el historial de sesión asociado al contexto de navegación actual.

JavaScript
console.log(window.history === history); // true
console.log(typeof history.back);      // "function"

La primera instrucción comprueba que ambas expresiones hacen referencia al mismo objeto. La segunda indica que back es un método.

⚠️ Atención

El historial de sesión no es una lista de páginas que JavaScript pueda leer. El navegador protege esa información por motivos de privacidad.

Longitud del historial

La propiedad history.length devuelve el número de entradas del historial de sesión del contexto actual, incluida la entrada en la que nos encontramos.

JavaScript
console.log(history.length);

El resultado depende de cómo se haya llegado a la página y de las navegaciones realizadas. Por ejemplo, podría mostrar 3, pero no hay un valor fijo para todos los usuarios.

📌 Importante

history.length no indica cuántas páginas distintas se han visitado ni permite saber si existe una entrada posterior disponible. Una longitud mayor que 1 tampoco garantiza que al pulsar «Atrás» se regrese a una página de nuestra aplicación.

history.back()

El método history.back() solicita volver una entrada hacia atrás en el historial, de manera similar al botón «Atrás» del navegador.

JavaScript
// Solicita volver a la entrada anterior
history.back();

Si no existe una entrada anterior, no se produce el desplazamiento esperado. Si existe, la navegación puede llevar a otra página de nuestro proyecto o incluso a un sitio web diferente.

⚠️ Atención

No ejecutes history.back() directamente en la consola de los apuntes si no deseas abandonar el apartado actual.

history.forward()

El método history.forward() solicita avanzar una entrada hacia delante, siempre que exista una entrada posterior disponible.

JavaScript
// Solicita avanzar a la entrada siguiente
history.forward();

Este método suele resultar útil después de haber retrocedido. Si no hay una entrada posterior, la llamada no tiene un efecto visible.

💻 Ejemplo DAW

Si el usuario consulta el catálogo, abre una ficha y retrocede, un botón «Avanzar» podría solicitar el regreso a la ficha mediante history.forward(). El resultado dependerá del historial real de la pestaña.

history.go()

El método history.go(desplazamiento) permite solicitar un movimiento relativo a la entrada actual. El argumento es un número entero que indica cuántas posiciones deseamos movernos.

InstrucciónSignificado
history.go(-1)Retroceder una entrada; equivalente a back().
history.go(1)Avanzar una entrada; equivalente a forward().
history.go(-2)Solicitar retroceder dos entradas.
history.go(2)Solicitar avanzar dos entradas.
JavaScript
// Ejemplos de navegación: ejecutar solo el que necesites
history.go(-1); // Una entrada atrás
history.go(1);  // Una entrada adelante
history.go(-2); // Dos entradas atrás

Si el desplazamiento solicitado no es posible, puede no producirse ninguna navegación. Con history.go(0) se solicita recargar el documento actual; para explicar una recarga explícita ya conocemos location.reload().

Limitaciones y seguridad

El navegador impone restricciones al acceso al historial para proteger la privacidad de las personas. Podemos solicitar movimientos, pero no obtener una lista completa de páginas anteriores y posteriores.

Podemos hacerNo podemos hacer con esta API
Consultar history.length.Leer las URL de todas las entradas visitadas.
Solicitar retroceder o avanzar.Garantizar que la entrada anterior pertenece a nuestra web.
Desplazarnos varias posiciones con go().Conocer de forma fiable el número de entradas disponibles hacia delante.
⚠️ Atención

No utilices history.back() como única forma de regresar a una sección concreta de tu aplicación: puede conducir a una web externa o no realizar ningún desplazamiento. Si necesitas un destino garantizado, utiliza un enlace conocido o location.assign().

Relación con location

En el 7.10 vimos que location.assign() realiza una navegación ordinaria y que location.replace() sustituye la entrada actual. Ahora entendemos por qué esto afecta al comportamiento de history.back(): una entrada reemplazada no permanece como paso independiente al que regresar.

Ejemplos prácticos

Ejemplo 1. Mostrar la longitud del historial

Podemos informar al usuario del número de entradas registradas, sin suponer que todas pertenecen a nuestra aplicación.

JavaScript
const totalEntradas = history.length;
console.log("Entradas del historial:", totalEntradas);

Salida orientativa:

Consola
Entradas del historial: 3

El valor 3 es únicamente ilustrativo; en tu navegador puede aparecer otro.

Ejemplo 2. Botones para retroceder y avanzar

En una página que contenga los botones con los identificadores indicados, podemos asociarles los métodos del historial:

HTML
<button id="volver" type="button">Volver</button>
<button id="avanzar" type="button">Avanzar</button>
JavaScript
const botonVolver = document.querySelector("#volver");
const botonAvanzar = document.querySelector("#avanzar");

botonVolver.addEventListener("click", () => {
  history.back();
});

botonAvanzar.addEventListener("click", () => {
  history.forward();
});

Los métodos se ejecutan únicamente al pulsar los botones. Si el historial no permite el movimiento solicitado, la página puede permanecer igual.

Ejemplo 3. Volver a una página conocida

Cuando queremos garantizar que el botón conduzca al catálogo de nuestra aplicación, es preferible indicar su dirección de forma explícita.

JavaScript
const botonCatalogo = document.querySelector("#irCatalogo");

botonCatalogo.addEventListener("click", () => {
  location.assign("catalogo.html");
});

Este ejemplo presupone la existencia de un botón con id="irCatalogo" y de la página catalogo.html. A diferencia de history.back(), el destino no depende de las páginas visitadas anteriormente.

💻 Ejemplo DAW

En una aplicación de gestión de pedidos, los botones «Atrás» y «Adelante» pueden aprovechar history, pero un botón «Volver al listado de pedidos» debería utilizar una ruta conocida para ofrecer un resultado previsible.

💭 Piensa

Imagina que un usuario visita las páginas Inicio → Catálogo → Producto en la misma pestaña. Se encuentra en «Producto» y ejecuta estas instrucciones en orden, esperando a que termine cada navegación. ¿En qué página terminará? ¿Qué diferencia existe entre history.back() y history.go(-1)?

JavaScript
// Situación inicial: Producto
history.back();
// Tras la navegación: se ejecuta desde Catálogo
history.forward();

Supón que no hay redirecciones ni otras navegaciones intermedias.

Ver una posible solución

La primera instrucción solicita volver de Producto a Catálogo. Una vez cargada la página Catálogo, la segunda solicita avanzar de nuevo a Producto.

Resultado esperado: el usuario termina en Producto.

history.back() y history.go(-1) son equivalentes: ambos solicitan retroceder una entrada. El ejemplo es una secuencia conceptual: la segunda instrucción tendría que ejecutarse después de cargar Catálogo, no como continuación automática del mismo script de Producto.
