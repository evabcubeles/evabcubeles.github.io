7.12 Objetos navigator y screen

En los apartados anteriores hemos estudiado cómo trabajar con la ventana, la dirección de la página y el historial. Ahora conoceremos dos objetos del navegador que permiten consultar información sobre el entorno en el que se ejecuta nuestra aplicación: navigator y screen.

Estos objetos pueden ayudarnos a adaptar ciertas funciones de una web a las capacidades disponibles, pero debemos interpretar sus datos con cuidado: no todas las propiedades identifican con precisión el dispositivo ni garantizan una característica.

📌 Importante

navigator proporciona información y acceso a determinadas capacidades del navegador; screen describe características de la pantalla. Ambos se consultan desde JavaScript ejecutado en un navegador.

El objeto navigator

El objeto navigator forma parte del entorno del navegador y está disponible mediante window.navigator o, normalmente, navigator. Expone información del entorno y distintas interfaces relacionadas con las capacidades del navegador.

JavaScript
console.log(window.navigator === navigator); // true
console.log(navigator.language);

La primera instrucción comprueba que ambas expresiones hacen referencia al mismo objeto. La segunda consulta el idioma preferido que comunica el navegador.

⚠️ Atención

Los datos de navigator pueden depender de la configuración del navegador, de las medidas de privacidad o del contexto de ejecución. No deben utilizarse como prueba infalible de la identidad del usuario, su sistema operativo o su dispositivo.

Propiedades de navigator

Entre las propiedades que podemos consultar destacan las siguientes:

PropiedadQué indicaPrecaución
navigator.languageIdioma preferido comunicado por el navegador.Puede diferir del idioma de la página.
navigator.languagesLista ordenada de idiomas preferidos.Su contenido puede variar según el navegador.
navigator.onLineEstado de conectividad que estima el navegador.true no garantiza acceso a Internet ni al servidor.
navigator.cookieEnabledSi el navegador comunica que las cookies están habilitadas.No garantiza que todas las cookies se puedan guardar o leer.
navigator.userAgentCadena de identificación comunicada por el navegador.Puede estar reducida, modificada o ser poco fiable.
JavaScript
console.log("Idioma:", navigator.language);
console.log("Idiomas:", navigator.languages);
console.log("Conectividad estimada:", navigator.onLine);
console.log("Cookies habilitadas:", navigator.cookieEnabled);

Los resultados dependen del navegador y de su configuración. Por ejemplo, navigator.language podría devolver "es-ES", pero no debemos suponer que será igual para todo el alumnado.

⚠️ Atención

navigator.onLine no es una comprobación real de que nuestro servidor responda. Para saber si una petición funciona, debemos realizarla y gestionar su posible error; esto se estudiará al trabajar con la comunicación asíncrona.

Capacidades del navegador

Además de propiedades informativas, navigator da acceso a ciertas funcionalidades. Algunas están disponibles únicamente en contextos seguros (habitualmente HTTPS o localhost) y otras requieren permisos o una interacción del usuario.

Una práctica recomendable es comprobar si existe la API que necesitamos antes de utilizarla. Este enfoque se conoce como detección de características (feature detection).

JavaScript
if ("geolocation" in navigator) {
  console.log("La API de geolocalización está disponible");
} else {
  console.log("La API de geolocalización no está disponible");
}

Esta comprobación solo verifica la presencia de la interfaz: no solicita la ubicación y tampoco garantiza que el usuario conceda permiso o que se obtenga una posición.

JavaScript
if (navigator.clipboard && navigator.clipboard.writeText) {
  console.log("Existe la función para copiar texto");
} else {
  console.log("No se dispone de esa función de copia");
}

En el ejemplo comprobamos la existencia de navigator.clipboard.writeText sin ejecutar ninguna copia. En una aplicación real, su uso puede exigir un contexto seguro y una acción del usuario, como pulsar un botón.

💻 Ejemplo DAW

En una aplicación de pedidos podemos ofrecer un botón «Copiar referencia» cuando la API del portapapeles esté disponible y mostrar una alternativa cuando no lo esté. Así evitamos depender exclusivamente del nombre del navegador.

El objeto screen

El objeto screen proporciona información sobre la pantalla asociada al contexto de navegación. Se puede consultar como window.screen o screen.

JavaScript
console.log(window.screen === screen); // true
console.log("Ancho de pantalla:", screen.width);
console.log("Alto de pantalla:", screen.height);

Las dimensiones se expresan habitualmente en píxeles CSS, que no tienen por qué coincidir con los píxeles físicos del panel. Además, los resultados pueden estar limitados o redondeados por motivos de privacidad.

📌 Importante

screen.width y screen.height describen la pantalla, no el espacio disponible dentro de la página web. Para conocer el tamaño del área visible de la ventana podemos consultar window.innerWidth y window.innerHeight, estudiados en el 7.8.

Dimensiones de pantalla

Estas son algunas de las propiedades más utilizadas:

PropiedadSignificado
screen.widthAncho comunicado de la pantalla.
screen.heightAlto comunicado de la pantalla.
screen.availWidthAncho disponible comunicado, que puede excluir zonas reservadas por el sistema.
screen.availHeightAlto disponible comunicado, que puede excluir zonas reservadas por el sistema.
screen.colorDepthProfundidad de color comunicada, expresada en bits por píxel.
JavaScript
console.log("Pantalla:", screen.width, "x", screen.height);
console.log("Disponible:", screen.availWidth, "x", screen.availHeight);
console.log("Ventana:", window.innerWidth, "x", window.innerHeight);

En un ordenador con una ventana del navegador reducida, el ancho de pantalla puede ser mayor que innerWidth. En móviles, los valores también dependen del navegador y de la configuración de visualización.

⚠️ Atención

No utilices screen.width para decidir por sí solo si una web debe mostrarse en formato móvil o de escritorio. Para adaptar la presentación se recomiendan diseños responsive y media queries de CSS, que responden al espacio de visualización.

Ejemplos prácticos

Ejemplo 1. Mostrar el idioma y el estado de conexión

Podemos consultar estos datos y mostrarlos en la consola:

JavaScript
const idioma = navigator.language;
const estado = navigator.onLine ? "Conectado" : "Sin conexión detectada";

console.log("Idioma preferido:", idioma);
console.log("Estado estimado:", estado);

Posible salida:

Consola
Idioma preferido: es-ES
Estado estimado: Conectado

Es una salida orientativa: el idioma y el estado pueden ser diferentes. El texto «Conectado» no demuestra que el servidor de nuestra aplicación sea accesible.

Ejemplo 2. Comparar pantalla y ventana

Este programa compara las dimensiones comunicadas de la pantalla con las del área interior de la ventana.

JavaScript
const anchoPantalla = screen.width;
const anchoVentana = window.innerWidth;

console.log("Ancho de pantalla:", anchoPantalla);
console.log("Ancho de ventana:", anchoVentana);

if (anchoVentana < anchoPantalla) {
  console.log("La ventana es más estrecha que la pantalla");
} else {
  console.log("La ventana no es más estrecha que la pantalla");
}

El resultado depende del entorno. Esta comparación sirve para comprender la diferencia entre ambos valores, pero no para identificar con certeza el tipo de dispositivo.

Ejemplo 3. Mostrar información del navegador en una página

Supongamos que una aplicación dispone de un elemento donde queremos presentar información básica del entorno.

HTML
<p id="informacionNavegador"></p>
JavaScript
const informacion = document.querySelector("#informacionNavegador");

if (informacion) {
  informacion.textContent =
    `Idioma: ${navigator.language}. ` +
    `Pantalla: ${screen.width} x ${screen.height}.`;
}

Utilizamos textContent para mostrar el resultado como texto. El ejemplo presupone que el elemento HTML ya existe cuando se ejecuta el script.

💻 Ejemplo DAW

En un panel de soporte técnico de una tienda online, estos datos pueden ayudar a describir el entorno del usuario. Sin embargo, conviene solicitar solo la información necesaria y no tratarla como una identificación inequívoca del dispositivo.

💭 Piensa

Observa el siguiente código sin ejecutarlo. Supón que el navegador comunica navigator.language === "es-ES", navigator.onLine === true, screen.width === 1920 y window.innerWidth === 900.

JavaScript
console.log(navigator.language);
console.log(navigator.onLine);
console.log(screen.width > window.innerWidth);

¿Qué tres valores aparecerán en la consola? ¿Podemos concluir que existe conexión con el servidor de la aplicación?

Ver una posible solución

La salida será:

Consola
es-ES
true
true

El tercer valor es true porque 1920 > 900. Sin embargo, navigator.onLine === true no garantiza que el servidor de la aplicación responda; únicamente refleja el estado de conectividad estimado por el navegador.
