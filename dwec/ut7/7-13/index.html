7.13 Almacenamiento en el navegador

En los apartados anteriores hemos aprendido a consultar información del navegador y de la pantalla. Ahora estudiaremos cómo guardar datos en el propio navegador para recuperarlos durante la navegación o en visitas posteriores. Esta capacidad resulta útil, por ejemplo, para recordar preferencias de visualización o conservar temporalmente información de un formulario.

Nos centraremos en localStorage, sessionStorage y las cookies. Aunque los tres mecanismos permiten conservar información, tienen diferencias importantes en duración, alcance y funcionamiento.

📌 Importante

El almacenamiento del navegador no sustituye a una base de datos del servidor. Los datos pueden borrarse, modificarse o no estar disponibles. Nunca debemos guardar contraseñas, tokens de autenticación ni otra información sensible en localStorage o sessionStorage.

Introducción al almacenamiento web

Una variable de JavaScript mantiene su valor mientras existe el contexto de ejecución correspondiente. Si recargamos una página, las variables se crean de nuevo y, normalmente, se pierde su estado anterior. Para conservar ciertos datos podemos recurrir al almacenamiento que ofrece el navegador.

JavaScript
let contador = 1;
contador++;
console.log(contador); // 2

// Al recargar la página, este script comienza de nuevo.

La API Web Storage proporciona dos objetos principales: localStorage y sessionStorage. Ambos almacenan pares clave–valor y sus valores son cadenas de texto.

⚠️ Atención

Para realizar las pruebas utiliza una página servida mediante Live Server u otro servidor local (http://localhost o una dirección local equivalente). Con archivos abiertos mediante file:, el comportamiento del almacenamiento puede variar entre navegadores.

localStorage

localStorage permite guardar información que, en condiciones normales, permanece después de cerrar la pestaña o reiniciar el navegador. Los datos se asocian al origen de la página (protocolo, dominio y puerto), y pueden ser eliminados por el usuario o por el propio navegador.

JavaScript
localStorage.setItem("idioma", "es");

const idioma = localStorage.getItem("idioma");
console.log(idioma); // "es"

Si ejecutamos el código, recargamos la página y volvemos a consultar la clave "idioma", normalmente recuperaremos el valor guardado.

💻 Ejemplo DAW

Una aplicación web puede recordar si el usuario prefiere el modo oscuro. De hecho, nuestros apuntes digitales utilizan localStorage para conservar la preferencia de tema entre páginas.

sessionStorage

sessionStorage utiliza la misma forma de trabajo que localStorage, pero sus datos pertenecen a la sesión de una pestaña o contexto de navegación. Se conservan al recargar la página y normalmente se eliminan al cerrar esa pestaña.

JavaScript
sessionStorage.setItem("pasoFormulario", "2");

console.log(sessionStorage.getItem("pasoFormulario")); // "2"

Dos pestañas independientes de un mismo sitio no comparten normalmente la misma sesión de sessionStorage. No obstante, algunas formas de abrir o duplicar pestañas pueden crear una copia inicial de sus datos; posteriormente, cada una mantiene su propio almacenamiento.

📌 Importante

localStorage y sessionStorage están separados por origen. Además, sessionStorage está separado por sesión de pestaña. No confundas «cerrar una pestaña» con «recargar una página»: la recarga no borra automáticamente sessionStorage.

Métodos de almacenamiento

Los dos objetos ofrecen los mismos métodos básicos:

Método o propiedadFunción
setItem(clave, valor)Guarda un valor asociado a una clave; si existe, lo sustituye.
getItem(clave)Recupera el valor de una clave; devuelve null si no existe.
removeItem(clave)Elimina únicamente la clave indicada.
clear()Elimina todas las claves del almacenamiento correspondiente para ese origen y ámbito.
key(indice)Devuelve la clave situada en una posición o null si no existe.
lengthIndica el número de claves almacenadas.
JavaScript
localStorage.setItem("usuario", "Ana");
localStorage.setItem("color", "verde");

console.log(localStorage.getItem("usuario")); // "Ana"
console.log(localStorage.getItem("inexistente")); // null
console.log(localStorage.length); // Número de claves existentes

localStorage.removeItem("usuario");
// localStorage.clear(); // Borra TODAS las claves de este origen

El valor de length puede ser mayor de lo esperado porque otras partes de la web pueden haber guardado información. En particular, no ejecutes localStorage.clear() sin pensar: también podrías borrar la preferencia de tema de estos apuntes.

Los valores se guardan como texto

JavaScript
localStorage.setItem("cantidad", 5);

const cantidad = localStorage.getItem("cantidad");
console.log(cantidad);        // "5"
console.log(typeof cantidad); // "string"

const cantidadNumerica = Number(cantidad);
console.log(cantidadNumerica + 1); // 6

Aunque enviemos un número a setItem(), se convierte a texto. Al recuperarlo, debemos convertirlo si necesitamos realizar operaciones numéricas.

Almacenamiento de objetos con JSON

Los objetos y arrays no deben guardarse directamente mediante setItem(), porque el almacenamiento admite cadenas. Para conservar su estructura utilizamos JSON.stringify() al guardar y JSON.parse() al recuperar, métodos estudiados en el apartado 7.6.

JavaScript
const preferencias = {
  tema: "oscuro",
  avisos: true,
  productosPorPagina: 12
};

localStorage.setItem("preferenciasDemo", JSON.stringify(preferencias));

const texto = localStorage.getItem("preferenciasDemo");
const preferenciasRecuperadas = JSON.parse(texto);

console.log(preferenciasRecuperadas.tema); // "oscuro"

Si la clave no existe, getItem() devuelve null. Además, si el texto almacenado no contiene un JSON válido, JSON.parse() produce un error. Por eso, cuando trabajamos con datos que pueden haber sido modificados, conviene controlar ambos casos.

JavaScript
function recuperarPreferencias() {
  const texto = localStorage.getItem("preferenciasDemo");

  if (texto === null) {
    return null;
  }

  try {
    return JSON.parse(texto);
  } catch (error) {
    console.log("No se pudieron recuperar las preferencias");
    return null;
  }
}

console.log(recuperarPreferencias());
⚠️ Atención

El navegador puede bloquear el acceso al almacenamiento o quedarse sin espacio, y algunas operaciones pueden lanzar excepciones. Además, los datos recuperados pueden estar manipulados: comprueba su estructura y valores antes de utilizarlos.

Cookies

Las cookies son pequeños datos asociados a un sitio web. A diferencia de Web Storage, las cookies que cumplen las condiciones correspondientes pueden enviarse automáticamente al servidor en las peticiones HTTP. Por eso se utilizan, entre otras finalidades, para gestionar sesiones mediante cookies configuradas por el servidor.

En JavaScript podemos consultar o establecer determinadas cookies mediante document.cookie, pero no podemos leer las marcadas con el atributo HttpOnly.

JavaScript
document.cookie = "idiomaWeb=es; Path=/; SameSite=Lax";
console.log(document.cookie);

El ejemplo crea una cookie accesible desde JavaScript con un valor sencillo. Al no indicar Max-Age ni Expires, se trata de una cookie de sesión; su eliminación efectiva puede depender de la restauración de sesiones del navegador.

JavaScript
document.cookie = "idiomaWeb=es; Max-Age=3600; Path=/; SameSite=Lax";

// Para eliminar esta cookie, usamos la misma ruta:
document.cookie = "idiomaWeb=; Max-Age=0; Path=/; SameSite=Lax";

La lectura de document.cookie devuelve una cadena con las cookies accesibles desde el documento, no un objeto con claves y valores como localStorage.

⚠️ Atención

Las cookies relacionadas con autenticación deberían configurarse desde el servidor con medidas adecuadas como HttpOnly, Secure y SameSite. Las cookies no deben utilizarse como un lugar seguro para guardar contraseñas. Además, según su finalidad, puede ser necesario informar al usuario y obtener su consentimiento conforme a la normativa aplicable.

Los tres mecanismos tienen límites de tamaño y pueden estar restringidos por las opciones de privacidad del navegador. No son adecuados para almacenar información crítica sin respaldo.

Ejemplos prácticos

Ejemplo 1. Recordar una preferencia de visualización

Guardamos una preferencia sencilla y la recuperamos en una visita posterior:

JavaScript
const clave = "tamanoTextoDemo";

localStorage.setItem(clave, "grande");

const tamanoGuardado = localStorage.getItem(clave);
console.log("Tamaño preferido:", tamanoGuardado);

Este ejemplo es similar al mecanismo que utilizan nuestros apuntes para recordar el modo claro u oscuro.

Ejemplo 2. Conservar temporalmente un paso del formulario

JavaScript
sessionStorage.setItem("pasoPedidoDemo", "3");

const paso = Number(sessionStorage.getItem("pasoPedidoDemo"));

if (Number.isInteger(paso) && paso >= 1) {
  console.log("Continuar desde el paso:", paso);
} else {
  console.log("Comenzar desde el primer paso");
}

Al recargar la pestaña, el paso puede seguir disponible. Al cerrar la sesión de esa pestaña, normalmente desaparecerá. En una aplicación real también deberíamos comprobar que el paso pertenece al rango permitido.

Ejemplo 3. Guardar un carrito sencillo

JavaScript
const carrito = [
  { id: 1, nombre: "Teclado", cantidad: 2 },
  { id: 2, nombre: "Ratón", cantidad: 1 }
];

localStorage.setItem("carritoDemo", JSON.stringify(carrito));

const textoCarrito = localStorage.getItem("carritoDemo");
let carritoRecuperado = [];

if (textoCarrito !== null) {
  try {
    const datos = JSON.parse(textoCarrito);
    if (Array.isArray(datos)) {
      carritoRecuperado = datos;
    }
  } catch (error) {
    console.log("El carrito guardado no es válido");
  }
}

console.log(carritoRecuperado);

La comprobación con Array.isArray() evita asumir que el JSON recuperado contiene necesariamente un array. Para una aplicación real también sería necesario validar cada producto y sus cantidades.

💻 Ejemplo DAW

En una tienda online desarrollada en DAW, localStorage puede servir para recordar preferencias o un carrito provisional. Sin embargo, el precio definitivo, el stock y la validación del pedido deben comprobarse en el servidor: el cliente puede modificar los datos almacenados.

💭 Piensa

Observa el siguiente código sin ejecutarlo. Supón que las claves utilizadas no existían antes y que las operaciones se completan correctamente:

JavaScript
localStorage.setItem("numeroDemo", 8);
sessionStorage.setItem("estadoDemo", "pendiente");

console.log(typeof localStorage.getItem("numeroDemo"));
console.log(localStorage.getItem("numeroDemo") + 2);
console.log(sessionStorage.getItem("estadoDemo"));

localStorage.removeItem("numeroDemo");
console.log(localStorage.getItem("numeroDemo"));

¿Qué cuatro valores aparecerán en la consola? ¿Qué ocurrirá normalmente con estadoDemo al recargar la pestaña?

Ver una posible solución

La salida será:

Consola
string
82
pendiente
null

getItem() devuelve texto, por eso 8 se recupera como "8" y "8" + 2 produce "82". Después de removeItem(), la clave ya no existe y getItem() devuelve null. La clave estadoDemo normalmente seguirá disponible tras recargar la misma pestaña, porque está en sessionStorage.
