7.14 Interacción con el usuario y aplicación práctica del BOM

A lo largo de la UT7 hemos estudiado objetos nativos de JavaScript y herramientas del Browser Object Model (BOM). Ahora vamos a relacionarlos para resolver una necesidad concreta: construir una pequeña aplicación que interactúe con el usuario, consulte información del navegador y recuerde algunos datos.

El objetivo no es memorizar métodos aislados, sino aprender a elegir el objeto adecuado, organizar las funciones y comprobar el comportamiento de la aplicación.

📌 Importante

El BOM permite trabajar con la ventana y el entorno del navegador. Para modificar elementos de la página se utiliza el DOM, que estudiaremos con detalle en la UT8. En el ejemplo final aparecerán unas pocas operaciones básicas del DOM para mostrar resultados en pantalla.

Planteamiento de una aplicación

Imaginemos una pequeña aplicación llamada Panel de consulta de pedidos. El usuario podrá escribir su nombre y un identificador de pedido, consultar un resumen y conservar sus preferencias entre visitas.

Requisitos funcionales

  • Solicitar un nombre y un código de pedido mediante una interfaz sencilla.
  • Comprobar que el código tiene un formato válido.
  • Mostrar la fecha y la hora de la consulta.
  • Recordar el nombre del usuario entre visitas y el último código consultado durante la sesión de la pestaña.
  • Permitir limpiar los datos de demostración y mostrar mensajes de confirmación.
  • Consultar el idioma del navegador y los parámetros de la URL.

Antes de programar conviene separar las entradas (nombre, código), el procesamiento (validación y preparación de datos) y las salidas (mensajes, resultados y almacenamiento).

EntradaProcesoSalida
Nombre del usuarioEliminar espacios y comprobar que no está vacíoSaludo personalizado
Código de pedidoNormalizar a mayúsculas y validar el patrónCódigo aceptado o aviso de error
Fecha actualCrear y formatear un objeto DateFecha y hora de la consulta
Preferencias guardadasLeer localStorage y sessionStorageRecuperación de datos al abrir o recargar
💻 Ejemplo DAW

En una aplicación de gestión de pedidos, el navegador puede facilitar la interacción, pero la existencia real de un pedido, sus precios y su estado deben comprobarse en el servidor. Nuestro panel es una simulación local, no una consulta a una base de datos.

Selección de objetos predefinidos

Una vez definidos los requisitos, identificamos qué objetos y métodos nos ayudan a implementarlos.

Objeto o APIAplicación en el panel
String y RegExpLimpiar el texto y comprobar el formato del código.
DateObtener y mostrar la fecha de la consulta.
JSONConvertir datos estructurados en texto si necesitamos almacenarlos.
windowMostrar diálogos y utilizar temporizadores.
location y URLSearchParamsConsultar parámetros de la dirección actual.
navigatorConocer el idioma preferido del navegador.
localStorageRecordar el nombre entre visitas.
sessionStorageConservar el último código durante la sesión de la pestaña.

No es necesario utilizar todos los objetos estudiados en cada aplicación. Por ejemplo, Math, screen o history solo deben incorporarse cuando resuelvan una necesidad real.

JavaScript
function validarCodigo(codigo) {
  const patron = /^PED-\d{4}$/;
  return patron.test(codigo.trim().toUpperCase());
}

console.log(validarCodigo("ped-0025")); // true
console.log(validarCodigo("pedido25")); // false

La expresión regular exige el prefijo PED- seguido de cuatro dígitos. El método trim() elimina espacios iniciales y finales, y toUpperCase() normaliza el código.

Navegación e interacción

El BOM ofrece formas sencillas de comunicarnos con el usuario. alert() muestra un aviso, confirm() solicita una confirmación y prompt() permite introducir texto. En una aplicación completa suelen utilizarse formularios HTML, pero estos métodos siguen siendo útiles para comprender la interacción.

JavaScript
const respuesta = prompt("Introduce un código de pedido:");

if (respuesta === null) {
  console.log("El usuario canceló la operación");
} else if (respuesta.trim() === "") {
  alert("Debes introducir un código");
} else {
  console.log("Código introducido:", respuesta.trim());
}
⚠️ Atención

prompt() devuelve una cadena de texto o null si se cancela. Comprueba null antes de llamar a métodos como trim().

Consultar parámetros de la URL

Podemos obtener información de la dirección actual sin cambiar de página. Por ejemplo, una URL como http://localhost:5500/dwec/ut7/7-14/index.html?origen=clase contiene un parámetro llamado origen.

JavaScript
const parametros = new URLSearchParams(window.location.search);
const origen = parametros.get("origen");

console.log(origen); // "clase" si aparece ?origen=clase
// Si no existe el parámetro, devuelve null.

El método location.assign() permite navegar a otra dirección, pero en nuestro ejemplo no es necesario abandonar la página. Tampoco utilizaremos history.back() para controlar la lógica de los pedidos: el historial depende de la navegación real del usuario.

Temporizadores para avisos

JavaScript
const temporizador = setTimeout(() => {
  console.log("Han transcurrido 3 segundos");
}, 3000);

// Si queremos cancelar el aviso antes de ejecutarse:
// clearTimeout(temporizador);

Un temporizador programa una función para ejecutarse más adelante, pero no detiene el resto del programa. Para un aviso puntual es adecuado setTimeout(); para una acción repetida, setInterval() junto con clearInterval().

Persistencia de información

En nuestro panel distinguiremos entre una preferencia que interesa conservar y un dato temporal de la consulta actual.

DatoMecanismoMotivo
Nombre del usuariolocalStorageResulta útil recuperarlo en visitas posteriores.
Último código consultadosessionStorageSolo interesa durante la sesión de la pestaña.
Resultado de validaciónVariable de JavaScriptSe calcula cuando el usuario realiza la consulta.
JavaScript
localStorage.setItem("panel714_nombre", "Ana");
sessionStorage.setItem("panel714_ultimo", "PED-0025");

console.log(localStorage.getItem("panel714_nombre"));
console.log(sessionStorage.getItem("panel714_ultimo"));

Usaremos claves específicas de esta demostración para no interferir con otras funcionalidades de la web, como la preferencia de tema de los apuntes.

⚠️ Atención

Los datos almacenados en el navegador pueden modificarse o borrarse. No guardes contraseñas, tokens ni información sensible. Además, las operaciones de almacenamiento pueden fallar si el navegador las bloquea o no dispone de espacio.

Organización del código

Aunque la aplicación sea pequeña, es recomendable distribuir las responsabilidades entre funciones. Así podemos comprobar cada parte sin depender de toda la interfaz.

JavaScript
function normalizarCodigo(texto) {
  return texto.trim().toUpperCase();
}

function esCodigoValido(codigo) {
  return /^PED-\d{4}$/.test(codigo);
}

function fechaConsulta() {
  return new Date().toLocaleString("es-ES");
}

console.log(esCodigoValido(normalizarCodigo(" ped-0025 ")));

La función normalizarCodigo() transforma el dato, esCodigoValido() comprueba una regla y fechaConsulta() prepara un valor para mostrar. Esta separación evita repetir instrucciones y facilita las pruebas.

Separar la lógica de la presentación

La lógica decide si un código es válido; la presentación decide dónde mostrar el mensaje. En el ejemplo completo utilizaremos textContent para insertar resultados como texto, sin interpretar el contenido introducido por el usuario como HTML.

📌 Importante

La validación del navegador mejora la experiencia de uso, pero no sustituye la validación del servidor cuando se procesan pedidos reales.

Pruebas y depuración

Antes de considerar terminada la aplicación debemos comprobar casos correctos, incorrectos y situaciones especiales. La consola y las herramientas de desarrollo del navegador nos ayudan a localizar problemas.

PruebaEntrada o acciónResultado esperado
Código correctoped-0025Se normaliza a PED-0025 y se acepta.
Código incorrectoABC-25Se muestra un aviso de formato incorrecto.
Nombre vacíoSolo espaciosSe solicita un nombre válido.
Recarga de páginaRecargar la misma pestañaSe recuperan los datos guardados cuando están disponibles.
LimpiezaPulsar «Borrar datos» y confirmarSe eliminan únicamente las dos claves de la demostración.
CancelaciónCancelar el borradoSe mantienen los datos.
Parámetro ausenteAbrir la URL sin ?origen=...Se indica que no hay origen especificado.

También debemos comprobar el funcionamiento con el almacenamiento deshabilitado. El ejemplo completo controla los posibles errores y permite seguir realizando consultas aunque no pueda recordar los datos.

Ejemplo práctico completo

Vamos a reunir los conceptos en una página independiente. Crea una carpeta de prueba, añade un archivo index.html y copia el siguiente código. Ábrelo con Live Server para que el almacenamiento tenga un comportamiento predecible.

El panel permite consultar códigos con el formato PED-0000, recordar el nombre, recuperar el último código durante la sesión, consultar el idioma y mostrar el parámetro origen de la URL. Los códigos son ficticios: no se comprueba ningún pedido real.

HTML + JavaScript
<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Panel de consulta de pedidos</title>
</head>
<body>
  <h1>Panel de consulta de pedidos</h1>
  <label for="nombre">Nombre:</label>
  <input id="nombre" type="text">
  <label for="codigo">Código de pedido:</label>
  <input id="codigo" type="text" placeholder="PED-0025">
  <button id="consultar" type="button">Consultar</button>
  <button id="borrar" type="button">Borrar datos</button>
  <p id="resultado" role="status"></p>
  <p id="informacion"></p>

  <script>
    "use strict";

    const nombreInput = document.getElementById("nombre");
    const codigoInput = document.getElementById("codigo");
    const resultado = document.getElementById("resultado");
    const informacion = document.getElementById("informacion");

    function leer(tipo, clave) {
      try {
        const almacen = window[tipo];
        return almacen.getItem(clave);
      } catch (error) {
        console.warn("No se puede leer el almacenamiento", error);
        return null;
      }
    }

    function guardar(tipo, clave, valor) {
      try {
        const almacen = window[tipo];
        almacen.setItem(clave, valor);
      } catch (error) {
        console.warn("No se puede guardar el dato", error);
      }
    }

    function borrar(tipo, clave) {
      try {
        const almacen = window[tipo];
        almacen.removeItem(clave);
      } catch (error) {
        console.warn("No se puede borrar el dato", error);
      }
    }

    function normalizarCodigo(texto) {
      return texto.trim().toUpperCase();
    }

    function esCodigoValido(codigo) {
      return /^PED-\d{4}$/.test(codigo);
    }

    function consultarPedido() {
      const nombre = nombreInput.value.trim();
      const codigo = normalizarCodigo(codigoInput.value);

      if (nombre === "") {
        resultado.textContent = "Introduce tu nombre.";
        return;
      }

      if (!esCodigoValido(codigo)) {
        resultado.textContent = "Formato incorrecto. Usa PED-0000.";
        return;
      }

      guardar("localStorage", "panel714_nombre", nombre);
      guardar("sessionStorage", "panel714_ultimo", codigo);

      const fecha = new Date().toLocaleString("es-ES");
      resultado.textContent = `${nombre}, consulta simulada de ${codigo} realizada el ${fecha}.`;
    }

    function borrarDatos() {
      if (!confirm("¿Borrar los datos de esta demostración?")) {
        return;
      }

      borrar("localStorage", "panel714_nombre");
      borrar("sessionStorage", "panel714_ultimo");

      nombreInput.value = "";
      codigoInput.value = "";
      resultado.textContent = "Datos de demostración borrados.";
    }

    function iniciar() {
      nombreInput.value = leer("localStorage", "panel714_nombre") ?? "";
      codigoInput.value = leer("sessionStorage", "panel714_ultimo") ?? "";

      const parametros = new URLSearchParams(window.location.search);
      const origen = parametros.get("origen") ?? "no especificado";
      informacion.textContent = `Idioma: ${navigator.language}. Origen: ${origen}.`;
    }

    document.getElementById("consultar").addEventListener("click", consultarPedido);
    document.getElementById("borrar").addEventListener("click", borrarDatos);
    iniciar();
  </script>
</body>
</html>

Cómo comprobar el funcionamiento

  1. Abre el ejemplo con Live Server.
  2. Introduce Ana y ped-0025, y pulsa «Consultar».
  3. Recarga la pestaña: deberían recuperarse el nombre y el último código.
  4. Abre la misma página con ?origen=clase al final de la URL y observa el texto informativo.
  5. Pulsa «Borrar datos», confirma y comprueba que los campos quedan vacíos.

El ejemplo utiliza addEventListener(), getElementById() y textContent para conectar botones y resultados con la página. Estas operaciones pertenecen al DOM y se estudiarán con más detalle en la siguiente unidad.

💻 Ejemplo DAW

El código distingue entre datos del usuario, validación, persistencia e interfaz. Esta organización será útil cuando trabajemos con formularios y eventos en la UT8.

💭 Piensa

Supón que la página está abierta en una pestaña y que el almacenamiento funciona correctamente. Observa este código:

JavaScript
localStorage.setItem("panel714_nombre", "Lucía");
sessionStorage.setItem("panel714_ultimo", "PED-0042");

const codigo = " ped-0042 ".trim().toUpperCase();
console.log(/^PED-\d{4}$/.test(codigo));
console.log(localStorage.getItem("panel714_nombre"));

¿Qué dos resultados aparecen en la consola? ¿Qué dato se conserva normalmente tras cerrar y volver a abrir el navegador? ¿Cuál se conserva al recargar la misma pestaña?

Ver una posible solución

La consola muestra:

Consola
true
Lucía

La expresión regular acepta PED-0042 y el nombre recuperado es Lucía. localStorage suele conservar el nombre incluso después de cerrar el navegador, salvo borrado o restricciones. sessionStorage conserva normalmente el último código al recargar la misma pestaña, pero su duración está vinculada a esa sesión de pestaña.
