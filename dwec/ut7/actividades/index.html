📝 Actividades de la UT7

Para finalizar la UT7 vas a aplicar los conocimientos sobre objetos predefinidos de JavaScript y el modelo de objetos del navegador (BOM), trabajados en los apartados 7.1 a 7.14.

Las actividades se organizan en tres bloques: actividades prácticas, un reto final y una autoevaluación para comprobar los conocimientos fundamentales de la unidad.

📌 Importante

Debes distinguir entre los objetos propios del lenguaje (String, Math, Date, JSON...) y los objetos proporcionados por el navegador (window, location, navigator, localStorage...). Comprueba tus programas desde el navegador, preferentemente con Live Server.

💻 Actividades prácticas

Actividad 1 — Analiza cadenas con String

Analiza el código de partida y completa las tareas propuestas.

JavaScript · Código de partida
const texto = "  JavaScript en DAW  ";
console.log(texto.length);
console.log(texto.trim().toUpperCase());
console.log(texto.includes("DAW"));
  1. Predice las tres salidas antes de ejecutar el programa.
  2. Explica por qué trim() no modifica la variable original.
  3. Obtén únicamente la palabra JavaScript utilizando un método de cadenas.
  4. Crea una función que reciba un nombre, elimine espacios iniciales y finales y devuelva su primera letra en mayúscula.
  5. Prueba la función con una cadena vacía y explica cómo evitas errores.

Actividad 2 — Number y conversión de datos

Analiza el código de partida y completa las tareas propuestas.

JavaScript · Código de partida
const precio = "39.95";
const cantidad = "3";
const descuento = "10";
  1. Convierte los tres valores a números y calcula el importe del pedido antes del descuento.
  2. Aplica el descuento porcentual y muestra el total con dos decimales.
  3. Comprueba qué ocurre con Number("39,95") y explica el resultado.
  4. Valida los valores utilizando Number.isFinite() antes de calcular.
  5. Explica la diferencia entre un número y el texto devuelto por toFixed().

Actividad 3 — Cálculos con Math

Analiza el código de partida y completa las tareas propuestas.

JavaScript · Código de partida
const precios = [19.99, 42.50, 7.25, 105.10];
  1. Obtén el precio más alto y el más bajo con Math.max() y Math.min().
  2. Calcula la media de los precios y redondéala a dos decimales.
  3. Genera un identificador aleatorio entero entre 1000 y 9999, ambos incluidos.
  4. Explica por qué Math.random() no debe utilizarse para generar contraseñas o tokens de seguridad.
  5. Comprueba qué sucede si pasas directamente el array a Math.max(precios) y corrígelo.

Actividad 4 — Fechas con Date

Analiza el código de partida y completa las tareas propuestas.

JavaScript · Código de partida
const entrega = new Date(2026, 10, 15);
const hoy = new Date();
  1. Indica qué fecha representa new Date(2026, 10, 15) y explica cómo se numeran los meses.
  2. Muestra el año, mes y día de entrega.
  3. Calcula los días que faltan para la entrega utilizando marcas de tiempo; especifica cómo redondeas el resultado. Si la fecha de entrega ya ha pasado, interpreta el resultado negativo como días transcurridos desde la entrega. Explica también qué sucede si el cálculo se realiza el mismo día.
  4. Muestra la fecha de entrega con toLocaleDateString("es-ES").
  5. Explica por qué los cambios de horario pueden afectar a cálculos de días basados en milisegundos.

Actividad 5 — Métodos de Array

Analiza el código de partida y completa las tareas propuestas.

JavaScript · Código de partida
const pedidos = [
  { codigo: "PED-1001", total: 80, entregado: true },
  { codigo: "PED-1002", total: 125, entregado: false },
  { codigo: "PED-1003", total: 45, entregado: false }

  2. Localiza el pedido PED-1002 con find().
  3. Genera un nuevo array con solo los códigos mediante map().
  4. Calcula el importe total de todos los pedidos con reduce().
  5. Comprueba con some() si existe algún pedido superior a 100 €.

Actividad 7 — Validación con expresiones regulares

Analiza el código de partida y completa las tareas propuestas.

JavaScript · Código de partida
const codigos = ["PED-1234", "ped-1234", "PED-12", "PED-9999"];
const patron = /^PED-\d{4}$/;
  1. Predice qué códigos cumplen el patrón y compruébalo con test().
  2. Explica qué significan ^, \d{4} y $.
  3. Adapta la validación para aceptar minúsculas mediante una bandera de la expresión regular.
  4. Crea un patrón para validar un código de producto formado por ART- y tres cifras.
  5. Explica por qué una expresión regular en el cliente no sustituye la validación en el servidor.

Actividad 8 — Interacción con window y temporizadores

Analiza el código de partida y completa las tareas propuestas.

JavaScript · Código de partida
const nombre = window.prompt("Introduce tu nombre:");
console.log(nombre);
  1. Comprueba qué devuelve prompt() cuando el usuario pulsa Cancelar. Compara ese resultado con aceptar sin escribir nada e introducir únicamente espacios. Explica cómo tratarías cada caso antes de utilizar trim().
  2. Evita que se acepte un nombre vacío o formado solo por espacios.
  3. Solicita confirmación con window.confirm() antes de continuar.
  4. Programa un mensaje en consola después de dos segundos con setTimeout().
  5. Crea un contador con setInterval() y detenlo al llegar a cinco utilizando clearInterval().

Actividad 9 — Navegación y datos del navegador

Analiza el código de partida y completa las tareas propuestas.

JavaScript · Código de partida
const parametros = new URLSearchParams(window.location.search);
const codigo = parametros.get("pedido");
console.log(codigo);
console.log(navigator.language);
  1. Abre una página con la URL ?pedido=PED-1234 y comprueba el valor obtenido.
  2. Muestra un mensaje alternativo si no existe el parámetro pedido.
  3. Investiga qué información ofrece window.location.pathname.
  4. Explica la diferencia entre location.assign() y location.replace().
  5. Consulta navigator.language y screen.width, e indica por qué estos valores no identifican de forma fiable a una persona.

🧩 Reto final — Panel de consulta de pedidos con BOM

Una tienda de informática necesita una pequeña aplicación web que permita consultar pedidos, recordar preferencias y mostrar información contextual del navegador. Tu trabajo consiste en construir un panel de consulta de pedidos utilizando los objetos predefinidos de JavaScript y las herramientas del BOM.

Situación inicial

Los pedidos se simulan mediante datos locales. No hay servidor ni acceso a una base de datos. La interfaz puede ser sencilla: un formulario con nombre, código de pedido, botones de consulta y limpieza, y una zona de resultados.

JavaScript · Datos iniciales
const pedidos = [
  { codigo: "PED-1001", cliente: "Ana", total: 89.90, fecha: "2026-10-15", estado: "entregado" },
  { codigo: "PED-1002", cliente: "Luis", total: 145.50, fecha: "2026-10-28", estado: "pendiente" },
  { codigo: "PED-1003", cliente: "Marta", total: 29.99, fecha: "2026-11-02", estado: "preparación" }
];

Organiza el proyecto de la siguiente forma:

Estructura de archivos
panel-pedidos-bom/
├── index.html
├── css/
│   └── estilos.css
└── js/
    └── app.js

Tu misión

  1. Prepara la interfaz. Incluye campos para nombre y código de pedido, un botón de consulta, otro para borrar la última consulta y un área donde mostrar resultados sin recargar la página.
  2. Normaliza los datos. Utiliza String.trim() y toUpperCase() para tratar el código.
  3. Valida el código. Acepta únicamente el formato PED- seguido de cuatro cifras mediante una expresión regular.
  4. Localiza el pedido. Utiliza Array.find() y muestra un aviso claro si no existe.
  5. Formatea los datos. Muestra el importe con dos decimales y la fecha en formato español. Para interpretar las fechas almacenadas como AAAA-MM-DD, separa el año, el mes y el día y construye el objeto Date con sus componentes. Recuerda que los meses comienzan en cero. Evita interpretar fechas de forma ambigua.
  6. Recuerda el nombre. Guarda el nombre del usuario en localStorage y recupéralo al volver a la página.
  7. Recuerda la consulta de la pestaña. Guarda el último código consultado en sessionStorage y recupéralo al recargar.
  8. Lee parámetros de la URL. Si existe ?pedido=PED-1002, precarga ese código mediante URLSearchParams.
  9. Utiliza el BOM. Muestra el idioma de navigator.language y pide confirmación con window.confirm() antes de borrar la última consulta.
  10. Incorpora un temporizador. Simula un breve tiempo de espera con setTimeout() y evita consultas simultáneas mientras se procesa una.
  11. Gestiona errores. Controla entradas vacías, códigos mal formados, pedidos inexistentes y posibles fallos de almacenamiento.
  12. Comprueba el funcionamiento. Prueba una consulta válida, otra inexistente, un código incorrecto, la recarga, una nueva pestaña y la navegación con parámetros.
  13. Explica tu solución. Identifica qué objetos pertenecen a JavaScript y cuáles al entorno del navegador, y justifica la elección de localStorage y sessionStorage.
⚠️ Atención

En esta unidad el objetivo es trabajar los objetos predefinidos y el BOM. Puedes usar operaciones básicas del DOM como getElementById(), textContent y addEventListener() para construir la interfaz, pero su estudio detallado corresponde a la UT8. No utilices document.write() para mostrar resultados ni almacenes información sensible.

📦 Entrega del reto

Entrega la carpeta panel-pedidos-bom con todos los archivos y un documento breve que explique los objetos utilizados, las decisiones de almacenamiento y las pruebas realizadas.

El proyecto debe funcionar en el navegador mediante Live Server. Incluye capturas o una tabla de pruebas que evidencie los casos correctos y los errores controlados.
