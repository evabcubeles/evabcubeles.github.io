6.11 Organización de programas mediante objetos y clases

A lo largo de esta unidad hemos aprendido a crear objetos, definir sus propiedades y métodos, utilizar clases, construir instancias y aplicar principios de la Programación Orientada a Objetos (POO).

También hemos estudiado la encapsulación, la herencia y el polimorfismo. Sin embargo, conocer estos mecanismos no significa necesariamente saber organizar correctamente una aplicación.

Cuando un programa empieza a crecer, aparecen nuevas necesidades: gestionar varios tipos de objetos, relacionarlos, evitar la repetición de código y mantener separadas las distintas responsabilidades.

En este último apartado aprenderemos a organizar programas JavaScript mediante objetos y clases, aplicando de forma conjunta los conocimientos adquiridos durante la UT6.

📌 Importante

La finalidad de la POO no es crear muchas clases, sino organizar el código de manera comprensible, reutilizable y fácil de mantener.

Cada clase debe tener una responsabilidad clara y colaborar con otras clases cuando sea necesario.

Necesidad de organizar el código

Imaginemos que estamos desarrollando una aplicación web para gestionar los pedidos de una tienda online.

La aplicación debe permitir almacenar productos, registrar clientes, crear pedidos y calcular importes. Una primera solución podría utilizar variables y funciones independientes.

JavaScript — Código poco organizado 
let nombreProducto = "Teclado";
let precioProducto = 35;
let stockProducto = 10;

let nombreCliente = "Ana";
let correoCliente = "ana@ejemplo.com";

function calcularImporte(cantidad) {
  return precioProducto * cantidad;
}

function reducirStock(cantidad) {
  stockProducto -= cantidad;
}

console.log(calcularImporte(2)); // 70

Este ejemplo funciona para una situación muy sencilla, pero presenta varios inconvenientes:

  • Los datos de productos y clientes aparecen mezclados.
  • Las funciones dependen de variables externas.
  • Resulta difícil gestionar varios productos diferentes.
  • Una modificación puede afectar a partes del programa que no esperábamos.
  • El código se vuelve más difícil de ampliar y mantener.

Una alternativa consiste en agrupar los datos y las operaciones relacionadas dentro de clases.

JavaScript — Organización mediante clases 
class Producto {
  constructor(nombre, precio, stock) {
    this.nombre = nombre;
    this.precio = precio;
    this.stock = stock;
  }

  calcularImporte(cantidad) {
    return this.precio * cantidad;
  }

  reducirStock(cantidad) {
    if (cantidad > 0 && cantidad <= this.stock) {
      this.stock -= cantidad;
      return true;
    }

    return false;
  }
}

class Cliente {
  constructor(nombre, correo) {
    this.nombre = nombre;
    this.correo = correo;
  }
}

const producto = new Producto("Teclado", 35, 10);
const cliente = new Cliente("Ana", "ana@ejemplo.com");

console.log(producto.calcularImporte(2)); // 70
console.log(cliente.nombre);              // Ana

Ahora cada clase agrupa información y comportamiento relacionados. Podemos crear tantos productos o clientes como necesitemos sin duplicar toda su estructura.

💻 Ejemplo DAW

En una aplicación de comercio electrónico es habitual trabajar con entidades como Producto, Cliente, Pedido y Carrito.

Cada una representa un concepto diferente del problema que queremos resolver.

Responsabilidades de las clases

Uno de los aspectos más importantes al diseñar un programa orientado a objetos consiste en decidir qué debe hacer cada clase.

Una clase debería agrupar tareas relacionadas y evitar asumir responsabilidades que corresponden a otras partes de la aplicación.

Una clase, una responsabilidad principal

Por ejemplo, en una tienda online podemos distribuir las responsabilidades de la siguiente manera:

Clase Responsabilidad principal
Producto Representar un producto y gestionar sus datos.
Cliente Almacenar los datos de un cliente.
Pedido Gestionar los productos y cantidades de un pedido.
Tienda Coordinar el catálogo y las operaciones de la tienda.

Esta distribución permite modificar el comportamiento de una clase sin tener que reescribir toda la aplicación.

Ejemplo de una clase con demasiadas responsabilidades

JavaScript — Diseño poco recomendable 
class Producto {
  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio;
  }

  calcularPrecioConIVA() {
    return this.precio * 1.21;
  }

  enviarCorreoAlCliente() {
    console.log("Enviando correo...");
  }

  gestionarUsuarios() {
    console.log("Gestionando usuarios...");
  }
}

Los métodos relacionados con correos y usuarios no pertenecen a la responsabilidad principal de un producto.

Sería preferible trasladar esas operaciones a clases o servicios específicos.

⚠️ Atención

Organizar el código no significa crear una clase para cada operación. Una función independiente puede ser suficiente cuando no necesitamos representar un objeto con estado y comportamiento.

Debemos elegir la solución más sencilla que permita mantener el programa bien organizado.

Identificar objetos y clases en un problema

Antes de comenzar a programar, conviene analizar qué elementos intervienen en la aplicación y qué información necesitamos almacenar sobre ellos.

Supongamos que queremos desarrollar una aplicación para gestionar los préstamos de una biblioteca.

El sistema debe permitir registrar libros, identificar usuarios y controlar los préstamos.

Identificación de posibles clases

📚 Libro Título, autor, disponibilidad
👤 Usuario Nombre, identificador
📝 Préstamo Libro, usuario, fecha
↓
🏛️ Biblioteca Gestiona libros, usuarios y préstamos

Una vez identificadas las clases, podemos definir sus propiedades y métodos.

Clase Propiedades Métodos
Libro título, autor, disponible prestar(), devolver()
Usuario nombre, identificador mostrarDatos()

Para identificar las clases podemos preguntarnos: ¿qué elementos forman parte del problema?, ¿qué datos necesita cada elemento? y ¿qué operaciones debe realizar?

Relaciones entre objetos

En una aplicación real, los objetos normalmente no trabajan de manera aislada.

Un pedido puede estar asociado a un cliente, una matrícula a un alumno y un préstamo a un libro.

Podemos representar estas relaciones almacenando referencias a otros objetos dentro de las propiedades de una clase.

Ejemplo: un pedido asociado a un cliente

JavaScript — Relación entre objetos 
class Cliente {
  constructor(nombre, correo) {
    this.nombre = nombre;
    this.correo = correo;
  }
}

class Pedido {
  constructor(numero, cliente) {
    this.numero = numero;
    this.cliente = cliente;
  }

  mostrarInformacion() {
    return `Pedido ${this.numero} de ${this.cliente.nombre}`;
  }
}

const cliente1 = new Cliente(
  "Lucía",
  "lucia@ejemplo.com"
);

const pedido1 = new Pedido(101, cliente1);

console.log(pedido1.mostrarInformacion());
// Pedido 101 de Lucía

Observa que la propiedad cliente del objeto pedido1 no almacena únicamente un nombre, sino una referencia al objeto cliente1.

Por ello, podemos acceder a sus propiedades mediante this.cliente.nombre.

⚠️ Atención

Cuando dos objetos comparten una referencia al mismo objeto, los cambios realizados sobre ese objeto pueden observarse desde ambas referencias.

Esto es importante para comprender cómo se relacionan los datos dentro de una aplicación JavaScript.

Composición de objetos

La composición es una técnica de organización que permite construir objetos utilizando otros objetos.

Mientras que la herencia expresa una relación del tipo «es un tipo de», la composición suele representar relaciones como «tiene un» o «está formado por».

Ejemplo: un ordenador formado por componentes

JavaScript — Composición 
class Procesador {
  constructor(modelo, nucleos) {
    this.modelo = modelo;
    this.nucleos = nucleos;
  }
}

class Ordenador {
  constructor(marca, procesador) {
    this.marca = marca;
    this.procesador = procesador;
  }

  mostrarCaracteristicas() {
    return `${this.marca}: ${this.procesador.modelo}`;
  }
}

const cpu = new Procesador("Ryzen 7", 8);

const ordenador = new Ordenador("Lenovo", cpu);

console.log(ordenador.mostrarCaracteristicas());
// Lenovo: Ryzen 7

console.log(ordenador.procesador.nucleos);
// 8

En este caso, un ordenador tiene un procesador, pero no es un tipo de procesador.

Por tanto, la composición representa mejor esta relación que la herencia.

Herencia Composición
Relación «es un tipo de». Relación «tiene un» o «utiliza un».
Utiliza extends. Utiliza referencias a otros objetos.
Reutiliza características de una clase base. Combina objetos con responsabilidades diferentes.
Ejemplo: Profesor hereda de Usuario. Ejemplo: Pedido contiene productos.
📌 Importante

No debemos utilizar herencia simplemente porque dos clases estén relacionadas. Si un objeto contiene o utiliza otro objeto, normalmente será más adecuado estudiar una solución basada en composición.

Colecciones de objetos

Una aplicación suele necesitar trabajar con numerosos objetos del mismo tipo.

Por ejemplo, una tienda puede almacenar cientos de productos y una plataforma educativa puede gestionar muchos alumnos.

En JavaScript podemos utilizar arrays de objetos para organizar estas colecciones.

Ejemplo: catálogo de productos

JavaScript — Array de instancias 
class Producto {
  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio;
  }

  mostrarInformacion() {
    return `${this.nombre}: ${this.precio} €`;
  }
}

const productos = [
  new Producto("Ratón", 15),
  new Producto("Teclado", 35),
  new Producto("Monitor", 180)
];

productos.forEach(producto => {
  console.log(producto.mostrarInformacion());
});

Cada elemento del array es una instancia de la clase Producto.

Esto nos permite utilizar métodos de arrays, como forEach(), filter() o find(), junto con los métodos definidos en nuestras clases.

Filtrar objetos de una colección

JavaScript — Filtrado de productos 
const productosCaros = productos.filter(
  producto => producto.precio > 30
);

productosCaros.forEach(producto => {
  console.log(producto.nombre);
});

// Teclado
// Monitor

La combinación de clases y arrays resulta especialmente útil para gestionar listados de productos, usuarios, reservas, pedidos o calificaciones.

💻 Ejemplo DAW

En una aplicación de gestión académica podríamos almacenar un array de objetos Alumno y utilizar filter() para obtener los alumnos aprobados.

Cada alumno seguiría siendo responsable de calcular su propia nota media mediante un método de instancia.

Separación de responsabilidades

En una aplicación web conviene distinguir entre el código encargado de gestionar los datos y las reglas de negocio y el código encargado de mostrarlos al usuario.

Esta separación permite que las clases puedan utilizarse en diferentes contextos sin depender necesariamente de una página HTML.

Ejemplo: lógica de negocio independiente

JavaScript — Clase independiente de la interfaz 
class Cuenta {
  #saldo;

  constructor(titular, saldoInicial = 0) {
    this.titular = titular;
    this.#saldo = saldoInicial;
  }

  ingresar(cantidad) {
    if (cantidad <= 0) {
      return false;
    }

    this.#saldo += cantidad;
    return true;
  }

  consultarSaldo() {
    return this.#saldo;
  }
}

const cuenta = new Cuenta("María", 100);

cuenta.ingresar(50);

console.log(cuenta.consultarSaldo());
// 150

La clase Cuenta conoce las operaciones que puede realizar sobre su saldo, pero no necesita saber si los datos se mostrarán en una consola, en una página web o en otra interfaz.

Representar la información

En una aplicación web podríamos tener una función independiente que se encargase de mostrar el saldo en un elemento HTML.

JavaScript — Código de presentación 
function mostrarSaldo(cuenta) {
  const elemento = document.querySelector("#saldo");

  if (elemento) {
    elemento.textContent =
      `${cuenta.consultarSaldo()} €`;
  }
}

// En una página que contenga un elemento
// con id="saldo":
mostrarSaldo(cuenta);

De esta forma, si cambia la manera de presentar los datos, no será necesario modificar la lógica interna de la clase.

📌 Importante

Separar la lógica de negocio de la presentación facilita la reutilización del código, su mantenimiento y la realización de pruebas.

Organización del código en archivos

Cuando una aplicación crece, mantener todas las clases y funciones en un único archivo JavaScript puede dificultar su comprensión.

Una solución consiste en distribuir el código en varios archivos según sus responsabilidades.

Ejemplo de estructura de carpetas

Estructura de un proyecto 
tienda/
│
├── index.html
│
├── css/

En esta estructura, cada archivo contiene una parte concreta de la aplicación.

Exportar una clase

JavaScript permite organizar el código mediante módulos. Podemos exportar una clase desde un archivo e importarla desde otro.

JavaScript — js/modelos/Producto.js 
export class Producto {
  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio;
  }

  mostrarInformacion() {
    return `${this.nombre}: ${this.precio} €`;
  }
}

Importar una clase

JavaScript — js/app.js 
import { Producto } from "./modelos/Producto.js";

const producto = new Producto("Monitor", 180);

console.log(producto.mostrarInformacion());

Para cargar el archivo principal como módulo desde HTML, utilizamos el atributo type="module".

HTML — Cargar un módulo JavaScript 
<script type="module" src="./js/app.js"></script>
⚠️ Atención

Los módulos JavaScript deben cargarse de una manera compatible con las restricciones de seguridad del navegador.

Para probarlos, es recomendable utilizar un servidor local, por ejemplo, mediante una extensión de servidor en Visual Studio Code, en lugar de abrir directamente el archivo HTML con file://.

💻 Ejemplo DAW

En proyectos de desarrollo web es habitual separar los modelos de datos, las operaciones de negocio y los archivos responsables de la interacción con el usuario.

Esta organización resulta especialmente útil cuando varias personas trabajan sobre una misma aplicación.

Diseño progresivo de una aplicación

No es necesario diseñar todas las clases de una aplicación desde el principio con todos sus posibles métodos.

Una estrategia recomendable consiste en comenzar con una solución sencilla y ampliarla a medida que aparecen nuevas necesidades.

Pasos para organizar un programa

  1. Analizar el problema: identificar qué debe hacer la aplicación.
  2. Identificar las entidades: reconocer los posibles objetos y clases.
  3. Definir responsabilidades: decidir qué datos y operaciones corresponden a cada clase.
  4. Establecer relaciones: determinar qué objetos necesitan colaborar.
  5. Implementar las clases: programar constructores, propiedades y métodos.
  6. Crear y probar instancias: comprobar que cada objeto funciona correctamente.
  7. Integrar las clases: construir las operaciones generales de la aplicación.
  8. Revisar el diseño: simplificar, eliminar duplicaciones y mejorar la organización cuando sea necesario.

Este proceso no es estrictamente lineal: durante el desarrollo podemos descubrir que una clase necesita dividirse o que una responsabilidad debe trasladarse a otro objeto.

Errores habituales al organizar programas

1. Crear clases innecesarias

No todas las operaciones requieren una clase. Para una transformación sencilla, una función puede resultar más clara.

JavaScript — Función suficiente 
function calcularIVA(precio, porcentaje = 21) {
  return precio * porcentaje / 100;
}

console.log(calcularIVA(100)); // 21

2. Concentrar toda la lógica en una única clase

Una clase que gestiona productos, usuarios, pagos y notificaciones al mismo tiempo resulta difícil de mantener.

Conviene repartir las responsabilidades entre componentes con funciones claras.

3. Repetir código en distintas clases

Si varias clases contienen operaciones prácticamente idénticas, debemos estudiar si podemos extraer una función común, utilizar composición o aplicar herencia cuando exista una relación adecuada.

4. Utilizar herencia para cualquier relación

Un pedido no debería heredar de un producto simplemente porque necesita utilizar productos.

En ese caso, la composición es una opción más apropiada.

5. Permitir modificaciones sin validación

Cuando una propiedad representa información que debe cumplir determinadas reglas, es recomendable controlar sus cambios mediante métodos.

JavaScript — Encapsulación y validación 
class Producto {
  #stock;

  constructor(nombre, stock) {
    if (!Number.isInteger(stock) || stock < 0) {
      throw new Error("Stock inicial no válido");
    }

    this.nombre = nombre;
    this.#stock = stock;
  }

  vender(cantidad) {
    if (
      !Number.isInteger(cantidad) ||
      cantidad <= 0 ||
      cantidad > this.#stock
    ) {
      return false;
    }

    this.#stock -= cantidad;
    return true;
  }

  consultarStock() {
    return this.#stock;
  }
}

const producto = new Producto("Teclado", 10);

console.log(producto.vender(3));       // true
console.log(producto.consultarStock()); // 7

6. Mezclar la lógica de negocio con la interfaz

Si una clase depende directamente de elementos HTML para realizar sus operaciones principales, será más difícil reutilizarla en otros contextos.

⚠️ Atención

Un programa orientado a objetos no es automáticamente un programa bien diseñado.

La calidad del diseño depende de cómo distribuimos las responsabilidades, relacionamos los objetos y controlamos las modificaciones de sus datos.

Ejemplo práctico completo: gestión de pedidos

Vamos a desarrollar un pequeño sistema de pedidos que reúna los principales conceptos estudiados durante esta unidad.

La aplicación tendrá tres clases: Producto, Cliente y Pedido.

El objetivo será crear productos, registrar un cliente, añadir productos a un pedido y calcular su importe total.

Paso 1. Definir la clase Producto

JavaScript — Clase Producto 
class Producto {
  constructor(nombre, precio) {
    if (
      typeof precio !== "number" ||
      !Number.isFinite(precio) ||
      precio < 0
    ) {
      throw new Error("El precio no es válido");
    }

    this.nombre = nombre;
    this.precio = precio;
  }

  mostrarInformacion() {
    return `${this.nombre}: ${this.precio} €`;
  }
}

Esta clase representa cada producto y almacena su nombre y precio.

Paso 2. Definir la clase Cliente

JavaScript — Clase Cliente 
class Cliente {
  constructor(nombre, correo) {
    this.nombre = nombre;
    this.correo = correo;
  }

  mostrarDatos() {
    return `${this.nombre} (${this.correo})`;
  }
}

La clase Cliente almacena los datos de la persona que realiza el pedido.

Paso 3. Definir la clase Pedido

Un pedido tendrá un número identificador, un cliente y una colección de líneas de pedido.

Cada línea contendrá una referencia a un producto, la cantidad solicitada y el precio unitario aplicado al añadirlo al pedido.

JavaScript — Clase Pedido 
class Pedido {
  #lineas = [];

  constructor(numero, cliente) {
    this.numero = numero;
    this.cliente = cliente;
  }

  agregarProducto(producto, cantidad) {
    if (
      !(producto instanceof Producto) ||
      !Number.isInteger(cantidad) ||
      cantidad <= 0
    ) {
      return false;
    }

    this.#lineas.push({
      producto: producto,
      cantidad: cantidad,
      precioUnitario: producto.precio
    });

    return true;
  }

  calcularTotal() {
    return this.#lineas.reduce(
      (total, linea) => {
        return total +
          linea.precioUnitario * linea.cantidad;
      },
      0
    );
  }

  mostrarResumen() {
    console.log(`Pedido: ${this.numero}`);
    console.log(`Cliente: ${this.cliente.nombre}`);

    this.#lineas.forEach(linea => {
      console.log(
        `${linea.producto.nombre} x ${linea.cantidad}`
      );
    });

    console.log(`Total: ${this.calcularTotal()} €`);
  }
}

Observa cómo la clase Pedido se relaciona con otras clases sin necesidad de heredar de ellas.

También utiliza un campo privado #lineas para evitar que se modifique directamente la colección desde el exterior.

Paso 4. Crear las instancias

JavaScript — Creación de objetos 
const teclado = new Producto("Teclado", 35);
const raton = new Producto("Ratón", 15);

const cliente = new Cliente(
  "Ana",
  "ana@ejemplo.com"
);

const pedido = new Pedido(101, cliente);

pedido.agregarProducto(teclado, 2);
pedido.agregarProducto(raton, 1);

pedido.mostrarResumen();

Resumen del apartado

En este apartado hemos aprendido a organizar programas JavaScript mediante objetos y clases, aplicando los principales conceptos de la Programación Orientada a Objetos.

  • Las clases permiten agrupar datos y comportamientos relacionados.
  • Cada clase debería tener una responsabilidad principal clara.
  • Antes de programar conviene identificar las entidades del problema.
  • Los objetos pueden relacionarse mediante referencias a otros objetos.
  • La composición permite construir objetos utilizando otros objetos.
  • Los arrays de objetos permiten gestionar colecciones de instancias.
  • Separar la lógica de negocio de la presentación facilita el mantenimiento del programa.
  • Los módulos JavaScript permiten distribuir las clases entre diferentes archivos.
  • Un buen diseño debe evitar las responsabilidades mezcladas, la duplicación innecesaria y las modificaciones sin validación.
  • La organización del código debe evolucionar conforme crecen las necesidades de la aplicación.
📌 Importante

La Programación Orientada a Objetos es una forma de organizar y estructurar los programas.

Su utilidad aparece especialmente cuando necesitamos representar entidades relacionadas, reutilizar comportamientos y mantener aplicaciones que evolucionan con el tiempo.

💭 Piensa

Imagina que tienes que desarrollar una aplicación para gestionar las matrículas de un centro educativo.

La aplicación debe permitir registrar alumnos, gestionar módulos y almacenar las matrículas de cada alumno.

Reflexiona sobre las siguientes cuestiones:

  1. ¿Qué clases crearías para representar los elementos principales de la aplicación?
  2. ¿Qué propiedades y métodos tendría cada una?
  3. ¿Cómo relacionarías los alumnos con los módulos en los que están matriculados?
  4. ¿Utilizarías herencia o composición para relacionar un alumno con una matrícula? ¿Por qué?
  5. ¿Qué clase sería responsable de impedir que un alumno se matriculase dos veces en el mismo módulo?

Una posible organización sería utilizar las clases Alumno, Modulo, Matricula y GestorMatriculas.

  • Alumno: almacena identificador, nombre y datos del estudiante.
  • Modulo: almacena código, nombre y número de horas.
  • Matricula: relaciona un alumno con un módulo.
  • GestorMatriculas: administra las matrículas y comprueba las reglas de inscripción.

Para relacionar alumnos y módulos sería adecuada la composición o, más concretamente, una asociación mediante referencias.

Una matrícula no es un tipo de alumno, sino un registro que relaciona un alumno con un módulo.

El gestor de matrículas podría comprobar que no exista ya una inscripción con el mismo alumno y módulo.

JavaScript — Posible organización 
class Alumno {
  constructor(id, nombre) {
    this.id = id;
    this.nombre = nombre;
  }
}

class Modulo {
  constructor(codigo, nombre) {
    this.codigo = codigo;
    this.nombre = nombre;
  }
}

class Matricula {
  constructor(alumno, modulo) {
    this.alumno = alumno;
    this.modulo = modulo;
  }
}

class GestorMatriculas {
  #matriculas = [];

  matricular(alumno, modulo) {
    const existe = this.#matriculas.some(
      matricula =>
        matricula.alumno.id === alumno.id &&
        matricula.modulo.codigo === modulo.codigo
    );

    if (existe) {
      return false;
    }

    this.#matriculas.push(
      new Matricula(alumno, modulo)
    );

    return true;
  }

  consultarMatriculas() {
    return [...this.#matriculas];
  }
}

const alumno = new Alumno(1, "Lucía");
const modulo = new Modulo("DWEC", "Entorno cliente");

const gestor = new GestorMatriculas();

console.log(gestor.matricular(alumno, modulo));
// true

console.log(gestor.matricular(alumno, modulo));
// false

La primera matrícula se registra correctamente. El segundo intento devuelve false porque ya existe una matrícula con el mismo identificador de alumno y el mismo código de módulo.

Esta es una solución simplificada. En una aplicación real también tendríamos que validar los identificadores, gestionar los datos persistentes y controlar otras reglas académicas.
