6.9 Principios de la Programación Orientada a Objetos

En los apartados anteriores hemos aprendido a crear objetos, definir clases, utilizar constructores y trabajar con propiedades y métodos en JavaScript.

Sin embargo, la Programación Orientada a Objetos (POO) no consiste únicamente en escribir clases o crear instancias mediante new. También propone una forma de organizar los programas para que resulten más comprensibles, reutilizables y fáciles de mantener.

Para conseguirlo, se utilizan una serie de principios que ayudan a decidir qué información debe almacenar cada objeto, qué operaciones puede realizar y cómo debe relacionarse con otros objetos.

📌 Importante

Los cuatro principios fundamentales que vamos a estudiar son la abstracción, la encapsulación, la herencia y el polimorfismo.

Estos principios son ideas de diseño. Las clases y los objetos son herramientas que podemos utilizar para aplicarlos en JavaScript.

Qué son los principios de la POO

Cuando una aplicación crece, puede contener muchos objetos que representan usuarios, productos, pedidos, reservas o facturas.

Si todos los datos y operaciones se organizan sin ningún criterio, el código puede volverse difícil de entender y modificar.

Los principios de la POO proporcionan orientaciones para distribuir las responsabilidades entre los objetos.

Abstracción Representar únicamente la información y el comportamiento relevantes.
Encapsulación Organizar los datos y controlar cómo se utilizan o modifican.
Herencia Crear clases que aprovechan y amplían características de otras.
Polimorfismo Permitir que diferentes objetos respondan a una misma operación.

Vamos a estudiar cada principio por separado y después veremos cómo pueden combinarse en una aplicación web.

Abstracción

La abstracción consiste en identificar las características importantes de un elemento y representar únicamente aquellas que necesita nuestro programa.

Un objeto de la vida real puede tener muchas propiedades y comportamientos, pero una aplicación no necesita reproducirlos todos.

Ejemplo: un producto de una tienda online

Imagina que estamos desarrollando una tienda online. Para gestionar sus productos, puede resultar necesario almacenar el nombre, el precio y las unidades disponibles.

En cambio, otros datos, como la ubicación exacta del producto dentro del almacén, podrían no ser necesarios para la parte de la aplicación que estamos desarrollando.

JavaScript 
class Producto {
  constructor(nombre, precio, stock) {
    this.nombre = nombre;
    this.precio = precio;
    this.stock = stock;
  }

  estaDisponible() {
    return this.stock > 0;
  }

  calcularImporte(unidades) {
    return this.precio * unidades;
  }
}

const producto = new Producto("Teclado", 45, 10);

console.log(producto.nombre);
// Teclado

console.log(producto.estaDisponible());
// true

console.log(producto.calcularImporte(2));
// 90

Hemos creado una representación simplificada de un producto, centrada en la información que necesita nuestra aplicación.

La clase no intenta describir todos los aspectos posibles de un producto real. Selecciona aquellos que resultan útiles para resolver el problema.

💻 Ejemplo DAW

En una aplicación de reservas, una clase Habitacion podría almacenar su número, precio y disponibilidad.

No sería necesario representar todas las características físicas de la habitación si la aplicación únicamente debe gestionar las reservas.

Abstracción y diseño de clases

Antes de programar una clase, conviene plantearse tres preguntas:

  • ¿Qué elemento o concepto queremos representar?
  • ¿Qué datos necesita almacenar?
  • ¿Qué operaciones debe poder realizar?

Las respuestas ayudan a decidir qué propiedades y métodos incluiremos en la clase.

📌 Importante

La abstracción permite centrarnos en lo esencial y evitar detalles innecesarios.

Una buena abstracción depende de las necesidades concretas de la aplicación.

Encapsulación

La encapsulación consiste en organizar los datos de un objeto junto con las operaciones relacionadas con ellos y establecer cómo pueden utilizarse desde el exterior.

Este principio es especialmente útil cuando necesitamos impedir que determinadas propiedades reciban valores incorrectos.

El problema de modificar los datos directamente

Vamos a recuperar un ejemplo parecido al del apartado anterior: una cuenta bancaria que almacena su saldo.

JavaScript 
class CuentaBancaria {
  constructor(titular, saldo) {
    this.titular = titular;
    this.saldo = saldo;
  }
}

const cuenta = new CuentaBancaria("Ana", 100);

cuenta.saldo = -500;

console.log(cuenta.saldo);
// -500

En este ejemplo, la propiedad saldo es pública. Por tanto, cualquier parte del programa puede modificarla directamente.

Esto puede provocar que el objeto termine almacenando un estado que no cumple las reglas de nuestra aplicación.

Controlar las operaciones mediante métodos

Una primera mejora consiste en definir métodos que comprueben las condiciones necesarias antes de modificar los datos.

JavaScript 
class CuentaBancaria {
  constructor(titular, saldoInicial = 0) {
    this.titular = titular;
    this.saldo = saldoInicial;
  }

  ingresar(cantidad) {
    if (cantidad <= 0) {
      return false;
    }

    this.saldo += cantidad;
    return true;
  }

  retirar(cantidad) {
    if (cantidad <= 0 || cantidad > this.saldo) {
      return false;
    }

    this.saldo -= cantidad;
    return true;
  }

  consultarSaldo() {
    return this.saldo;
  }
}

const cuenta = new CuentaBancaria("Ana", 100);

console.log(cuenta.ingresar(50));
// true

console.log(cuenta.retirar(30));
// true

console.log(cuenta.consultarSaldo());
// 120

Ahora las operaciones de ingreso y retirada están organizadas dentro de la clase.

Además, los métodos pueden comprobar que las cantidades sean válidas antes de modificar el saldo.

⚠️ Atención

Aunque hayamos definido los métodos ingresar() y retirar(), la propiedad saldo sigue siendo pública.

Por tanto, todavía sería posible modificarla directamente mediante cuenta.saldo = -500.

Para impedir ese acceso directo, necesitamos utilizar un mecanismo de privacidad.

Propiedades privadas en JavaScript

JavaScript permite declarar campos privados dentro de las clases.

Para ello, escribimos el símbolo # delante del nombre del campo.

Los campos privados solo pueden utilizarse desde el interior de la clase que los declara.

Declaración de un campo privado

JavaScript 
class CuentaBancaria {
  #saldo;

  constructor(titular, saldoInicial = 0) {
    this.titular = titular;

    if (
      typeof saldoInicial !== "number" ||
      !Number.isFinite(saldoInicial) ||
      saldoInicial < 0
    ) {
      throw new Error("Saldo inicial no válido");
    }

    this.#saldo = saldoInicial;
  }

  ingresar(cantidad) {
    if (
      typeof cantidad !== "number" ||
      !Number.isFinite(cantidad) ||
      cantidad <= 0
    ) {
      return false;
    }

    this.#saldo += cantidad;
    return true;
  }

  retirar(cantidad) {
    if (
      typeof cantidad !== "number" ||
      !Number.isFinite(cantidad) ||
      cantidad <= 0 ||
      cantidad > this.#saldo
    ) {
      return false;
    }

    this.#saldo -= cantidad;
    return true;
  }

  consultarSaldo() {
    return this.#saldo;
  }
}

const cuenta = new CuentaBancaria("Ana", 100);

console.log(cuenta.ingresar(50));
// true

console.log(cuenta.retirar(30));
// true

console.log(cuenta.consultarSaldo());
// 120

En este ejemplo, #saldo es un campo privado.

Solo los métodos de la propia clase pueden consultarlo o modificarlo directamente.

Desde el exterior, el programa debe utilizar los métodos públicos que hemos definido.

Qué ocurre si intentamos acceder desde fuera

JavaScript 
// Acceso permitido:
console.log(cuenta.consultarSaldo());
// 120

// Acceso no permitido:
// console.log(cuenta.#saldo);

// La línea anterior produciría
// un error de sintaxis.

El acceso directo a #saldo desde fuera de la clase no está permitido. Si intentamos utilizarlo, JavaScript genera un error de sintaxis.

📌 Importante

La encapsulación no consiste simplemente en declarar propiedades privadas.

También implica definir una interfaz de operaciones adecuada para que otros objetos puedan utilizar la clase sin depender de sus detalles internos.

Métodos públicos y datos privados

Podemos distinguir dos partes en el diseño de una clase:

Parte pública Métodos que pueden utilizarse desde otros lugares del programa. Ejemplo: ingresar(), retirar() y consultarSaldo().
Parte privada Datos o métodos internos que no deben utilizarse directamente desde fuera. Ejemplo: #saldo.

Esta separación facilita que una clase controle su propio estado y reduce las dependencias entre diferentes partes del programa.

Herencia

La herencia permite crear una clase a partir de otra, aprovechando sus propiedades y métodos y añadiendo nuevas características.

Resulta útil cuando diferentes tipos de objetos comparten una estructura o un comportamiento común.

Ejemplo: usuarios de una aplicación

Imagina que una plataforma educativa permite trabajar con alumnos y profesores.

Ambos tipos de usuarios pueden tener un nombre y un correo electrónico, aunque cada uno realice operaciones diferentes.

Podemos definir una clase general Usuario y crear otras clases más específicas a partir de ella.

JavaScript 
class Usuario {
  constructor(nombre, email) {
    this.nombre = nombre;
    this.email = email;
  }

  mostrarDatos() {
    return `${this.nombre} - ${this.email}`;
  }
}

class Alumno extends Usuario {
  consultarCalificaciones() {
    return "Consultando calificaciones";
  }
}

const alumno = new Alumno(
  "Lucía",
  "lucia@ejemplo.com"
);

console.log(alumno.mostrarDatos());
// Lucía - lucia@ejemplo.com

console.log(alumno.consultarCalificaciones());
// Consultando calificaciones

La clase Alumno se ha definido utilizando extends Usuario.

Esto significa que Alumno hereda el comportamiento disponible en Usuario.

Por ello, una instancia de Alumno puede utilizar mostrarDatos(), aunque no hayamos definido ese método directamente en la clase Alumno.

Clase base y clase derivada

Concepto Significado Ejemplo
Clase base o padre Clase de la que se heredan características. Usuario
Clase derivada o hija Clase que hereda de otra. Alumno
extends Palabra reservada que establece la relación de herencia. class Alumno extends Usuario
⚠️ Atención

La herencia no significa que dos clases simplemente tengan propiedades parecidas.

Debe existir una relación conceptual adecuada entre ellas.

Por ejemplo, un alumno es un tipo de usuario, pero un pedido no es un tipo de producto.

Introducción a super()

Cuando una clase derivada define su propio constructor, puede utilizar super() para ejecutar el constructor de la clase base.

JavaScript 
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }
}

class Alumno extends Usuario {
  constructor(nombre, ciclo) {
    super(nombre);
    this.ciclo = ciclo;
  }
}

const alumno = new Alumno("Lucía", "DAW");

console.log(alumno.nombre);
// Lucía

console.log(alumno.ciclo);
// DAW

La instrucción super(nombre) ejecuta el constructor de Usuario, que inicializa la propiedad nombre.

Después, el constructor de Alumno inicializa la propiedad específica ciclo.

📌 Importante

En el siguiente apartado, 6.10 Herencia básica entre clases, estudiaremos con mayor profundidad el funcionamiento de extends, super() y la redefinición de métodos.

Por ahora, lo fundamental es comprender que la herencia permite reutilizar y ampliar el comportamiento de una clase.

Polimorfismo

El polimorfismo permite que diferentes objetos respondan a una misma operación, aunque cada uno la realice de una manera distinta.

El nombre procede de la idea de adoptar distintas formas.

En programación, esto significa que podemos utilizar una operación común sin tener que conocer todos los detalles internos de cada objeto.

Ejemplo: diferentes tipos de notificaciones

Supongamos que estamos desarrollando una aplicación web capaz de enviar notificaciones por distintos medios.

Todas las notificaciones pueden disponer de un método enviar(), pero cada tipo necesita ejecutarlo de una manera diferente.

JavaScript 
class NotificacionEmail {
  enviar(mensaje) {
    return `Email enviado: ${mensaje}`;
  }
}

class NotificacionSMS {
  enviar(mensaje) {
    return `SMS enviado: ${mensaje}`;
  }
}

const email = new NotificacionEmail();
const sms = new NotificacionSMS();

console.log(email.enviar("Pedido confirmado"));
// Email enviado: Pedido confirmado

console.log(sms.enviar("Pedido confirmado"));
// SMS enviado: Pedido confirmado

Los dos objetos tienen un método llamado enviar(), pero cada clase define un comportamiento diferente.

Esta es una forma sencilla de observar el polimorfismo en JavaScript.

Utilizar distintos objetos con la misma operación

La ventaja aparece cuando una función puede trabajar con diferentes objetos que ofrecen el mismo método.

JavaScript 
class NotificacionEmail {
  enviar(mensaje) {
    return `Email enviado: ${mensaje}`;
  }
}

class NotificacionSMS {
  enviar(mensaje) {
    return `SMS enviado: ${mensaje}`;
  }
}

function procesarNotificacion(notificacion, mensaje) {
  return notificacion.enviar(mensaje);
}

const email = new NotificacionEmail();
const sms = new NotificacionSMS();

console.log(
  procesarNotificacion(email, "Bienvenido")
);
// Email enviado: Bienvenido

console.log(
  procesarNotificacion(sms, "Bienvenido")
);
// SMS enviado: Bienvenido

La función procesarNotificacion() no necesita comprobar si recibe una notificación por correo o por SMS.

Simplemente utiliza el método enviar() del objeto recibido.

💻 Ejemplo DAW

En una aplicación web, podríamos disponer de distintos sistemas para enviar avisos: correo electrónico, SMS o notificaciones internas.

Si todos ofrecen un método enviar(), otras partes de la aplicación pueden trabajar con ellos mediante una operación común.

Polimorfismo y herencia

El polimorfismo también puede aparecer cuando una clase derivada redefine un método heredado.

JavaScript 
class Usuario {
  mostrarRol() {
    return "Usuario general";
  }
}

class Alumno extends Usuario {
  mostrarRol() {
    return "Alumno";
  }
}

class Profesor extends Usuario {
  mostrarRol() {
    return "Profesor";
  }
}

const usuarios = [
  new Usuario(),
  new Alumno(),
  new Profesor()
];

usuarios.forEach(usuario => {
  console.log(usuario.mostrarRol());
});

// Usuario general
// Alumno
// Profesor

Todos los objetos responden a la operación mostrarRol(), pero el resultado depende del tipo de objeto.

En este ejemplo, las clases Alumno y Profesor redefinen un método de la clase base.

⚠️ Atención

El polimorfismo no exige necesariamente utilizar herencia en JavaScript.

Diferentes objetos pueden ofrecer un mismo método y utilizarse de manera intercambiable en determinados contextos, aunque pertenezcan a clases independientes.

Relación entre los principios de la POO

Aunque hemos estudiado los cuatro principios por separado, en una aplicación pueden utilizarse de manera conjunta.

Vamos a comparar sus objetivos y las herramientas que podemos emplear para aplicarlos.

Principio Objetivo Ejemplo en JavaScript
Abstracción Representar los aspectos relevantes de un elemento. Una clase Producto con nombre, precio y stock.
Encapsulación Organizar y controlar el acceso a los datos. Un campo #saldo y métodos para modificarlo.
Herencia Reutilizar y ampliar características de otra clase. class Alumno extends Usuario
Polimorfismo Utilizar una operación común con comportamientos diferentes. Distintos objetos que implementan enviar().

Un mismo programa puede aplicar varios principios

Imagina una aplicación de gestión de usuarios con las clases Usuario, Alumno y Profesor.

  • Aplicamos abstracción al seleccionar las propiedades y métodos necesarios para representar usuarios.
  • Aplicamos encapsulación cuando protegemos determinados datos y controlamos cómo pueden modificarse.
  • Aplicamos herencia cuando Alumno y Profesor aprovechan características de Usuario.
  • Aplicamos polimorfismo cuando distintos tipos de usuarios responden de forma diferente a una misma operación.
📌 Importante

Los principios de la POO no son instrucciones que debamos utilizar obligatoriamente en todas las clases.

Son herramientas de diseño que debemos aplicar cuando ayudan a resolver un problema de manera más clara y mantenible.

Ventajas de aplicar los principios de la POO

Una organización adecuada mediante objetos y clases puede aportar diferentes ventajas al desarrollo de aplicaciones web.

Organización del código

Cada clase puede encargarse de una responsabilidad concreta. Esto facilita localizar las operaciones relacionadas con una determinada entidad.

Reutilización

Podemos aprovechar clases y métodos existentes en diferentes partes de una aplicación.

La herencia es uno de los mecanismos que permiten reutilizar comportamiento, aunque no es el único.

Mantenimiento

Cuando los datos y operaciones están bien organizados, resulta más sencillo modificar una parte del programa sin afectar innecesariamente a otras.

Control de los datos

La encapsulación permite establecer operaciones que comprueben las condiciones necesarias antes de modificar el estado de los objetos.

Ampliación de funcionalidades

Podemos incorporar nuevas clases o comportamientos sin tener que reescribir necesariamente todo el código existente.

💻 Ejemplo DAW

Una tienda online puede comenzar gestionando productos y pedidos. Más adelante, podría incorporar diferentes métodos de pago o sistemas de notificación.

Si la aplicación está bien diseñada, estas nuevas funcionalidades pueden integrarse manteniendo una estructura comprensible.

Errores habituales al aplicar los principios de la POO

1. Pensar que utilizar class significa aplicar correctamente la POO

Podemos escribir muchas clases y, aun así, organizar mal las responsabilidades de nuestro programa.

Lo importante no es la cantidad de clases, sino que cada una represente adecuadamente un concepto o responsabilidad.

2. Confundir abstracción con ocultar propiedades

La abstracción consiste en seleccionar y representar los aspectos relevantes de un problema.

Ocultar el acceso directo a determinados datos está relacionado con la encapsulación.

3. Pensar que un método de validación hace privada una propiedad

Definir un método cambiarPrecio() no impide modificar directamente producto.precio si esa propiedad es pública.

Para establecer privacidad real podemos utilizar campos privados mediante #.

4. Utilizar herencia cuando no existe una relación adecuada

No todas las clases relacionadas deben utilizar herencia.

Por ejemplo, una clase Pedido puede contener varios productos, pero eso no significa que deba heredar de Producto.

⚠️ Atención

Que un objeto contenga o utilice otro objeto no significa que deba heredar de él.

La herencia suele representar una relación del tipo «es un tipo de».

5. Pensar que polimorfismo significa utilizar métodos con nombres distintos

La idea fundamental del polimorfismo es que diferentes objetos puedan responder a una operación común.

No se trata simplemente de que cada clase tenga métodos diferentes.

Ejemplos prácticos en aplicaciones web

Ejemplo 1. Gestión de productos con encapsulación

Vamos a diseñar una clase Producto que controle el precio y las unidades disponibles.

Utilizaremos campos privados para evitar modificaciones directas desde fuera de la clase.

JavaScript 
class Producto {
  #precio;
  #stock;

  constructor(nombre, precio, stock) {
    if (
      typeof precio !== "number" ||
      !Number.isFinite(precio) ||
      precio < 0 ||
      !Number.isInteger(stock) ||
      stock < 0
    ) {
      throw new Error("Datos del producto no válidos");
    }

    this.nombre = nombre;
    this.#precio = precio;
    this.#stock = stock;
  }

  consultarPrecio() {
    return this.#precio;
  }

  consultarStock() {
    return this.#stock;
  }

  vender(unidades) {
    if (
      !Number.isInteger(unidades) ||
      unidades <= 0 ||
      unidades > this.#stock
    ) {
      return false;
    }

    this.#stock -= unidades;
    return true;
  }

  cambiarPrecio(nuevoPrecio) {
    if (
      typeof nuevoPrecio !== "number" ||
      !Number.isFinite(nuevoPrecio) ||
      nuevoPrecio < 0
    ) {
      return false;
    }

    this.#precio = nuevoPrecio;
    return true;
  }
}

const producto = new Producto("Teclado", 45, 10);

console.log(producto.vender(3));
// true

console.log(producto.consultarStock());
// 7

console.log(producto.cambiarPrecio(-20));
// false

console.log(producto.consultarPrecio());
// 45

En este ejemplo aplicamos la abstracción al representar únicamente los datos necesarios para gestionar el producto.

También aplicamos encapsulación: los campos #precio y #stock son privados y sus modificaciones se realizan mediante métodos que comprueban los valores.

Ejemplo 2. Diferentes métodos de pago

Supongamos que nuestra tienda permite pagar mediante tarjeta o transferencia bancaria.

Podemos crear diferentes clases que ofrezcan una misma operación: procesarPago().

JavaScript 
class PagoTarjeta {
  procesarPago(importe) {
    return `Pago con tarjeta: ${importe} €`;
  }
}

class PagoTransferencia {
  procesarPago(importe) {
    return `Transferencia por ${importe} €`;
  }
}

function realizarPago(metodoPago, importe) {
  if (
    typeof importe !== "number" ||
    !Number.isFinite(importe) ||
    importe <= 0
  ) {
    return "Importe no válido";
  }

  return metodoPago.procesarPago(importe);
}

const tarjeta = new PagoTarjeta();
const transferencia = new PagoTransferencia();

console.log(realizarPago(tarjeta, 75));
// Pago con tarjeta: 75 €

console.log(realizarPago(transferencia, 120));
// Transferencia por 120 €

La función realizarPago() trabaja con ambos objetos mediante el método común procesarPago().

Este ejemplo muestra cómo el polimorfismo puede facilitar la ampliación de una aplicación.

⚠️ Atención

Este ejemplo simula el procesamiento de pagos mediante cadenas de texto.

No realiza transacciones reales ni se conecta a ninguna pasarela de pago.

Ejemplo 3. Usuarios con diferentes roles

Vamos a combinar herencia y polimorfismo en una aplicación educativa.

JavaScript 
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }

  mostrarPanel() {
    return `Panel general de ${this.nombre}`;
  }
}

class Alumno extends Usuario {
  mostrarPanel() {
    return `Panel de calificaciones: ${this.nombre}`;
  }
}

class Profesor extends Usuario {
  mostrarPanel() {
    return `Panel de gestión docente: ${this.nombre}`;
  }
}

const usuarios = [
  new Alumno("Lucía"),
  new Profesor("Carlos"),
  new Alumno("Pablo")
];

usuarios.forEach(usuario => {
  console.log(usuario.mostrarPanel());
});

// Panel de calificaciones: Lucía
// Panel de gestión docente: Carlos
// Panel de calificaciones: Pablo

Las clases Alumno y Profesor heredan de Usuario.

Además, cada una redefine mostrarPanel() para ofrecer un resultado adecuado a su función.

El bucle puede recorrer todos los objetos y utilizar el mismo método, sin necesidad de comprobar manualmente el tipo de usuario.

💻 Ejemplo DAW

Este diseño podría utilizarse como punto de partida para una aplicación educativa con diferentes paneles según el tipo de usuario.

En una aplicación real, también sería necesario gestionar la autenticación, los permisos y la seguridad de las operaciones.

Resumen del apartado

En este apartado hemos estudiado los principales fundamentos de la Programación Orientada a Objetos y su aplicación en JavaScript.

  • La abstracción permite representar los aspectos relevantes de un elemento y omitir detalles innecesarios.
  • La encapsulación organiza los datos y métodos de los objetos y permite controlar su utilización.
  • JavaScript permite declarar campos privados mediante el símbolo #.
  • Los métodos públicos pueden proporcionar operaciones controladas para consultar o modificar datos privados.
  • La herencia permite crear clases derivadas que aprovechan características de una clase base.
  • En JavaScript, la palabra extends permite establecer relaciones de herencia entre clases.
  • El polimorfismo permite utilizar una operación común con objetos que ofrecen comportamientos diferentes.
  • Los principios de la POO ayudan a diseñar programas más organizados, reutilizables y fáciles de mantener.
📌 Importante

Recuerda la diferencia fundamental entre los cuatro principios:

Abstracción: seleccionar lo esencial.

Encapsulación: organizar y controlar el acceso a los datos.

Herencia: reutilizar y ampliar características de otras clases.

Polimorfismo: utilizar una misma operación con diferentes comportamientos.

💭 Piensa

Queremos desarrollar una aplicación web para gestionar diferentes tipos de usuarios de una biblioteca.

Todos los usuarios tienen un nombre y pueden consultar información de su cuenta.

Sin embargo, existen dos tipos de usuarios: lectores y bibliotecarios.

Los lectores pueden consultar sus préstamos, mientras que los bibliotecarios pueden gestionar el catálogo.

Además, queremos evitar que el número de préstamos de un lector se modifique directamente desde fuera de su clase.

Reflexiona sobre estas cuestiones:

  1. ¿Qué clase general podríamos definir para representar a todos los usuarios?
  2. ¿Cómo aplicaríamos la abstracción al decidir sus propiedades y métodos?
  3. ¿Qué relación de herencia podríamos establecer?
  4. ¿Cómo utilizaríamos la encapsulación para proteger el número de préstamos?
  5. ¿Cómo podríamos aplicar el polimorfismo al mostrar las opciones disponibles para cada usuario?
Ver una posible solución

Podemos definir una clase general Usuario y crear las clases Lector y Bibliotecario a partir de ella.

JavaScript 
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }

  mostrarOpciones() {
    return "Opciones generales";
  }
}

class Lector extends Usuario {
  #prestamos;

  constructor(nombre) {
    super(nombre);
    this.#prestamos = 0;
  }

  registrarPrestamo() {
    this.#prestamos++;
  }

  consultarPrestamos() {
    return this.#prestamos;
  }

  mostrarOpciones() {
    return "Consultar libros y préstamos";
  }
}

class Bibliotecario extends Usuario {
  mostrarOpciones() {
    return "Gestionar el catálogo";
  }
}

const lector = new Lector("Lucía");
const bibliotecario = new Bibliotecario("Carlos");

lector.registrarPrestamo();
lector.registrarPrestamo();

console.log(lector.consultarPrestamos());
// 2

console.log(lector.mostrarOpciones());
// Consultar libros y préstamos

console.log(bibliotecario.mostrarOpciones());
// Gestionar el catálogo

const usuarios = [lector, bibliotecario];

usuarios.forEach(usuario => {
  console.log(
    `${usuario.nombre}: ${usuario.mostrarOpciones()}`
  );
});

// Lucía: Consultar libros y préstamos
// Carlos: Gestionar el catálogo

Abstracción: representamos únicamente los datos y operaciones que necesita la aplicación para gestionar sus usuarios.

Encapsulación: el campo #prestamos es privado y se gestiona mediante métodos de la clase Lector.

Herencia: Lector y Bibliotecario heredan de Usuario.

Polimorfismo: ambos tipos de usuario responden al método mostrarOpciones(), pero ofrecen resultados diferentes.

Esta solución es una versión simplificada. En una aplicación real necesitaríamos añadir más comprobaciones y reglas de funcionamiento.
