6.10 Herencia básica entre clases

En el apartado anterior hemos estudiado los principales principios de la Programación Orientada a Objetos: abstracción, encapsulación, herencia y polimorfismo.

También hemos visto que la herencia permite crear nuevas clases aprovechando características de otras ya existentes.

Ahora vamos a profundizar en este mecanismo y aprender a utilizarlo en JavaScript mediante las palabras clave extends y super.

Además, estudiaremos cómo funcionan los métodos heredados, cómo podemos redefinirlos y qué errores debemos evitar al trabajar con clases relacionadas.

📌 Importante

La herencia permite crear una clase más específica a partir de otra más general, reutilizando su comportamiento y añadiendo nuevas propiedades o métodos cuando sea necesario.

En JavaScript, utilizamos extends para establecer la relación de herencia y super para acceder a determinados comportamientos de la clase base.

Qué es la herencia entre clases

Cuando desarrollamos una aplicación, es habitual encontrar objetos que comparten determinadas propiedades y métodos.

Por ejemplo, en una plataforma educativa podemos tener usuarios de diferentes tipos: alumnos, profesores y administradores.

Todos ellos pueden compartir información como el nombre y el correo electrónico, pero cada tipo de usuario necesita realizar operaciones específicas.

Una posibilidad sería crear clases independientes y repetir en todas ellas las mismas propiedades y métodos.

Sin embargo, esta solución puede provocar duplicación de código y dificultar el mantenimiento de la aplicación.

El problema de repetir código

JavaScript 
class Alumno {
  constructor(nombre, email, ciclo) {
    this.nombre = nombre;
    this.email = email;
    this.ciclo = ciclo;
  }

  mostrarDatos() {
    return `${this.nombre} - ${this.email}`;
  }
}

class Profesor {
  constructor(nombre, email, departamento) {
    this.nombre = nombre;
    this.email = email;
    this.departamento = departamento;
  }

  mostrarDatos() {
    return `${this.nombre} - ${this.email}`;
  }
}

Observa que las dos clases repiten las propiedades nombre y email, además del método mostrarDatos().

Si más adelante queremos modificar la forma de mostrar la información de los usuarios, tendríamos que realizar cambios en las dos clases.

La solución mediante herencia

Podemos crear una clase general Usuario que contenga las características compartidas.

Después, las clases Alumno y Profesor pueden heredar de ella y añadir sus características particulares.

Usuario Clase general nombre · email · mostrarDatos()
Alumno Hereda de Usuario Añade ciclo y operaciones propias
Profesor Hereda de Usuario Añade departamento y operaciones propias
💻 Ejemplo DAW

En una aplicación educativa, podemos utilizar una clase general para representar los datos comunes de los usuarios y clases derivadas para sus diferentes funciones.

Esto permite mantener el comportamiento compartido en un único lugar.

Clase base y clase derivada

Para comprender la herencia, debemos distinguir dos conceptos: la clase base y la clase derivada.

Concepto Significado Ejemplo
Clase base Clase que proporciona características a otra. Usuario
Clase derivada Clase que hereda de otra y puede ampliarla. Alumno
Herencia Relación que permite aprovechar el comportamiento de una clase base. Alumno extends Usuario

También podemos encontrar otros nombres para estos conceptos.

  • La clase base también se denomina clase padre o superclase.
  • La clase derivada también se denomina clase hija o subclase.

Todos estos términos se utilizan para describir la misma relación.

📌 Importante

Una clase derivada no sustituye a la clase base.

La amplía o especializa. Por ejemplo, un Alumno es un tipo de Usuario, pero no todos los usuarios tienen que ser alumnos.

La palabra clave extends

En JavaScript utilizamos la palabra reservada extends para indicar que una clase hereda de otra.

Su sintaxis básica es la siguiente:

JavaScript 
class ClaseBase {
  // Propiedades y métodos comunes
}

class ClaseDerivada extends ClaseBase {
  // Características específicas
}

Vamos a utilizar esta estructura con un ejemplo sencillo.

Primer ejemplo de herencia

JavaScript 
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }

  saludar() {
    return `Hola, soy ${this.nombre}`;
  }
}

class Alumno extends Usuario {
  estudiar() {
    return `${this.nombre} está estudiando`;
  }
}

const alumno = new Alumno("Lucía");

console.log(alumno.saludar());
// Hola, soy Lucía

console.log(alumno.estudiar());
// Lucía está estudiando

Vamos a analizar lo que ocurre:

  1. Definimos la clase Usuario con una propiedad nombre y un método saludar().
  2. Creamos la clase Alumno utilizando extends Usuario.
  3. Añadimos el método específico estudiar().
  4. Creamos una instancia de Alumno.
  5. La instancia puede utilizar tanto saludar() como estudiar().

Aunque no hemos escrito saludar() dentro de Alumno, el método está disponible gracias a la herencia.

⚠️ Atención

En este primer ejemplo, Alumno no define su propio constructor.

Por eso puede utilizar el constructor heredado de Usuario.

Más adelante veremos qué ocurre cuando la clase derivada necesita definir su propio constructor.

Propiedades y métodos heredados

Una instancia de una clase derivada puede utilizar las propiedades inicializadas por la clase base y los métodos que recibe mediante herencia.

Además, la clase derivada puede definir sus propias propiedades y métodos.

Combinar características comunes y específicas

JavaScript 
class Vehiculo {
  constructor(marca) {
    this.marca = marca;
  }

  mostrarMarca() {
    return `Marca: ${this.marca}`;
  }
}

class Coche extends Vehiculo {
  tocarClaxon() {
    return "¡Pip, pip!";
  }
}

const coche = new Coche("Toyota");

console.log(coche.marca);
// Toyota

console.log(coche.mostrarMarca());
// Marca: Toyota

console.log(coche.tocarClaxon());
// ¡Pip, pip!

En este ejemplo, el objeto coche dispone de diferentes características.

Elemento Procedencia
marca Inicializada por el constructor de Vehiculo.
mostrarMarca() Método heredado de Vehiculo.
tocarClaxon() Método definido en Coche.

Cómo funciona la búsqueda de métodos

JavaScript utiliza una cadena de prototipos para resolver el acceso a las propiedades y métodos de los objetos.

Cuando escribimos coche.mostrarMarca(), JavaScript busca ese método en el objeto y, si no lo encuentra, continúa buscando en su cadena de prototipos.

En este caso, encuentra mostrarMarca() en el prototipo asociado a la clase Vehiculo.

Objeto coche Contiene la propiedad marca
Coche.prototype Contiene tocarClaxon()
Vehiculo.prototype Contiene mostrarMarca()
📌 Importante

Los métodos heredados no se copian individualmente dentro de cada objeto.

JavaScript los encuentra mediante la cadena de prototipos. La sintaxis class facilita trabajar con este mecanismo sin tener que manipular directamente los prototipos.

Constructores y super()

Hasta ahora hemos utilizado clases derivadas sin declarar un constructor propio.

Sin embargo, en muchas aplicaciones necesitamos que una clase derivada almacene información adicional.

Por ejemplo, todos los usuarios pueden tener un nombre, pero los alumnos también pueden tener un ciclo formativo.

Definir un constructor en la clase derivada

Cuando una clase derivada define su propio constructor, utilizamos super() para llamar al constructor de la clase base.

JavaScript 
class Usuario {
  constructor(nombre, email) {
    this.nombre = nombre;
    this.email = email;
  }
}

class Alumno extends Usuario {
  constructor(nombre, email, ciclo) {
    super(nombre, email);

    this.ciclo = ciclo;
  }
}

const alumno = new Alumno(
  "Lucía",
  "lucia@ejemplo.com",
  "DAW"
);

console.log(alumno.nombre);
// Lucía

console.log(alumno.email);
// lucia@ejemplo.com

console.log(alumno.ciclo);
// DAW

Observa que el constructor de Alumno recibe tres parámetros.

Los dos primeros se envían al constructor de Usuario mediante:

JavaScript 
super(nombre, email);

Después, el constructor de Alumno inicializa su propiedad específica:

JavaScript 
this.ciclo = ciclo;

Orden de ejecución de los constructores

Vamos a observar el orden en el que se ejecutan los constructores.

JavaScript 
class Usuario {
  constructor(nombre) {
    console.log("Constructor de Usuario");

    this.nombre = nombre;
  }
}

class Alumno extends Usuario {
  constructor(nombre, ciclo) {
    console.log("Inicio del constructor de Alumno");

    super(nombre);

    console.log("Después de super()");

    this.ciclo = ciclo;
  }
}

const alumno = new Alumno("Lucía", "DAW");

// Inicio del constructor de Alumno
// Constructor de Usuario
// Después de super()

El constructor de Alumno comienza a ejecutarse, llama al constructor de Usuario y después continúa con las instrucciones restantes.

⚠️ Atención

Cuando una clase derivada define un constructor, debe llamar a super() antes de utilizar this.

Si intentamos acceder a this antes de esa llamada, JavaScript produce un error.

Ejemplo incorrecto

JavaScript 
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }
}

class Alumno extends Usuario {
  constructor(nombre, ciclo) {
    // INCORRECTO:
    // this.ciclo = ciclo;

    super(nombre);

    // CORRECTO:
    this.ciclo = ciclo;
  }
}

En este código hemos dejado comentada la instrucción incorrecta para que el ejemplo pueda ejecutarse.

Si eliminamos el comentario de la primera asignación, se producirá un error al utilizar this antes de super().

📌 Importante

Recuerda esta secuencia:

1. Declaramos el constructor de la clase derivada.

2. Llamamos a super() para inicializar la parte correspondiente a la clase base.

3. Utilizamos this para inicializar las propiedades específicas.

Redefinición de métodos heredados

La herencia permite utilizar métodos definidos en una clase base.

Pero también puede ocurrir que una clase derivada necesite realizar una operación de forma diferente.

En ese caso, podemos redefinir el método heredado.

Para hacerlo, declaramos en la clase derivada un método con el mismo nombre.

Ejemplo: diferentes formas de presentarse

JavaScript 
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }

  presentarse() {
    return `Soy ${this.nombre}`;
  }
}

class Alumno extends Usuario {
  presentarse() {
    return `Soy ${this.nombre} y soy alumno`;
  }
}

class Profesor extends Usuario {
  presentarse() {
    return `Soy ${this.nombre} y soy profesor`;
  }
}

const usuario = new Usuario("Ana");
const alumno = new Alumno("Lucía");
const profesor = new Profesor("Carlos");

console.log(usuario.presentarse());
// Soy Ana

console.log(alumno.presentarse());
// Soy Lucía y soy alumno

console.log(profesor.presentarse());
// Soy Carlos y soy profesor

Las tres clases disponen de un método llamado presentarse().

Sin embargo, cada tipo de objeto puede ofrecer un resultado diferente.

Cuando llamamos a alumno.presentarse(), JavaScript utiliza el método definido en Alumno, en lugar del heredado de Usuario.

Objeto Método utilizado
usuario El método de Usuario.
alumno La redefinición de Alumno.
profesor La redefinición de Profesor.

Relación con el polimorfismo

La redefinición de métodos está relacionada con el principio de polimorfismo que estudiamos en el apartado 6.9.

Podemos recorrer un conjunto de objetos diferentes y llamar al mismo método sin comprobar manualmente de qué clase es cada uno.

JavaScript 
class Usuario {
  presentarse() {
    return "Soy un usuario";
  }
}

class Alumno extends Usuario {
  presentarse() {
    return "Soy un alumno";
  }
}

class Profesor extends Usuario {
  presentarse() {
    return "Soy un profesor";
  }
}

const usuarios = [
  new Usuario(),
  new Alumno(),
  new Profesor()
];

usuarios.forEach(usuario => {
  console.log(usuario.presentarse());
});

// Soy un usuario
// Soy un alumno
// Soy un profesor
💻 Ejemplo DAW

Una aplicación educativa podría mostrar diferentes paneles según el tipo de usuario.

Si cada clase dispone de un método mostrarPanel(), la aplicación puede llamar a ese método sin repetir estructuras condicionales para cada tipo de usuario.

Llamadas a métodos heredados con super

Hasta ahora hemos utilizado super() para llamar al constructor de la clase base.

Pero super también permite acceder a métodos definidos en la clase base.

Esto resulta útil cuando queremos ampliar el comportamiento de un método heredado sin sustituirlo completamente.

Ampliar un método existente

JavaScript 
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }

  mostrarDatos() {
    return `Nombre: ${this.nombre}`;
  }
}

class Alumno extends Usuario {
  constructor(nombre, ciclo) {
    super(nombre);
    this.ciclo = ciclo;
  }

  mostrarDatos() {
    return `${super.mostrarDatos()} - Ciclo: ${this.ciclo}`;
  }
}

const alumno = new Alumno("Lucía", "DAW");

console.log(alumno.mostrarDatos());
// Nombre: Lucía - Ciclo: DAW

Observa esta instrucción:

JavaScript 
super.mostrarDatos()

Mediante ella, el método mostrarDatos() de Alumno ejecuta el método correspondiente de la clase base.

Después, añade la información específica del ciclo formativo.

Diferencia entre super() y super.metodo()

Expresión Utilidad
super(...) Llama al constructor de la clase base desde el constructor derivado.
super.metodo() Permite llamar a un método de la clase base.
⚠️ Atención

No debemos confundir super() con super.metodo().

La primera forma se utiliza para llamar al constructor de la clase base.

La segunda permite acceder a un método heredado dentro de los métodos de la clase derivada.

Herencia y operador instanceof

En el apartado 6.6 estudiamos el operador instanceof.

Este operador permite comprobar si un objeto está relacionado con el prototipo de una clase a través de su cadena de prototipos.

Cuando utilizamos herencia, una instancia de una clase derivada puede cumplir la comprobación tanto con su clase como con la clase base.

JavaScript 
class Usuario {}

class Alumno extends Usuario {}

class Profesor extends Usuario {}

const alumno = new Alumno();

console.log(alumno instanceof Alumno);
// true

console.log(alumno instanceof Usuario);
// true

console.log(alumno instanceof Profesor);
// false

El objeto alumno es una instancia de Alumno.

Como Alumno hereda de Usuario, también se cumple alumno instanceof Usuario.

En cambio, Alumno no hereda de Profesor, por lo que esa comprobación devuelve false.

📌 Importante

instanceof no comprueba simplemente si un objeto tiene determinadas propiedades.

Comprueba una relación basada en la cadena de prototipos del objeto.

Cuándo utilizar herencia

La herencia puede ayudarnos a reutilizar código, pero no todas las relaciones entre objetos deben representarse mediante clases derivadas.

Antes de utilizar extends, conviene comprobar si existe una relación conceptual adecuada entre las clases.

Relación «es un tipo de»

La herencia suele resultar adecuada cuando podemos afirmar que una clase representa un tipo más específico de otra clase.

Relación ¿Tiene sentido la herencia? Explicación
Alumno - Usuario Sí Un alumno es un tipo de usuario.
Coche - Vehículo Sí Un coche es un tipo de vehículo.
Producto digital - Producto Puede ser adecuada Un producto digital es un tipo específico de producto.
Pedido - Producto No Un pedido puede contener productos, pero no es un producto.
Biblioteca - Libro No Una biblioteca contiene libros, pero no es un libro.

Herencia frente a composición

Cuando un objeto contiene o utiliza otros objetos, suele ser más adecuado utilizar composición.

Por ejemplo, un pedido puede almacenar un array de productos.

JavaScript 
class Producto {
  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio;
  }
}

class Pedido {
  constructor() {
    this.productos = [];
  }

  agregarProducto(producto) {
    this.productos.push(producto);
  }

  calcularTotal() {
    return this.productos.reduce(
      (total, producto) => total + producto.precio,
      0
    );
  }
}

const pedido = new Pedido();

pedido.agregarProducto(
  new Producto("Teclado", 45)
);

pedido.agregarProducto(
  new Producto("Ratón", 20)
);

console.log(pedido.calcularTotal());
// 65

En este ejemplo, Pedido no hereda de Producto.

En su lugar, contiene objetos Producto dentro de un array.

Esta relación es más adecuada porque un pedido contiene productos, pero no es un tipo de producto.

⚠️ Atención

No debemos utilizar herencia únicamente para evitar repetir unas pocas líneas de código.

La relación entre las clases debe tener sentido dentro del modelo de nuestra aplicación.

Errores habituales al utilizar herencia

1. Olvidar la palabra clave extends

Si definimos dos clases independientes, no existe una relación de herencia entre ellas, aunque tengan métodos con el mismo nombre.

JavaScript 
class Usuario {
  saludar() {
    return "Hola";
  }
}

// No hereda de Usuario:
class Alumno {}

const alumno = new Alumno();

console.log(typeof alumno.saludar);
// undefined

Para establecer la herencia debemos utilizar extends Usuario.

2. Utilizar this antes de super()

En un constructor derivado, no podemos acceder a this antes de llamar a super().

JavaScript 
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }
}

class Alumno extends Usuario {
  constructor(nombre, ciclo) {
    // Incorrecto si se ejecuta aquí:
    // this.ciclo = ciclo;

    super(nombre);

    // Correcto:
    this.ciclo = ciclo;
  }
}

3. No enviar los parámetros necesarios a super()

Si el constructor de la clase base necesita determinados datos, debemos proporcionarlos correctamente.

JavaScript 
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }
}

class Alumno extends Usuario {
  constructor(nombre, ciclo) {
    // Incorrecto para este caso:
    // super();

    // Correcto:
    super(nombre);

    this.ciclo = ciclo;
  }
}

Si utilizáramos super() sin enviar el nombre, la propiedad nombre quedaría con el valor undefined.

4. Confundir redefinir un método con crear otro diferente

Para redefinir un método, debemos utilizar el mismo nombre que tiene en la clase base.

JavaScript 
class Usuario {
  mostrarDatos() {
    return "Datos generales";
  }
}

class Alumno extends Usuario {
  mostrarDatosAlumno() {
    return "Datos del alumno";
  }
}

const alumno = new Alumno();

console.log(alumno.mostrarDatos());
// Datos generales

console.log(alumno.mostrarDatosAlumno());
// Datos del alumno

En este caso no hemos redefinido mostrarDatos().

Hemos creado un método nuevo llamado mostrarDatosAlumno().

5. Intentar acceder directamente a campos privados de la clase base

En el apartado 6.9 aprendimos que los campos declarados con # son privados.

Una clase derivada no puede acceder directamente a los campos privados declarados en su clase base.

JavaScript 
class Usuario {
  #codigo;

  constructor(codigo) {
    this.#codigo = codigo;
  }

  consultarCodigo() {
    return this.#codigo;
  }
}

class Alumno extends Usuario {
  mostrarCodigo() {
    // Incorrecto:
    // return this.#codigo;

    // Correcto:
    return this.consultarCodigo();
  }
}

const alumno = new Alumno("A102");

console.log(alumno.mostrarCodigo());
// A102

Aunque Alumno hereda de Usuario, no puede utilizar directamente this.#codigo.

Debe acceder a esa información mediante un método público proporcionado por la clase base.

📌 Importante

Los campos privados declarados con # pertenecen a la clase que los declara.

No son accesibles directamente desde una clase derivada, aunque exista una relación de herencia.

Ejemplos prácticos en aplicaciones web

Ejemplo 1. Usuarios de una plataforma educativa

Vamos a crear una estructura de clases para representar diferentes tipos de usuarios de una plataforma educativa.

Todos los usuarios tendrán un nombre y un correo electrónico. Los alumnos tendrán un ciclo formativo y los profesores un departamento.

JavaScript 
class Usuario {
  constructor(nombre, email) {
    this.nombre = nombre;
    this.email = email;
  }

  mostrarDatos() {
    return `${this.nombre} - ${this.email}`;
  }

  mostrarRol() {
    return "Usuario general";
  }
}

class Alumno extends Usuario {
  constructor(nombre, email, ciclo) {
    super(nombre, email);
    this.ciclo = ciclo;
  }

  mostrarRol() {
    return "Alumno";
  }

  mostrarDatos() {
    return `${super.mostrarDatos()} - ${this.ciclo}`;
  }
}

class Profesor extends Usuario {
  constructor(nombre, email, departamento) {
    super(nombre, email);
    this.departamento = departamento;
  }

  mostrarRol() {
    return "Profesor";
  }

  mostrarDatos() {
    return `${super.mostrarDatos()} - ${this.departamento}`;
  }
}

const alumno = new Alumno(
  "Lucía",
  "lucia@ejemplo.com",
  "DAW"
);

const profesor = new Profesor(
  "Carlos",
  "carlos@ejemplo.com",
  "Informática"
);

console.log(alumno.mostrarRol());
// Alumno

console.log(alumno.mostrarDatos());
// Lucía - lucia@ejemplo.com - DAW

console.log(profesor.mostrarRol());
// Profesor

console.log(profesor.mostrarDatos());
// Carlos - carlos@ejemplo.com - Informática

En este ejemplo utilizamos diferentes mecanismos de herencia.

  • extends establece la relación entre las clases.
  • super() ejecuta el constructor de Usuario.
  • Las clases derivadas añaden propiedades específicas.
  • mostrarRol() se redefine en cada clase derivada.
  • super.mostrarDatos() permite reutilizar el método de la clase base.
💻 Ejemplo DAW

Esta estructura podría utilizarse como punto de partida para una aplicación educativa que gestione diferentes perfiles de usuario.

En una aplicación real, los permisos de acceso deberían comprobarse también en el servidor. La herencia por sí sola no proporciona seguridad.

Ejemplo 2. Productos de una tienda online

Supongamos que estamos desarrollando una tienda online que vende productos físicos y digitales.

Todos los productos tienen un nombre y un precio, pero cada tipo necesita mostrar información diferente.

JavaScript 
class Producto {
  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio;
  }

  mostrarInformacion() {
    return `${this.nombre}: ${this.precio} €`;
  }
}

class ProductoFisico extends Producto {
  constructor(nombre, precio, peso) {
    super(nombre, precio);
    this.peso = peso;
  }

  mostrarInformacion() {
    return `${super.mostrarInformacion()} - ${this.peso} kg`;
  }
}

class ProductoDigital extends Producto {
  constructor(nombre, precio, formato) {
    super(nombre, precio);
    this.formato = formato;
  }

  mostrarInformacion() {
    return `${super.mostrarInformacion()} - ${this.formato}`;
  }
}

const teclado = new ProductoFisico(
  "Teclado",
  45,
  0.8
);

const curso = new ProductoDigital(
  "Curso de JavaScript",
  30,
  "Vídeo"
);

console.log(teclado.mostrarInformacion());
// Teclado: 45 € - 0.8 kg

console.log(curso.mostrarInformacion());
// Curso de JavaScript: 30 € - Vídeo

La clase Producto contiene las características compartidas.

Las clases ProductoFisico y ProductoDigital amplían esa información con propiedades específicas.

Además, ambas redefinen mostrarInformacion() para incluir sus datos particulares.

Ejemplo 3. Notificaciones de una aplicación

Vamos a diseñar un sistema sencillo de notificaciones.

Todas las notificaciones tendrán un mensaje, pero cada tipo mostrará una información diferente.

JavaScript 
class Notificacion {
  constructor(mensaje) {
    this.mensaje = mensaje;
  }

  mostrar() {
    return `Notificación: ${this.mensaje}`;
  }
}

class NotificacionEmail extends Notificacion {
  mostrar() {
    return `Email: ${this.mensaje}`;
  }
}

class NotificacionSMS extends Notificacion {
  mostrar() {
    return `SMS: ${this.mensaje}`;
  }
}

class NotificacionInterna extends Notificacion {
  mostrar() {
    return `Aviso interno: ${this.mensaje}`;
  }
}

const notificaciones = [
  new NotificacionEmail("Pedido confirmado"),
  new NotificacionSMS("Código de acceso"),
  new NotificacionInterna("Tienes un mensaje")
];

notificaciones.forEach(notificacion => {
  console.log(notificacion.mostrar());
});

// Email: Pedido confirmado
// SMS: Código de acceso
// Aviso interno: Tienes un mensaje

Este ejemplo combina herencia y polimorfismo.

Las clases derivadas reutilizan la propiedad mensaje y redefinen el método mostrar().

Después, recorremos un array de notificaciones y utilizamos la misma operación con todos los objetos.

⚠️ Atención

Este ejemplo simula las notificaciones mediante mensajes de texto.

No envía correos electrónicos ni SMS reales.

Resumen del apartado

En este apartado hemos profundizado en la herencia entre clases y hemos aprendido a utilizarla en JavaScript.

  • La herencia permite crear clases derivadas que aprovechan características de una clase base.
  • La clase base contiene propiedades y métodos que pueden compartir diferentes clases derivadas.
  • La clase derivada puede añadir propiedades y métodos específicos.
  • La palabra clave extends establece la relación de herencia entre clases.
  • Una instancia de una clase derivada puede utilizar métodos heredados.
  • JavaScript utiliza la cadena de prototipos para encontrar los métodos heredados.
  • Cuando una clase derivada define su propio constructor, puede llamar al constructor base mediante super().
  • En un constructor derivado, debemos llamar a super() antes de utilizar this.
  • La redefinición de métodos permite modificar el comportamiento heredado.
  • Mediante super.metodo() podemos utilizar un método de la clase base.
  • El operador instanceof permite comprobar relaciones basadas en la cadena de prototipos.
  • La herencia suele ser adecuada cuando existe una relación del tipo «es un tipo de».
  • Cuando un objeto contiene otros, puede resultar más adecuada la composición.
📌 Importante

Recuerda estas tres instrucciones fundamentales:

extends: establece la herencia.

super(): llama al constructor de la clase base.

super.metodo(): permite utilizar un método de la clase base.

💭 Piensa

Queremos desarrollar una aplicación web para gestionar diferentes tipos de empleados de una empresa tecnológica.

Todos los empleados tienen un nombre y un salario base.

Sin embargo, existen dos tipos de empleados: desarrolladores y diseñadores.

Los desarrolladores tienen un lenguaje de programación principal, mientras que los diseñadores tienen una especialidad.

Además, queremos que cada tipo de empleado pueda mostrar una descripción adaptada a su función.

Reflexiona sobre estas cuestiones:

  1. ¿Qué clase base podríamos definir para representar a todos los empleados?
  2. ¿Qué clases derivadas necesitaríamos?
  3. ¿Cómo utilizaríamos extends para establecer la herencia?
  4. ¿Para qué utilizaríamos super() en los constructores?
  5. ¿Cómo podríamos redefinir un método mostrarDatos() en cada clase derivada?
  6. ¿Cómo podríamos aprovechar super.mostrarDatos() para evitar repetir código?
Ver una posible solución

Podemos definir una clase base Empleado y crear las clases derivadas Desarrollador y Disenador.

JavaScript 
class Empleado {
  constructor(nombre, salarioBase) {
    this.nombre = nombre;
    this.salarioBase = salarioBase;
  }

  mostrarDatos() {
    return `${this.nombre} - ${this.salarioBase} €`;
  }
}

class Desarrollador extends Empleado {
  constructor(nombre, salarioBase, lenguaje) {
    super(nombre, salarioBase);
    this.lenguaje = lenguaje;
  }

  mostrarDatos() {
    return `${super.mostrarDatos()} - Lenguaje: ${this.lenguaje}`;
  }
}

class Disenador extends Empleado {
  constructor(nombre, salarioBase, especialidad) {
    super(nombre, salarioBase);
    this.especialidad = especialidad;
  }

  mostrarDatos() {
    return `${super.mostrarDatos()} - Especialidad: ${this.especialidad}`;
  }
}

const desarrollador = new Desarrollador(
  "Ana",
  1800,
  "JavaScript"
);

const disenador = new Disenador(
  "Carlos",
  1700,
  "Interfaces web"
);

console.log(desarrollador.mostrarDatos());
// Ana - 1800 € - Lenguaje: JavaScript

console.log(disenador.mostrarDatos());
// Carlos - 1700 € - Especialidad: Interfaces web

console.log(desarrollador instanceof Empleado);
// true

console.log(disenador instanceof Empleado);
// true

Clase base: Empleado contiene las propiedades nombre y salarioBase, además del método mostrarDatos().

Clases derivadas: Desarrollador y Disenador heredan de Empleado.

extends: establece la relación de herencia entre las clases.

super(): permite ejecutar el constructor de Empleado para inicializar los datos comunes.

Redefinición: cada clase derivada define su propia versión de mostrarDatos().

super.mostrarDatos(): permite reutilizar la información común sin repetir el código del método original.

Esta solución es una versión simplificada. En una aplicación real podríamos añadir validaciones para los salarios y otras reglas de gestión de empleados.
