📝 Actividades de la UT6

Para finalizar la UT6 vas a aplicar de forma conjunta los principales conceptos de objetos y Programación Orientada a Objetos en JavaScript, trabajados en los apartados 6.1 a 6.11.

Las actividades se organizan en tres bloques: actividades prácticas, un reto final y una autoevaluación para comprobar los conocimientos fundamentales de la unidad.

📌 Importante

En las actividades de programación no basta con que el resultado sea correcto. Debes identificar responsabilidades, utilizar correctamente objetos, clases y métodos, y organizar el código para que sea comprensible y reutilizable.

💻 Actividades prácticas

Actividad 1 — Analiza un objeto literal

Observa este objeto sin ejecutar el código.

JavaScript · Código de partida
const alumno = {
  nombre: "Lucía",
  edad: 20,
  presentarse() {
    return `Soy ${this.nombre}`;
  }
};

console.log(alumno.nombre);
console.log(alumno.presentarse());
  1. Identifica todas sus propiedades y el método.
  2. Predice qué muestran las dos llamadas a console.log().
  3. Explica qué representa this dentro de presentarse().
  4. Añade una propiedad curso con el valor "2.º DAW" y muéstrala.
  5. Ejecuta el código y contrasta tus respuestas.
📌 Recuerda

Un método es una función asociada a un objeto. Para ejecutarlo debes utilizar paréntesis.

Actividad 2 — Acceso y manipulación de propiedades

Crea y modifica un objeto que represente un producto informático.

JavaScript · Código de partida
const producto = {
  nombre: "Teclado",
  precio: 40,
  stock: 8
};
  1. Crea un objeto producto con nombre, precio y stock.
  2. Consulta nombre mediante notación de punto y precio mediante corchetes.
  3. Añade una propiedad categoria.
  4. Aumenta el precio un 10 % y reduce el stock en una unidad.
  5. Elimina categoria utilizando delete.
  6. Explica por qué puedes modificar sus propiedades aunque declares el objeto con const.

Actividad 3 — Recorrido de propiedades

Trabaja con un objeto que almacena las calificaciones de un alumno.

JavaScript · Código de partida
const calificaciones = {
  dwec: 8,
  diw: 9,
  despliegue: 7
};
  1. Muestra todas las claves utilizando Object.keys().
  2. Obtén sus valores con Object.values() y calcula la media.
  3. Recorre los pares clave–valor con Object.entries().
  4. Repite el recorrido con for...in.
  5. Explica la diferencia entre propiedades propias y heredadas y cómo ayuda Object.hasOwn().
⚠️ Atención

for...in puede recorrer propiedades enumerables heredadas; Object.entries() devuelve las propiedades propias enumerables.

Actividad 4 — Métodos y palabra clave this

Analiza qué ocurre cuando se utiliza un método para consultar y modificar el estado de un objeto.

JavaScript · Código de partida
const cuenta = {
  titular: "Ana",
  saldo: 100,
  ingresar(cantidad) {
    this.saldo += cantidad;
  },
  consultar() {
    return this.saldo;
  }
};

cuenta.ingresar(50);
console.log(cuenta.consultar());
  1. Predice el saldo final sin ejecutar el programa.
  2. Explica por qué ingresar() utiliza this.saldo.
  3. Añade un método retirar(cantidad) que solo permita retirar dinero si hay saldo suficiente.
  4. Haz que retirar() devuelva true o false según el resultado.
  5. Explica por qué una función flecha no es la opción habitual para definir este tipo de método.

Actividad 5 — Funciones constructoras e instancias

Crea varios objetos a partir de una misma función constructora.

JavaScript · Código de partida
function Alumno(nombre, curso) {
  // Inicializa las propiedades.
}

const alumno1 = new Alumno("Lucía", "DAW");
  1. Define una función constructora Alumno(nombre, curso).
  2. Asigna sus dos parámetros a propiedades utilizando this.
  3. Crea tres instancias con new y muestra sus datos.
  4. Añade un método compartido en Alumno.prototype llamado presentarse().
  5. Comprueba que modificar el nombre de una instancia no cambia el de las demás.
📌 Recuerda

Cada llamada a new crea una instancia diferente. Los métodos definidos en el prototipo pueden compartirse entre instancias.

Actividad 6 — Clases, constructor y métodos

Implementa una clase para representar libros de una biblioteca.

JavaScript · Código de partida
class Libro {
  constructor(titulo, autor, disponible = true) {
    this.titulo = titulo;
    this.autor = autor;
    this.disponible = disponible;
  }

  // Completa los métodos.
}
  1. Crea una clase Libro con un constructor(titulo, autor, disponible).
  2. Añade el método prestar(), que cambie la disponibilidad a false solo si estaba disponible.
  3. Añade el método devolver() y otro método mostrarInfo().
  4. Crea dos libros, presta uno y comprueba el estado de ambos.
  5. Explica qué diferencia existe entre la clase y sus instancias.

Actividad 7 — Encapsulación y miembros privados

Completa una clase que protege su estado mediante una propiedad privada.

JavaScript · Código de partida
class Contador {
  #valor = 0;

  // Completa los métodos.
}

const contador = new Contador();
  1. Añade el método incrementar() para aumentar el contador en una unidad.
  2. Añade consultar() para devolver el valor actual.
  3. Implementa reiniciar() para devolver el contador a cero.
  4. Crea una instancia y comprueba los tres métodos.
  5. Explica por qué no puede accederse a #valor directamente desde fuera de la clase.
⚠️ Atención

Acceder a una propiedad privada #valor desde fuera de la clase produce un error de sintaxis.

Actividad 8 — Miembros estáticos y abstracción

Diseña una clase que permita crear productos y llevar la cuenta de cuántos se han creado.

  1. Define una clase Producto con nombre y precio.
  2. Añade un campo estático cantidadCreados inicializado a cero.
  3. Incrementa ese contador en el constructor.
  4. Crea tres productos y consulta Producto.cantidadCreados.
  5. Explica por qué el contador pertenece a la clase y no a cada instancia.
  6. Indica qué datos y operaciones esenciales has seleccionado al abstraer un producto.

Actividad 9 — Herencia con extends y super

Completa una jerarquía sencilla de empleados.

JavaScript · Código de partida
class Empleado {
  constructor(nombre) {
    this.nombre = nombre;
  }

  presentarse() {
    return `Soy ${this.nombre}`;
  }
}

// Completa la clase Desarrollador.
  1. Crea una clase Desarrollador que herede de Empleado.
  2. Añade la propiedad lenguaje y llama a super(nombre) en el constructor.
  3. Sobrescribe presentarse() para incluir el lenguaje de programación.
  4. Crea un empleado y un desarrollador y compara sus resultados.
  5. Explica qué ocurriría si utilizases this antes de llamar a super() en el constructor derivado.

Actividad 10 — Composición y colecciones de objetos

Organiza un pedido mediante objetos que colaboran entre sí.

JavaScript · Código de partida
class Pedido {
  constructor() {
    this.productos = [];
  }

  // Completa los métodos.
}
  1. Crea una clase Producto con nombre y precio.
  2. Crea una clase Pedido que guarde productos en un array.
  3. Implementa agregarProducto(producto).
  4. Implementa calcularTotal() sumando los precios de los productos.
  5. Añade tres productos y comprueba el total.
  6. Explica por qué la relación entre Pedido y Producto es un ejemplo de composición o agregación, y no de herencia.
📌 Recuerda

La herencia expresa una relación «es un tipo de»; la composición permite construir un objeto con otros objetos que colaboran.

🧩 Reto final — Sistema de gestión de pedidos orientado a objetos

Te incorporas a un equipo de desarrollo que está creando una aplicación para gestionar pedidos de una tienda de informática. Debes transformar la lógica del programa en un diseño orientado a objetos, con clases que tengan responsabilidades claras y colaboren entre sí.

Situación inicial

La tienda necesita almacenar productos con nombre, precio y stock, crear pedidos, incorporar líneas con cantidades, calcular importes y controlar el estado de cada pedido.

Los datos de partida son:

JavaScript · Datos iniciales
const productosIniciales = [
  { id: 1, nombre: "Teclado", precio: 35, stock: 10 },
  { id: 2, nombre: "Ratón", precio: 20, stock: 15 },
  { id: 3, nombre: "Monitor", precio: 180, stock: 5 }
];

Organiza el proyecto con esta estructura:

Estructura de archivos
gestion-pedidos-poo/
├── index.html
└── js/
    ├── Producto.js
    ├── Pedido.js
    ├── GestorPedidos.js
    └── main.js

Tu misión

  1. Diseña la clase Producto. Incluye id, nombre, precio y stock. Valida que el precio y el stock no sean negativos.
  2. Encapsula el stock. Utiliza un campo privado #stock y métodos públicos para consultarlo y descontar unidades de forma controlada.
  3. Diseña la clase Pedido. Almacena sus líneas de pedido en una colección. Cada línea debe relacionar un producto y una cantidad.
  4. Añade productos al pedido. Implementa agregarProducto(producto, cantidad) y evita cantidades no válidas o superiores al stock disponible.
  5. Calcula el importe. Implementa calcularTotal() utilizando los precios y las cantidades de las líneas.
  6. Controla el estado. Define estados como "pendiente" y "confirmado". Al confirmar un pedido válido, descuenta las unidades del stock; no permitas confirmarlo dos veces.
  7. Crea GestorPedidos. Haz que esta clase gestione una colección de pedidos y permita buscar un pedido por identificador.
  8. Utiliza un miembro estático. Incorpora un contador o generador de identificadores de pedidos compartido por la clase Pedido.
  9. Organiza el código. Utiliza export e import para separar las clases y deja en main.js la creación de instancias y las pruebas.
  10. Comprueba el funcionamiento. Crea al menos tres productos y dos pedidos. Prueba una compra válida, una cantidad superior al stock y un intento de confirmar dos veces el mismo pedido.
  11. Explica el diseño. Describe las responsabilidades de cada clase, las relaciones entre objetos, dónde se aplica la encapsulación y por qué no necesitas herencia para relacionar pedidos y productos.
⚠️ Atención

No descuentes stock simplemente por añadir un producto a un pedido. Hazlo al confirmar, después de comprobar que todas las cantidades solicitadas están disponibles, para evitar dejar un pedido parcialmente confirmado.

📦 Entrega del reto

Entrega la carpeta gestion-pedidos-poo con todos los archivos y un documento breve que incluya el diseño de clases, las decisiones tomadas y las pruebas realizadas.

El proyecto debe ejecutarse mediante Live Server y mostrar en la consola del navegador los pedidos, sus totales, los estados y las comprobaciones de stock.
