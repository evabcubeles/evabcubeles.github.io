1.1 Desarrollo web en entorno cliente

El desarrollo web se ocupa de crear sitios y aplicaciones accesibles mediante un navegador. En una aplicación web distinguimos habitualmente frontend y backend, aunque estos términos no son exactamente equivalentes a cliente y servidor.

🖥️Frontend

Parte de la aplicación que interactúa directamente con el usuario y se ejecuta principalmente en el navegador.

🗄️Backend

Parte que gestiona datos, lógica de negocio, autenticación y servicios en el servidor.

🌐Navegador

Entorno de ejecución del código cliente y punto de acceso habitual a las aplicaciones web.

📌 Recuerda

Frontend/backend describen áreas de la aplicación; cliente/servidor describen la arquitectura de comunicación.

1.2 Arquitectura cliente-servidor

La arquitectura cliente-servidor organiza la comunicación entre un componente que solicita recursos o servicios y otro que los procesa y responde.

ClienteSolicita recursos o servicios y presenta el resultado al usuario.
ServidorRecibe peticiones, procesa información y devuelve respuestas.
PeticiónMensaje enviado por el cliente para solicitar un recurso o realizar una operación.
RespuestaResultado que el servidor devuelve al cliente.
RecursoHTML, CSS, JavaScript, imágenes, documentos o datos.
Servicio webFuncionalidad ofrecida por el servidor, por ejemplo autenticarse o consultar información.

1.3 Ejecución de código en cliente y servidor

Una aplicación web puede ejecutar código tanto en el navegador como en el servidor. La diferencia fundamental es dónde se ejecuta el código y qué responsabilidades tiene.

ClienteServidor
Se ejecuta en el navegador.Se ejecuta en la infraestructura del servidor.
Interfaz, interacción y respuesta inmediata.Datos, autenticación, permisos y lógica crítica.
El código enviado al navegador puede inspeccionarse.El código del servidor no se entrega al navegador.
No debe considerarse un entorno de confianza.Debe validar y controlar las operaciones importantes.
⚠️ Atención

La validación en cliente mejora la experiencia de usuario, pero no sustituye la validación y seguridad del servidor.

1.4 JavaScript y los lenguajes de programación en entorno cliente

HTML, CSS y JavaScript colaboran en una página web, pero cumplen funciones distintas.

🧱HTML

Define la estructura y el contenido.

🎨CSS

Controla la presentación visual.

⚙️JavaScript

Añade lógica, comportamiento e interactividad.

JavaScriptLenguaje de programación de propósito general muy utilizado en desarrollo web.
ECMAScriptEspecificación que define las características fundamentales del lenguaje JavaScript.
Motor JavaScriptComponente que interpreta, compila y optimiza el código para ejecutarlo.
EcosistemaIncluye librerías, frameworks, herramientas y entornos como Node.js.

1.5 Características de los lenguajes de script

Un script es un conjunto de instrucciones que se ejecuta dentro de un determinado entorno. Los lenguajes de script suelen favorecer ciclos de desarrollo rápidos e integración con el entorno anfitrión.

Ejecución en un entornoEl script depende de un navegador, servidor, sistema operativo u otro entorno capaz de ejecutarlo.
Desarrollo ágilEscribir → ejecutar → comprobar → corregir.
IntegraciónPuede utilizar las funciones y APIs proporcionadas por su entorno.
Interpretado ≠ simpleLos motores modernos pueden utilizar JIT y otras optimizaciones.
📌 Recuerda

JavaScript puede describirse históricamente como lenguaje de script, pero es un lenguaje de programación completo y de propósito general.

1.6 Integración de JavaScript con HTML

JavaScript se incorpora a un documento HTML mediante el elemento <script>. Puede escribirse dentro del propio documento o almacenarse en un archivo externo.

FormaEjemploUso habitual
Interno<script>...</script>Ejemplos o pruebas pequeñas.
Externo<script src="js/app.js"></script>Proyectos organizados y mantenibles.
Externo con defer<script src="js/app.js" defer></script>Forma habitual en los proyectos del módulo.
📌 Organización

Una estructura habitual separa index.html, css/estilos.css, js/app.js e img/.

1.7 Herramientas para desarrollar con JavaScript

Durante el desarrollo utilizamos varias herramientas que forman parte del flujo de trabajo diario.

🧑‍💻Visual Studio Code

Editor para escribir y organizar los archivos del proyecto.

🚀Live Server

Servidor local sencillo para ejecutar y recargar proyectos web durante el desarrollo.

🛠️DevTools

Herramientas del navegador para inspeccionar, probar y depurar la aplicación.

ConsoleMensajes, errores y ejecución de instrucciones JavaScript.
ElementsInspección del HTML y los estilos aplicados.
SourcesArchivos cargados y depuración del JavaScript.
NetworkRecursos y peticiones de la página.

1.8 Primer programa en JavaScript

El primer contacto práctico con JavaScript nos permite comprender que programar implica mucho más que escribir código: también debemos ejecutarlo, observar su resultado y corregir los errores.

console.log()Muestra información en la consola del navegador.
alert()Muestra un cuadro de diálogo sencillo al usuario.
Orden de ejecuciónLas instrucciones se ejecutan siguiendo el flujo del programa.
Error de sintaxisEl código no respeta la forma válida del lenguaje.
Error de ejecuciónEl código es sintácticamente válido, pero falla mientras se ejecuta.
DepuraciónLeer mensajes, localizar el problema, corregir y volver a probar.
💻 Ciclo de trabajo

Escribir → guardar → ejecutar → observar → corregir → volver a probar.

Ideas clave de la UT1

📌 Si tuvieras que recordar solo estas ideas…
  • Una aplicación web suele distribuir responsabilidades entre cliente y servidor.
  • El navegador es el principal entorno de ejecución del código cliente.
  • HTML estructura, CSS presenta y JavaScript aporta lógica y comportamiento.
  • JavaScript se integra en HTML mediante <script> y normalmente se organiza en archivos externos.
  • El atributo defer permite cargar scripts externos sin bloquear innecesariamente el análisis del HTML.
  • El código cliente puede inspeccionarse y modificarse, por lo que las operaciones críticas deben controlarse en el servidor.
  • DevTools y Console son herramientas esenciales para comprender qué está ocurriendo y localizar errores.
  • Programar implica un ciclo continuo de escribir, probar, observar, corregir y volver a probar.
