1.8 Primer programa en JavaScript

Ya conocemos dónde se ejecuta JavaScript, cómo se integra con HTML y qué herramientas utilizaremos para trabajar. Ha llegado el momento de reunir todo lo aprendido y crear nuestro primer programa JavaScript completo.

En este apartado aprenderemos a ejecutar instrucciones sencillas, observar sus resultados y reconocer los primeros errores. Todavía no estudiaremos variables, tipos de datos ni estructuras de control; esos contenidos comenzarán en la UT2.

📌 Importante

Programar no consiste únicamente en escribir código. El ciclo habitual será escribir → guardar → ejecutar → observar → corregir → volver a probar.

Nuestro primer programa

Vamos a crear un proyecto muy sencillo formado por un documento HTML y un archivo JavaScript externo. De esta forma mantenemos separada la estructura de la página del comportamiento.

Estructura del proyecto
primer-programa/
├── index.html
└── js/
    └── app.js

En index.html escribiremos:

HTML · index.html
<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mi primer programa JavaScript</title>
  <script src="js/app.js" defer></script>
</head>
<body>
  <h1>Mi primer programa JavaScript</h1>
</body>
</html>

Y dentro de js/app.js:

JavaScript · js/app.js
console.log("¡Hola, JavaScript!");
💻 Pruébalo

Abre la carpeta con Visual Studio Code, inicia Live Server, pulsa F12 y entra en Console. Allí debería aparecer el mensaje ¡Hola, JavaScript!.

console.log()

console.log() permite enviar información a la consola del navegador. Es una herramienta especialmente útil durante el desarrollo porque nos ayuda a comprobar qué está haciendo el programa.

JavaScript
console.log("Hola");
console.log("Estoy aprendiendo JavaScript");
console.log(2 + 3);

Al ejecutar estas instrucciones, la consola mostrará dos textos y el resultado de la operación, 5.

⚠️ Atención

console.log() está pensado principalmente para el desarrollo y la depuración. El usuario normal de la aplicación no tiene por qué tener abierta la consola.

Mostrar información en la consola

Podemos utilizar varias llamadas a console.log() para seguir la ejecución de un programa. Cada llamada genera una nueva salida y nos permite observar el orden en que se procesan las instrucciones.

JavaScript
console.log("Inicio del programa");
console.log("Realizando una operación...");
console.log(10 + 5);
console.log("Fin del programa");

La consola mostrará los resultados siguiendo el mismo orden en el que aparecen las instrucciones en el archivo.

📌 Importante

En los próximos temas utilizaremos la consola constantemente para observar valores y comprender cómo se ejecuta nuestro código.

La función alert()

Otra forma sencilla de mostrar información es alert(). Esta función abre un cuadro de diálogo del navegador que interrumpe temporalmente la interacción hasta que el usuario lo cierra.

JavaScript
alert("Bienvenido a mi primera aplicación JavaScript");
InstrucciónDónde apareceUso habitual
console.log()Consola de DevToolsPruebas y depuración durante el desarrollo.
alert()Cuadro de diálogo del navegadorAvisos muy sencillos o demostraciones.
⚠️ Atención

alert() bloquea la interacción y resulta molesto si se utiliza continuamente. En aplicaciones reales suelen emplearse elementos de la propia interfaz para comunicar información al usuario.

Ejecución del código paso a paso

En un programa sencillo, JavaScript ejecuta las instrucciones siguiendo el flujo establecido por el código. En este primer ejemplo podemos observar claramente una secuencia de arriba hacia abajo.

JavaScript
console.log("Primera instrucción");
console.log("Segunda instrucción");
alert("Tercera instrucción");
console.log("Cuarta instrucción");

Primero aparecen los dos mensajes en la consola. Después se abre el cuadro de alert(). Hasta que lo cerramos, la siguiente instrucción no continúa.

1. CargarEl navegador carga los archivos
2. EjecutarJavaScript procesa las instrucciones
3. ObservarComprobamos el resultado
💡 Más adelante

No todo JavaScript se comportará como una simple secuencia de arriba hacia abajo. Los eventos y las operaciones asíncronas cambiarán el flujo de ejecución; los estudiaremos en unidades posteriores.

Errores de sintaxis

La sintaxis son las reglas que indican cómo debe escribirse el código. Si escribimos una instrucción que no respeta esas reglas, JavaScript no puede interpretarla correctamente.

Por ejemplo, en el siguiente código falta la comilla que cierra el texto:

JavaScript · contiene un error
console.log("Hola JavaScript);

Al ejecutar la página, la consola mostrará un mensaje de error de sintaxis, normalmente identificado como SyntaxError.

⚠️ Atención

Cuando aparezca un error, no cambies código al azar. Lee primero el mensaje y comprueba el archivo y la línea que señala el navegador.

Errores durante la ejecución

También podemos escribir código cuya sintaxis sea válida pero que falle cuando JavaScript intenta ejecutarlo. En ese caso hablamos de un error producido durante la ejecución.

JavaScript · contiene un error
console.log("Antes del error");
mostrarMensaje();
console.log("Después del error");

Como todavía no existe ninguna función llamada mostrarMensaje, el navegador mostrará un ReferenceError. Además, la última instrucción no llegará a ejecutarse en ese flujo.

📌 Importante

Que un archivo JavaScript se cargue correctamente no significa que todo su código vaya a ejecutarse sin problemas. Algunos errores solo aparecen cuando se alcanza la instrucción problemática.

Lectura de mensajes de error

Los mensajes de la consola pueden parecer complicados al principio, pero contienen información muy útil. Habitualmente debemos fijarnos en tres datos:

  • tipo de error, por ejemplo SyntaxError o ReferenceError;
  • descripción del problema;
  • archivo y línea donde se ha detectado.
Console · ejemplo de mensaje
Uncaught ReferenceError: mostrarMensaje is not defined
    at app.js:2

En este ejemplo, ReferenceError identifica el tipo de error, el texto explica que mostrarMensaje no está definido y app.js:2 nos dirige al archivo y a la línea que debemos revisar.

⚠️ No todos los mensajes rojos tienen el mismo origen

Un error como 404 favicon.ico indica que el navegador no ha encontrado un recurso. No implica necesariamente que nuestro código JavaScript tenga un error.

Primeras buenas prácticas

Desde el primer programa conviene adquirir hábitos que harán que el código sea más fácil de leer, probar y mantener.

  • mantener HTML y JavaScript en archivos separados cuando el proyecto crece;
  • utilizar nombres de archivos claros, como app.js;
  • respetar la indentación;
  • guardar los archivos antes de comprobar los cambios;
  • mantener abierta la consola durante las pruebas;
  • leer los mensajes de error antes de modificar el código;
  • probar pequeños cambios cada vez.
📌 Método de trabajo recomendado

Haz un cambio pequeño, guarda, prueba y comprueba el resultado. Si modificas muchas cosas a la vez y algo falla, será más difícil localizar la causa.

Primera práctica guiada

Vamos a terminar la UT1 creando y probando un pequeño programa. Utiliza el proyecto primer-programa y sustituye el contenido de js/app.js por el siguiente:

JavaScript · js/app.js
console.log("=== Mi primer programa JavaScript ===");
console.log("DWEC - Desarrollo Web en Entorno Cliente");
console.log("Resultado de 8 + 4:");
console.log(8 + 4);
alert("¡JavaScript está funcionando!");
console.log("Programa finalizado");

Realiza estas comprobaciones: abre la página con Live Server, observa la consola, cierra el cuadro de diálogo y comprueba que aparece el último mensaje. Después cambia los textos y la operación matemática y vuelve a ejecutar la página.

💭 Comprueba lo aprendido

Introduce voluntariamente un error eliminando una comilla de uno de los textos. ¿Qué ocurre? ¿Qué tipo de error muestra la consola? ¿En qué archivo y línea aparece?

Ver orientación

La consola debería mostrar un error de sintaxis. El mensaje exacto puede variar según el navegador, pero debes localizar la referencia a app.js y utilizar la línea indicada como punto de partida para revisar el código.

Después corrige la comilla, guarda el archivo y recarga la página para comprobar que el programa vuelve a funcionar.

💻 Fin de la introducción

Ya sabemos crear un proyecto, enlazar JavaScript con HTML, ejecutarlo en el navegador, utilizar la consola y comenzar a interpretar errores. En la UT2 empezaremos a estudiar la sintaxis de JavaScript de forma sistemática: variables, tipos de datos y operadores.
