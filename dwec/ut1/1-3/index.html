1.3 Ejecución de código en cliente y servidor

En el apartado anterior hemos visto que una aplicación web suele estar formada por un cliente y uno o varios servidores que se comunican mediante peticiones y respuestas.

Pero todavía queda una cuestión fundamental: ¿dónde se ejecutan los programas que hacen funcionar la aplicación?

Parte del código puede ejecutarse directamente en el navegador del usuario y otra parte puede ejecutarse en un servidor. Esta distribución del trabajo determina qué operaciones puede realizar cada parte, cómo responde la aplicación y qué información debe protegerse.

📌 Importante

En una aplicación web, no todo el código se ejecuta en el mismo lugar. Podemos distinguir entre código ejecutado en el cliente y código ejecutado en el servidor.

Durante este módulo nos centraremos especialmente en el código que se ejecuta en el cliente, utilizando JavaScript.

Ejecución de código en el cliente

La ejecución en el cliente se produce cuando el código de una aplicación se ejecuta en el dispositivo del usuario.

En una aplicación web, este código se ejecuta normalmente dentro del navegador.

Cuando accedemos a una página, el servidor puede enviar al navegador distintos archivos, por ejemplo:

  • documentos HTML;
  • hojas de estilo CSS;
  • archivos JavaScript;
  • imágenes y otros recursos.

El navegador recibe estos archivos y se encarga de procesarlos. En el caso de JavaScript, dispone de un motor de JavaScript capaz de interpretar y ejecutar las instrucciones del programa.

Servidor Envía los archivos de la aplicación
Navegador Recibe HTML, CSS y JavaScript
JavaScript Se ejecuta en el cliente

¿Qué significa que JavaScript se ejecute en el navegador?

Significa que muchas instrucciones JavaScript pueden realizarse directamente en el equipo del usuario, sin que sea necesario solicitar al servidor cada pequeña operación.

Por ejemplo, JavaScript puede utilizarse para:

  • realizar cálculos;
  • comprobar inicialmente los datos de un formulario;
  • responder a un clic del usuario;
  • mostrar u ocultar elementos;
  • actualizar partes de una página;
  • crear interfaces interactivas;
  • almacenar determinada información en el navegador;
  • solicitar nuevos datos a un servidor.
💻 Ejemplo DAW

Imagina un formulario de registro que contiene los campos Contraseña y Repetir contraseña. JavaScript puede comprobar directamente en el navegador si ambos valores coinciden y mostrar inmediatamente un mensaje al usuario. Para realizar esa primera comprobación no es necesario enviar los datos al servidor.

⚠️ Atención

Que una comprobación se realice con JavaScript en el cliente no significa que sea suficiente desde el punto de vista de la seguridad. Los datos importantes también deberán validarse en el servidor, ya que el código que se ejecuta en el navegador puede ser manipulado por el usuario.

Ejecución de código en el servidor

La ejecución en el servidor se produce cuando el programa se ejecuta en un sistema remoto que recibe peticiones de los clientes.

El navegador no ejecuta directamente ese código.

El funcionamiento general puede resumirse así: Cliente → petición → Servidor → ejecuta código → genera respuesta → Cliente.

El código del servidor puede estar escrito en diferentes lenguajes y tecnologías, por ejemplo:

  • Java;
  • PHP;
  • Python;
  • JavaScript mediante Node.js;
  • C#;
  • entre otros.

El servidor puede utilizar esos programas para:

  • consultar o modificar una base de datos;
  • comprobar usuarios y contraseñas;
  • gestionar permisos;
  • procesar pedidos;
  • calcular precios;
  • guardar información;
  • aplicar reglas de negocio;
  • generar respuestas para los clientes.
💻 Ejemplo DAW

Un usuario introduce su correo electrónico y contraseña para iniciar sesión. JavaScript puede comprobar en el navegador que los campos no estén vacíos. Sin embargo, comprobar si esas credenciales corresponden realmente a un usuario registrado debe realizarse en el servidor. El servidor consulta la información almacenada y devuelve una respuesta indicando si el acceso es correcto.

El código del servidor no se envía al navegador

Esta diferencia es muy importante.

Si una aplicación utiliza código PHP, Java o Python en el servidor, el navegador no recibe normalmente el código fuente de esos programas para ejecutarlo. El servidor ejecuta el programa y envía al cliente únicamente el resultado que corresponda.

Servidor Ejecuta el programa y consulta datos
Respuesta Envía únicamente el resultado necesario
Cliente Recibe y muestra o procesa la respuesta
📌 Importante

El código JavaScript que enviamos al navegador puede ser inspeccionado por el usuario mediante las herramientas de desarrollo. Por ello, nunca debemos confiar secretos, contraseñas, claves privadas o reglas de seguridad exclusivamente al código del cliente.

Diferencias entre ejecución cliente y servidor

Aunque cliente y servidor colaboran para construir una aplicación web, sus características son diferentes.

Característica Ejecución en cliente Ejecución en servidor
¿Dónde se ejecuta? En el dispositivo del usuario, normalmente dentro del navegador. En un servidor.
¿Quién ejecuta el código? El navegador. El entorno o software instalado en el servidor.
Tecnologías habituales Principalmente JavaScript en aplicaciones web. Java, PHP, Python, JavaScript con Node.js, C#, etc.
Interfaz de usuario Puede modificarla directamente. Normalmente genera o proporciona datos y recursos que utilizará el cliente.
Acceso a bases de datos No debería acceder directamente a la base de datos del servidor. Puede acceder a bases de datos y otros recursos internos.
Código visible para el usuario El código enviado al navegador puede inspeccionarse. El código permanece normalmente en el servidor.
Seguridad No debe considerarse un entorno de confianza. Permite mantener operaciones y datos sensibles fuera del cliente.
Respuesta al usuario Puede ser inmediata para muchas operaciones. Puede requerir comunicación a través de la red.
⚠️ Atención

No debemos identificar cliente = JavaScript y servidor = otro lenguaje. JavaScript también puede ejecutarse en un servidor mediante tecnologías como Node.js. Lo que determina si hablamos de ejecución en cliente o servidor es dónde se está ejecutando el programa, no solamente el lenguaje utilizado.

Ventajas e inconvenientes de ejecutar código en el cliente

Ejecutar parte del código directamente en el navegador ofrece numerosas ventajas, pero también presenta algunas limitaciones.

Ventajas

  • Respuesta más rápida: muchas operaciones pueden realizarse inmediatamente sin esperar una comunicación con el servidor.
  • Mayor interactividad: JavaScript permite responder a las acciones del usuario y crear interfaces dinámicas.
  • Menor número de peticiones innecesarias: no es necesario contactar con el servidor para realizar todas las operaciones.
  • Distribución del procesamiento: parte del trabajo puede realizarse en los dispositivos de los usuarios.
  • Mejor experiencia de usuario: la interfaz puede reaccionar de forma inmediata ante muchas acciones.

Inconvenientes

  • El código puede inspeccionarse: el usuario puede consultar el código JavaScript recibido por su navegador.
  • El entorno no es completamente controlable: los usuarios pueden utilizar navegadores, dispositivos y versiones diferentes.
  • Existen restricciones de seguridad: el navegador limita deliberadamente determinadas operaciones.
  • El código puede manipularse: no podemos confiar en que el código del cliente se ejecute exactamente como esperamos.
  • Compatibilidad: algunas características pueden no estar disponibles de la misma manera en todos los navegadores o versiones.
📌 Importante

El código del cliente es excelente para mejorar la interactividad y la experiencia de usuario, pero las operaciones críticas relacionadas con seguridad, permisos o integridad de los datos deben controlarse también desde el servidor.

Capacidades del navegador

Los navegadores actuales son entornos de ejecución muy potentes. Ya no se limitan simplemente a mostrar documentos HTML.

Entre otras cosas, un navegador moderno puede:

  • interpretar HTML;
  • aplicar estilos CSS;
  • ejecutar JavaScript;
  • responder a eventos del usuario;
  • modificar dinámicamente una página;
  • realizar peticiones a servidores;
  • almacenar información localmente;
  • reproducir contenido multimedia;
  • trabajar con gráficos;
  • acceder a determinadas características del dispositivo cuando el usuario concede los permisos necesarios;
  • proporcionar herramientas para probar y depurar aplicaciones.

Estas posibilidades se ofrecen a JavaScript mediante diferentes API del navegador.

Una API proporciona un conjunto de mecanismos que permiten a nuestros programas utilizar determinadas funcionalidades.

Más adelante aprenderemos a utilizar APIs para trabajar con:

  • el documento HTML;
  • eventos;
  • almacenamiento;
  • temporizadores;
  • comunicaciones con servidores.
💻 Ejemplo DAW

Cuando una aplicación web pregunta al usuario si permite conocer su ubicación, el código JavaScript no accede libremente al GPS del dispositivo. Utiliza una API proporcionada por el navegador y este controla el permiso concedido por el usuario.

El navegador como intermediario

Podemos resumir esta idea de la siguiente forma: JavaScript → API del navegador → recurso o funcionalidad.

El navegador actúa como intermediario y establece qué operaciones están permitidas.

Limitaciones de la ejecución en el navegador

Si cualquier página web pudiera realizar libremente cualquier operación sobre nuestro ordenador, navegar por Internet sería extremadamente peligroso.

Por ese motivo, los navegadores ejecutan el código JavaScript dentro de un entorno controlado y aplican diferentes restricciones de seguridad.

Entre otras limitaciones, una página web no puede actuar libremente sobre todo el sistema del usuario.

Por ejemplo, el navegador restringe:

  • el acceso directo a archivos del dispositivo;
  • la ejecución arbitraria de programas instalados;
  • el acceso a determinados dispositivos;
  • la lectura de información perteneciente a otros sitios web;
  • determinadas comunicaciones con servidores externos.

Algunas de estas operaciones pueden realizarse mediante APIs específicas, pero normalmente requieren restricciones o permisos.

El sandbox del navegador

De forma simplificada, podemos imaginar el navegador como una especie de zona controlada o sandbox.

El código JavaScript se ejecuta dentro de ese entorno y debe respetar las reglas establecidas por el navegador. Esto permite ejecutar programas procedentes de Internet reduciendo el riesgo de que puedan acceder libremente al sistema.

⚠️ Atención

Estas restricciones no son un defecto de JavaScript. Son una medida de seguridad fundamental de los navegadores.

Compatibilidad entre navegadores

Una aplicación web puede ser utilizada desde navegadores diferentes, como Chrome, Firefox, Edge, Safari y otros.

Todos ellos intentan seguir los estándares de la Web, pero pueden existir diferencias en:

  • las características disponibles;
  • la forma en que se implementan algunas funcionalidades;
  • el momento en que una característica nueva comienza a estar disponible;
  • el comportamiento de determinadas APIs;
  • las versiones antiguas de los navegadores.

Por ello, una aplicación que funciona correctamente en un navegador no debería darse automáticamente por válida para todos los demás.

Los estándares web

Los estándares permiten definir comportamientos comunes para que los desarrolladores puedan crear aplicaciones compatibles con distintos navegadores.

Aun así, durante el desarrollo debemos comprobar que las funcionalidades que utilizamos tienen un nivel de compatibilidad adecuado para nuestros usuarios.

Probar en distintos navegadores

Una buena práctica consiste en realizar pruebas al menos en los navegadores que vaya a utilizar nuestro público objetivo.

También existen herramientas y documentación que permiten consultar qué características de HTML, CSS o JavaScript son compatibles con cada navegador.

📌 Importante

En desarrollo web no debemos programar pensando únicamente en «funciona en mi navegador». Debemos tener en cuenta los navegadores y dispositivos desde los que accederán los usuarios.

Cuándo utilizar cliente y cuándo servidor

En una aplicación real no se trata de elegir entre cliente o servidor. Lo habitual es que ambos colaboren y que cada tarea se ejecute en el lugar más adecuado.

Podemos utilizar principalmente el cliente para:

  • responder rápidamente a las acciones del usuario;
  • modificar la interfaz;
  • realizar cálculos que no requieran información protegida;
  • realizar validaciones iniciales;
  • mostrar, ocultar o reorganizar información;
  • mejorar la experiencia de usuario.

Debemos utilizar el servidor para tareas como:

  • acceder a bases de datos;
  • autenticar usuarios;
  • comprobar permisos;
  • almacenar información importante;
  • aplicar reglas de negocio críticas;
  • gestionar información privada;
  • realizar operaciones que no deben depender de lo que indique el cliente.

Un ejemplo: realizar una compra

Imaginemos que el usuario tiene en su carrito un producto cuyo precio es 900 €.

JavaScript podría mostrar en la interfaz: 1 producto × 900 € = 900 €.

Pero cuando el usuario pulsa Comprar, el servidor no debería confiar simplemente en que el navegador le diga: «El precio es 900 €». El cliente podría haber sido manipulado.

El servidor debe comprobar nuevamente:

  • qué producto se está comprando;
  • cuál es su precio real;
  • si existe stock;
  • si el usuario puede realizar la operación;
  • cuál es el importe final;
  • y registrar correctamente la compra.
⚠️ Atención

Nunca debemos confiar en el cliente para decidir información crítica. El cliente puede facilitar la interacción, pero el servidor debe comprobar las operaciones que afecten a la seguridad o a la integridad de los datos.

Una regla sencilla para empezar

Podemos utilizar esta pregunta: ¿qué ocurriría si el usuario modificara el código o los datos enviados desde su navegador?

Si eso pudiera provocar un problema de seguridad, alterar información importante o permitir una operación no autorizada, esa decisión no debe depender exclusivamente del cliente.

💭 Piensa

Una plataforma educativa permite a un alumno consultar sus calificaciones. La interfaz contiene un botón Ver mis notas.

Cuando el usuario lo pulsa, la aplicación debe mostrar únicamente las calificaciones correspondientes a ese alumno.

¿Qué tareas podrían realizarse en el cliente y cuáles deben controlarse en el servidor?

Ver una posible solución

En el cliente, JavaScript puede detectar que el usuario ha pulsado el botón, mostrar un indicador de carga, solicitar la información y posteriormente presentar las notas en la interfaz.

El servidor debe identificar al usuario, comprobar que tiene permiso para consultar esas calificaciones y obtener únicamente los datos que puede visualizar.

No sería seguro enviar al navegador las notas de todos los alumnos y utilizar JavaScript simplemente para ocultar las que no correspondan al usuario. El servidor debe impedir desde el origen que un usuario pueda obtener información para la que no tiene autorización.
