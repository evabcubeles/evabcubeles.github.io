1.7 Herramientas para desarrollar con JavaScript

Para programar en JavaScript no basta con escribir instrucciones. También necesitamos herramientas que nos permitan crear archivos, ejecutar la aplicación, comprobar qué está ocurriendo y localizar errores.

En este apartado conoceremos las herramientas básicas que utilizaremos durante el módulo: el editor de código, el navegador y sus herramientas de desarrollo.

📌 Importante

Una parte fundamental del trabajo de un desarrollador consiste en observar, probar y depurar el código. Saber utilizar las herramientas de desarrollo es tan importante como conocer la sintaxis del lenguaje.

El editor de código

Un editor de código es una aplicación diseñada para escribir y organizar código fuente.

Aunque podríamos escribir JavaScript con un editor de texto sencillo, los editores orientados a programación ofrecen funciones que facilitan mucho el trabajo:

  • coloreado de sintaxis;
  • numeración de líneas;
  • autocompletado;
  • detección visual de algunos errores;
  • búsqueda y sustitución de texto;
  • gestión de carpetas y archivos;
  • integración con terminales y sistemas de control de versiones;
  • posibilidad de instalar extensiones.
💻 Ejemplo DAW

Si olvidamos cerrar una etiqueta HTML o escribimos una instrucción JavaScript con una estructura extraña, el editor puede ayudarnos a detectar visualmente que algo no encaja antes incluso de ejecutar la página.

Visual Studio Code

Durante el módulo utilizaremos Visual Studio Code como editor principal. Es un editor muy extendido en desarrollo web y permite trabajar cómodamente con HTML, CSS, JavaScript y muchas otras tecnologías.

Zonas principales de Visual Studio Code

Zona Para qué sirve
Explorador Permite ver y gestionar las carpetas y archivos del proyecto.
Editor Es la zona donde escribimos y modificamos el código.
Barra de actividad Da acceso al explorador, búsqueda, control de versiones, extensiones y otras herramientas.
Panel inferior Puede mostrar la terminal, problemas, salida y otras utilidades.
Barra de estado Muestra información del archivo y accesos rápidos, como Go Live cuando utilizamos Live Server.

Extensiones

Visual Studio Code puede ampliarse mediante extensiones. En el apartado anterior ya utilizamos una de ellas: Live Server.

Las extensiones pueden añadir nuevas funciones al editor, pero conviene instalar solo las que realmente necesitamos.

⚠️ Atención

No todas las extensiones son necesarias ni tienen la misma calidad. Antes de instalar una extensión debemos comprobar qué hace y evitar llenar el editor de herramientas que no vamos a utilizar.

El navegador web

En DWEC el navegador no es únicamente el programa que utilizamos para visualizar una página: es también el entorno donde se ejecuta nuestro JavaScript.

Cuando cargamos una aplicación web, el navegador:

  • procesa el HTML;
  • aplica los estilos CSS;
  • carga y ejecuta JavaScript;
  • realiza peticiones a otros recursos;
  • muestra el resultado al usuario.
Editor Escribimos el código
Navegador Ejecuta la aplicación
DevTools Analizamos qué ocurre

Durante el desarrollo es habitual mantener abiertos al mismo tiempo Visual Studio Code y el navegador, modificando el código en uno y comprobando el resultado en el otro.

Herramientas de desarrollo del navegador

Los navegadores modernos incorporan un conjunto de herramientas destinadas a los desarrolladores, conocidas habitualmente como DevTools.

En Chrome y Edge podemos abrirlas pulsando F12. También podemos utilizar Ctrl + Shift + I.

Algunas de las pestañas que utilizaremos durante el módulo son:

Pestaña Utilidad principal
Elements Inspeccionar el HTML y los estilos que se están mostrando.
Console Ver mensajes, errores y ejecutar pequeñas instrucciones JavaScript.
Sources Consultar los archivos JavaScript cargados y depurar su ejecución.
Network Analizar los recursos y peticiones que realiza la página.
📌 Importante

No necesitamos dominar todas las pestañas desde el primer día. Iremos utilizando cada herramienta cuando aparezca una necesidad concreta durante el curso.

La consola

La Console es una de las herramientas que más utilizaremos al programar con JavaScript.

En el apartado 1.6 ya comprobamos que una instrucción como:

JavaScript 
console.log("Hola desde JavaScript");

muestra el mensaje en la consola del navegador.

¿Para qué utilizaremos la consola?

  • comprobar si una parte del programa se ha ejecutado;
  • mostrar temporalmente valores durante el desarrollo;
  • leer mensajes de error;
  • probar pequeñas instrucciones JavaScript;
  • seguir el comportamiento de una aplicación.
⚠️ Atención

La consola es una herramienta para el desarrollador. Los mensajes escritos con console.log() no forman parte de la interfaz que ve normalmente el usuario.

💻 Pruébalo

Abre con Live Server el proyecto prueba-javascript que creamos en el apartado anterior. Pulsa F12 y entra en Console.

Escribe directamente junto al símbolo >:

Console 
2 + 3

Pulsa Enter. La consola debería responder: 5.

Ahora prueba:

Console 
"Hola" + " JavaScript"

No es necesario comprender todavía todos los detalles de estas expresiones. Lo importante es comprobar que la consola también puede ejecutar instrucciones JavaScript directamente.

El inspector de elementos

La pestaña Elements permite inspeccionar la estructura HTML que el navegador está mostrando.

Podemos seleccionar un elemento de la página y observar:

  • qué etiqueta HTML lo representa;
  • sus atributos;
  • su posición dentro de la estructura del documento;
  • los estilos CSS que se le están aplicando.
📌 Importante

Los cambios realizados directamente desde DevTools son temporales. Sirven para probar y analizar, pero desaparecen al recargar la página si no modificamos también los archivos originales en Visual Studio Code.

💻 Ejemplo DAW

Podemos inspeccionar el título Probando JavaScript de nuestro proyecto para comprobar que corresponde a un elemento <h1>.

La pestaña Sources

La pestaña Sources permite consultar los archivos que el navegador ha cargado y, especialmente, trabajar con el código JavaScript durante la depuración.

Cuando utilicemos JavaScript externo, podremos localizar en esta pestaña archivos como:

Proyecto 
prueba-javascript/
├── index.html
└── js/
    └── app.js

Desde Sources podremos abrir app.js, consultar sus líneas y, más adelante, detener temporalmente la ejecución para analizar qué está ocurriendo.

Detección de errores

Cuando un programa no funciona como esperamos, la primera reacción no debería ser cambiar código al azar. Debemos intentar obtener información sobre el problema.

Algunas señales que debemos comprobar son:

  • mensajes rojos en la consola;
  • líneas y archivos indicados en los mensajes de error;
  • archivos que no se han cargado;
  • rutas incorrectas;
  • comportamientos diferentes de los esperados.
⚠️ Atención

No todos los mensajes que aparecen en la consola significan que nuestro JavaScript esté mal. En el apartado anterior vimos, por ejemplo, que un favicon.ico inexistente puede producir un error 404 sin impedir que nuestro programa JavaScript funcione correctamente.

Leer antes de corregir

Los mensajes de error suelen aportar pistas importantes: qué tipo de problema se ha producido, en qué archivo y en qué línea. Aprenderemos a interpretarlos con más detalle en el apartado 1.8.

Depuración básica

La depuración o debugging es el proceso de localizar y corregir errores en un programa.

Una estrategia inicial puede seguir este ciclo:

Observar Qué está ocurriendo
Localizar Dónde aparece el problema
Comprobar Si la corrección funciona

Mensajes temporales con console.log()

Una técnica muy sencilla consiste en colocar mensajes temporales para comprobar si una determinada parte del código se está ejecutando.

JavaScript 
console.log("He llegado hasta este punto");

Breakpoints

DevTools permite colocar puntos de interrupción o breakpoints. Un breakpoint hace que la ejecución se detenga temporalmente en una línea determinada para que podamos analizar el estado del programa.

No vamos a profundizar todavía en su uso. Lo utilizaremos más adelante cuando nuestros programas tengan variables, decisiones, bucles y funciones.

📌 Importante

Depurar no significa únicamente «buscar errores». También significa comprender cómo se está ejecutando realmente nuestro programa.

Organización básica de un proyecto web

Las herramientas funcionan mejor cuando el proyecto está bien organizado. Por eso seguiremos utilizando una estructura sencilla y coherente.

Estructura de proyecto 
mi-proyecto/
├── index.html
├── css/
│   └── estilos.css
├── js/
│   └── app.js
└── img/

Además de facilitar la lectura del proyecto, esta organización ayuda a evitar errores en las rutas de los archivos.

⚠️ Atención

Los nombres de carpetas y archivos forman parte de las rutas. Debemos escribirlos siempre de forma coherente y prestar atención a mayúsculas, minúsculas y extensiones.

Control de versiones con Git y GitHub

A medida que un proyecto crece es importante disponer de un sistema que permita registrar los cambios que vamos realizando.

Git es un sistema de control de versiones que permite guardar el historial de un proyecto y trabajar de forma organizada con sus cambios.

GitHub es una plataforma que permite alojar repositorios Git y compartir proyectos, colaborar con otras personas y publicar determinados contenidos.

Herramienta Idea principal
Git Controla versiones y registra cambios del proyecto.
GitHub Aloja repositorios y facilita compartir y colaborar.
📌 Importante

Git y GitHub están relacionados, pero no son lo mismo. Git es la herramienta de control de versiones; GitHub es una plataforma que trabaja con repositorios Git.

En esta unidad nos basta con comprender su función general. Durante el curso podremos utilizarlos para guardar y publicar nuestros proyectos.

💭 Piensa

Estás trabajando en una página web y al abrirla no aparece el resultado esperado. ¿Qué herramientas utilizarías y en qué orden para intentar localizar el problema?

Ver solución

Una estrategia razonable sería comprobar primero que el proyecto y sus archivos están correctamente organizados y que Live Server está cargando la página.

Después abriríamos DevTools y revisaríamos la Console para buscar mensajes de error. Si fuese necesario, consultaríamos Elements para revisar la estructura HTML o Sources para comprobar el JavaScript cargado.

Lo importante es utilizar las herramientas para obtener información antes de modificar el código al azar.
