1.1 Desarrollo web en entorno cliente

Cuando utilizamos una aplicación web para consultar información, comprar un producto, realizar una matrícula, enviar un mensaje o gestionar nuestros datos, detrás de lo que vemos en pantalla intervienen distintas tecnologías y diferentes partes de la aplicación.

Algunas tareas se realizan directamente en el navegador del usuario, mientras que otras necesitan comunicarse con un servidor. Comprender esta diferencia es fundamental para entender cómo funcionan las aplicaciones web y, especialmente, cuál será el papel de JavaScript durante este módulo.

📌 Importante

El desarrollo web en entorno cliente se ocupa de la parte de una aplicación que se ejecuta principalmente en el navegador del usuario. JavaScript será el lenguaje fundamental que estudiaremos para programar su comportamiento.

Qué es el desarrollo web

El desarrollo web comprende el conjunto de técnicas, tecnologías y procesos utilizados para crear sitios y aplicaciones que funcionan mediante tecnologías web.

En sus orígenes, muchas páginas web tenían una función principalmente informativa: el navegador recibía un documento y lo mostraba al usuario. Actualmente, una aplicación web puede permitir realizar tareas mucho más complejas, como editar documentos, realizar videollamadas, comprar, gestionar cuentas bancarias, reproducir contenido multimedia o trabajar de forma colaborativa.

Sitio web y aplicación web

Los términos sitio web y aplicación web se utilizan a veces indistintamente, aunque existe una diferencia útil para comprender su finalidad.

Concepto Finalidad habitual Ejemplo
Sitio web Presentar o consultar información, aunque también puede incluir elementos interactivos. La web informativa de una empresa, un periódico o la página de un centro educativo.
Aplicación web Permitir que el usuario realice tareas y manipule información mediante una interfaz. Gmail, una tienda online, una plataforma educativa o una aplicación de gestión.

En la práctica, la separación no siempre es absoluta. Muchos sitios web actuales contienen características propias de una aplicación, por lo que ambos conceptos pueden solaparse.

Frontend y backend

Al desarrollar una aplicación web es habitual distinguir entre frontend y backend.

El frontend es la parte con la que interactúa directamente el usuario. Incluye la interfaz que aparece en el navegador y el comportamiento asociado a ella.

El backend corresponde a la parte de la aplicación que normalmente se ejecuta en servidores y se encarga de tareas como procesar datos, aplicar reglas de negocio, acceder a bases de datos o comprobar credenciales.

Frontend Backend
Dónde se sitúa Principalmente en el lado visible para el usuario. Principalmente en servidores.
Responsabilidad Interfaz, interacción y presentación de la información. Procesamiento, lógica de negocio, almacenamiento y servicios.
Tecnologías habituales HTML, CSS y JavaScript. Java, PHP, Python, JavaScript con Node.js, bases de datos, etc.
Ejemplo El formulario que utiliza el usuario para iniciar sesión. La comprobación de las credenciales almacenadas en una base de datos.
⚠️ Atención

Frontend/backend y cliente/servidor son conceptos relacionados, pero no significan exactamente lo mismo. Frontend y backend describen partes o responsabilidades de una aplicación. Cliente y servidor describen cómo diferentes sistemas participan y se comunican dentro de una arquitectura. Estudiaremos esta arquitectura en el apartado 1.2.

¿Y qué significa full-stack?

Se denomina desarrollador o desarrolladora full-stack a quien trabaja tanto con tecnologías frontend como con tecnologías backend.

Esto no significa necesariamente dominar absolutamente todas las tecnologías existentes, sino tener conocimientos suficientes para trabajar en diferentes partes de una aplicación web.

Desarrollo en entorno cliente

En una aplicación web, llamamos cliente al software o dispositivo que solicita y utiliza un servicio. En nuestro contexto, el cliente será normalmente el navegador web.

El desarrollo en entorno cliente consiste en programar funcionalidades que se ejecutan principalmente en ese navegador.

Entre las tareas que pueden realizarse en el cliente encontramos:

  • mostrar y actualizar información en una página;
  • responder a las acciones del usuario;
  • comprobar datos introducidos en un formulario;
  • mostrar u ocultar elementos;
  • crear interfaces dinámicas;
  • almacenar determinados datos en el navegador;
  • solicitar información a un servidor sin necesidad de recargar toda la página.
💻 Ejemplo DAW

Imagina un formulario de registro. Cuando el usuario deja vacío un campo obligatorio y la página muestra inmediatamente un aviso, esa comprobación puede realizarse mediante JavaScript en el navegador. Más adelante aprenderemos a programar este tipo de comportamientos.

Ejecutar determinadas tareas en el cliente permite ofrecer interfaces más rápidas e interactivas, pero no todas las operaciones deben realizarse allí. Por ejemplo, una comprobación de seguridad importante no puede confiar únicamente en código ejecutado en el navegador.

Desarrollo en entorno servidor

El entorno servidor es la parte en la que se ejecutan programas encargados de atender peticiones de los clientes, procesar información y devolver resultados.

Entre las tareas que habitualmente se realizan en el servidor se encuentran:

  • consultar o modificar información en una base de datos;
  • comprobar usuarios y contraseñas;
  • gestionar permisos;
  • aplicar reglas de negocio;
  • procesar pedidos o pagos;
  • proporcionar datos a otras aplicaciones mediante servicios web.
💻 Ejemplo DAW

En una tienda online, JavaScript puede actualizar visualmente el carrito en el navegador. Sin embargo, el precio definitivo del pedido, el stock disponible y el registro de la compra deben comprobarse y procesarse también en el servidor.

Cliente y servidor, por tanto, no son alternativas excluyentes. En las aplicaciones actuales es habitual que ambos colaboren continuamente.

El navegador como entorno de ejecución

Un navegador web no se limita a descargar y mostrar páginas. Los navegadores actuales son plataformas capaces de interpretar diferentes tecnologías y ejecutar programas.

Cuando recibe los archivos de una aplicación web, el navegador puede:

  • interpretar el HTML para construir la estructura del documento;
  • aplicar el CSS para determinar su presentación;
  • ejecutar JavaScript para programar su comportamiento;
  • gestionar eventos producidos por las acciones del usuario;
  • almacenar determinados datos localmente;
  • realizar comunicaciones con servidores;
  • ofrecer herramientas para analizar y depurar las aplicaciones.

Google Chrome, Mozilla Firefox, Microsoft Edge y Safari son algunos de los navegadores actuales. Aunque todos implementan estándares web comunes, pueden existir diferencias entre ellos, cuestión que estudiaremos más adelante.

📌 Importante

Para DWEC debemos empezar a pensar en el navegador como un entorno donde se ejecutan programas, no únicamente como una aplicación que muestra páginas web.

El papel de JavaScript en una aplicación web

Las tres tecnologías fundamentales del desarrollo web en el navegador son HTML, CSS y JavaScript. Cada una desempeña una función diferente.

HTML Estructura y contenido
CSS Presentación y diseño
JavaScript Comportamiento e interacción

HTML permite definir elementos como títulos, párrafos, imágenes, enlaces, formularios o botones. CSS permite controlar aspectos como colores, tamaños, posiciones y distribución. JavaScript permite añadir comportamiento y responder a lo que ocurre mientras el usuario utiliza la aplicación.

¿Qué podremos hacer con JavaScript?

A lo largo del módulo aprenderemos, entre otras cosas, a:

  • trabajar con datos y realizar cálculos;
  • tomar decisiones y repetir operaciones;
  • crear y utilizar funciones;
  • trabajar con arrays y objetos;
  • responder a eventos producidos por el usuario;
  • validar formularios;
  • modificar dinámicamente documentos HTML;
  • comunicarnos de forma asíncrona con servidores;
  • construir interfaces mediante tecnologías como React.
⚠️ Atención

En esta primera unidad todavía no necesitamos conocer la sintaxis de JavaScript en profundidad. Primero debemos comprender dónde se ejecuta, qué función cumple y cómo encaja dentro de una aplicación web.

El desarrollo web como actividad profesional

El desarrollo de una aplicación web puede implicar numerosos perfiles profesionales. En proyectos pequeños, una misma persona puede asumir varias funciones, mientras que en proyectos grandes suele existir una mayor especialización.

Perfil Trabajo principal
Desarrollador/a frontend Implementa la parte de la aplicación que se ejecuta y se presenta en el navegador, utilizando principalmente HTML, CSS y JavaScript.
Desarrollador/a backend Implementa la lógica que se ejecuta en el servidor, trabaja con datos, servicios, seguridad y reglas de negocio.
Desarrollador/a full-stack Trabaja tanto con tecnologías frontend como backend.
Diseñador/a UI/UX Participa en la planificación de la interfaz y de la experiencia de las personas usuarias.
Otros perfiles Pueden intervenir especialistas en bases de datos, sistemas, seguridad, accesibilidad, pruebas, DevOps y otras áreas.

Dentro del ciclo de DAW trabajaremos diferentes partes del desarrollo de aplicaciones web. El módulo DWEC se centra especialmente en la programación realizada en el entorno cliente.

💭 Piensa

Una tienda online permite buscar productos, añadirlos al carrito, identificarse como usuario y realizar una compra.

¿Qué tareas crees que podrían realizarse en el navegador y cuáles deberían realizarse necesariamente también en el servidor?

Ver una posible solución

En el navegador podrían realizarse tareas relacionadas con la interfaz, como actualizar visualmente el carrito, mostrar u ocultar elementos, comprobar inicialmente algunos campos de un formulario o responder a determinadas acciones del usuario.

El servidor debería encargarse de operaciones que no pueden confiarse únicamente al navegador, como comprobar credenciales, verificar el stock real, obtener información de la base de datos, calcular y validar el precio definitivo o registrar la compra.

En una aplicación real ambas partes suelen colaborar. Esta relación entre cliente y servidor será precisamente lo que estudiaremos en el siguiente apartado.
