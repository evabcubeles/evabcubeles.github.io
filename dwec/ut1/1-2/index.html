1.2 Arquitectura cliente-servidor

La mayoría de las aplicaciones web actuales funcionan siguiendo un modelo en el que distintos sistemas colaboran entre sí. El usuario utiliza un navegador para solicitar información o realizar una acción, y esa petición puede ser atendida por uno o varios servidores.

Este modelo se conoce como arquitectura cliente-servidor y constituye una de las bases del funcionamiento de la Web.

📌 Importante

En una arquitectura cliente-servidor, el cliente solicita recursos o servicios y el servidor recibe esas peticiones, las procesa y devuelve una respuesta.

Comprender este funcionamiento nos permitirá entender después dónde se ejecuta el código JavaScript y cómo se comunica una aplicación web con un servidor.

Qué es una arquitectura cliente-servidor

La arquitectura cliente-servidor es un modelo de funcionamiento en el que dos partes diferenciadas colaboran mediante una red:

  • el cliente, que solicita información o servicios;
  • el servidor, que recibe las solicitudes, realiza el procesamiento necesario y devuelve una respuesta.

En una aplicación web, el cliente suele ser el navegador, mientras que el servidor es un sistema remoto que proporciona páginas, datos o servicios.

Por ejemplo, cuando escribimos una dirección web en el navegador, este puede solicitar al servidor los archivos necesarios para mostrar una página.

Cliente Navegador del usuario
Petición / Respuesta Comunicación a través de la red
Servidor Procesa y proporciona recursos o servicios

El funcionamiento general puede resumirse así: Cliente → Petición → Servidor → Respuesta → Cliente.

Aunque este esquema parece sencillo, en una aplicación real pueden intervenir muchos elementos intermedios: servidores web, servidores de aplicaciones, bases de datos, servicios externos, sistemas de autenticación o redes de distribución de contenido.

💻 Ejemplo DAW

Cuando un alumno accede a una plataforma educativa, su navegador solicita al servidor la página de inicio. Después, si introduce sus credenciales, el servidor puede comprobarlas y devolver información personalizada. El navegador y el servidor están colaborando, pero cada uno realiza tareas diferentes.

El cliente

El cliente es el sistema que inicia una comunicación solicitando un recurso o servicio.

En el desarrollo web, el cliente suele ser un navegador como:

  • Google Chrome;
  • Mozilla Firefox;
  • Microsoft Edge;
  • Safari.

El navegador puede solicitar diferentes tipos de recursos:

  • documentos HTML;
  • hojas de estilo CSS;
  • archivos JavaScript;
  • imágenes;
  • vídeos;
  • fuentes;
  • archivos JSON;
  • datos proporcionados por una API.

El cliente también puede ejecutar código y responder a las acciones del usuario.

Por ejemplo, JavaScript puede ejecutarse en el navegador para validar inicialmente un formulario, actualizar la interfaz o realizar una nueva petición al servidor.

El cliente no es solamente el dispositivo

Conviene distinguir entre dispositivo y software cliente.

Un ordenador, un móvil o una tableta son dispositivos. Sin embargo, el cliente que participa directamente en una comunicación web puede ser el navegador instalado en ese dispositivo.

También existen otros tipos de clientes, como aplicaciones móviles, programas de escritorio o herramientas que consumen servicios web.

📌 Importante

En este módulo utilizaremos normalmente la palabra cliente para referirnos al navegador que ejecuta la parte de la aplicación web destinada al usuario.

El servidor

El servidor es el sistema encargado de recibir y atender peticiones procedentes de uno o varios clientes.

Dependiendo de la aplicación, el servidor puede realizar distintas tareas:

  • proporcionar archivos HTML, CSS o JavaScript;
  • consultar información en una base de datos;
  • comprobar credenciales;
  • procesar formularios;
  • aplicar reglas de negocio;
  • gestionar sesiones;
  • devolver información en formatos como JSON;
  • comunicarse con otros servicios.

Un mismo servidor puede atender simultáneamente a muchos usuarios.

Por ejemplo, una tienda online puede recibir en pocos segundos peticiones de cientos o miles de clientes distintos.

Servidor físico y software servidor

La palabra servidor puede utilizarse con dos significados relacionados:

Concepto Significado
Servidor como máquina Equipo físico o virtual conectado a una red y preparado para ofrecer servicios.
Servidor como software Programa que escucha peticiones y devuelve respuestas.

En desarrollo web es frecuente que ambos significados aparezcan juntos.

Por ejemplo, Apache o Nginx son programas que pueden actuar como servidores web y ejecutarse dentro de una máquina física o virtual.

⚠️ Atención

No debemos pensar necesariamente en un servidor como un único ordenador situado en una sala. Actualmente es muy habitual utilizar servidores virtuales, servicios en la nube y arquitecturas distribuidas.

Cómo se produce una petición y una respuesta

La comunicación entre cliente y servidor se basa en un proceso de petición y respuesta.

De forma simplificada, ocurre lo siguiente:

  1. El usuario realiza una acción en el navegador.
  2. El cliente genera una petición.
  3. La petición viaja a través de la red.
  4. El servidor recibe la petición.
  5. El servidor la procesa.
  6. El servidor genera una respuesta.
  7. La respuesta regresa al cliente.
  8. El navegador procesa la respuesta y muestra o actualiza la información.
💻 Ejemplo DAW

Imagina que un usuario entra en una tienda online y pulsa sobre la categoría Portátiles. El navegador puede solicitar al servidor la lista de productos disponibles. El servidor consulta la información necesaria y devuelve los datos. Finalmente, el navegador muestra esos productos al usuario.

Este proceso puede realizarse de forma muy rápida, por lo que normalmente el usuario no percibe todos los pasos que están ocurriendo.

El papel de HTTP

En la Web, gran parte de la comunicación entre cliente y servidor se realiza mediante el protocolo HTTP o su versión segura HTTPS.

HTTP define cómo se estructuran muchas de las peticiones y respuestas intercambiadas entre clientes y servidores web.

Por ejemplo, una petición puede indicar:

  • qué recurso se solicita;
  • qué tipo de operación quiere realizarse;
  • información adicional enviada por el cliente.

La respuesta puede contener:

  • el recurso solicitado;
  • datos;
  • información sobre el resultado de la operación;
  • un código que indica si la petición ha sido correcta o ha producido algún error.

Estudiaremos estas comunicaciones con más detalle cuando trabajemos con peticiones asíncronas en JavaScript.

📌 Importante

De momento no necesitamos memorizar todos los métodos y códigos HTTP. En esta unidad es suficiente comprender el modelo: el cliente envía una petición y el servidor devuelve una respuesta.

Recursos y servicios web

Cuando un cliente se comunica con un servidor puede solicitar diferentes tipos de elementos.

Podemos distinguir especialmente entre recursos y servicios.

Recursos web

Un recurso web es cualquier elemento accesible mediante una dirección o identificador.

Por ejemplo:

  • una página HTML;
  • una imagen;
  • una hoja de estilos;
  • un archivo JavaScript;
  • un documento PDF;
  • un vídeo.

Cuando escribimos una dirección en el navegador, estamos solicitando uno o varios recursos.

Servicios web

Un servidor también puede proporcionar servicios que no consisten simplemente en devolver un archivo.

Por ejemplo:

  • consultar el catálogo de productos;
  • crear un usuario;
  • comprobar un inicio de sesión;
  • registrar una compra;
  • buscar información;
  • actualizar datos.

Estos servicios suelen ser utilizados por aplicaciones mediante interfaces de programación.

Una de las formas más habituales consiste en utilizar una API.

Una API permite que distintos programas se comuniquen siguiendo unas reglas determinadas.

💻 Ejemplo DAW

Una aplicación meteorológica puede mostrar el tiempo sin almacenar directamente toda la información meteorológica. El navegador puede comunicarse con una API externa y solicitar los datos de una ciudad. El servidor de esa API devuelve la información y JavaScript puede utilizarla para actualizar la interfaz. Más adelante realizaremos este tipo de comunicaciones utilizando JavaScript.

Ejemplo del funcionamiento de una aplicación web

Veamos un ejemplo completo.

Imagina una aplicación web de comercio electrónico. Un usuario abre la página de una tienda desde su navegador.

1. Acceso a la aplicación

El navegador solicita al servidor los recursos necesarios.

El servidor puede devolver:

  • un documento HTML;
  • hojas de estilo CSS;
  • archivos JavaScript;
  • imágenes;
  • otros recursos.

El navegador recibe esos archivos y construye la interfaz.

2. Interacción con el usuario

El usuario pulsa Añadir al carrito.

JavaScript puede reaccionar inmediatamente y actualizar el número de productos mostrado en la interfaz. Esta parte puede realizarse en el cliente.

3. Comunicación con el servidor

La aplicación puede necesitar informar al servidor de que se ha añadido un producto. El navegador envía una petición.

4. Procesamiento

El servidor recibe la petición y puede:

  • comprobar que el producto existe;
  • comprobar el stock;
  • consultar una base de datos;
  • guardar información asociada al usuario.

5. Respuesta

El servidor devuelve una respuesta indicando el resultado.

Por ejemplo, puede devolver información indicando que el producto ha sido añadido correctamente.

6. Actualización de la interfaz

JavaScript recibe esa información y actualiza la página sin necesidad de cargarla completamente de nuevo.

📌 Importante

Una aplicación web moderna suele repartir el trabajo entre cliente y servidor. El cliente se encarga especialmente de la interacción y de la experiencia inmediata del usuario, mientras que el servidor realiza tareas relacionadas con datos, lógica, seguridad y servicios.

Ventajas de la arquitectura cliente-servidor

La arquitectura cliente-servidor ofrece numerosas ventajas.

Separación de responsabilidades

El cliente y el servidor pueden encargarse de tareas diferentes. Esto permite organizar mejor las aplicaciones y dividir su desarrollo en partes.

Centralización de los datos

La información importante puede almacenarse en servidores o bases de datos centralizadas. De esta forma, distintos clientes pueden trabajar con la misma información.

Acceso desde diferentes dispositivos

Una aplicación web puede utilizarse desde ordenadores, teléfonos móviles, tabletas u otros dispositivos con navegador.

Mantenimiento más sencillo

Una parte importante de la lógica se encuentra en el servidor, por lo que muchas actualizaciones pueden realizarse sin instalar software nuevo en cada dispositivo de los usuarios.

Escalabilidad

Los sistemas pueden prepararse para atender a un número creciente de usuarios mediante diferentes técnicas: utilizar varios servidores, distribuir la carga o contratar más recursos en la nube.

Seguridad

Determinadas operaciones sensibles pueden mantenerse en el servidor y fuera del alcance directo del usuario.

Por ejemplo, las contraseñas, reglas de autorización o datos privados no deben confiarse únicamente al código ejecutado en el cliente.

⚠️ Atención

Que una aplicación utilice un servidor no significa automáticamente que sea segura. La seguridad depende de cómo se diseñen e implementen tanto el cliente como el servidor.

💭 Piensa

Un usuario entra en una aplicación web de una biblioteca y busca el libro El Quijote.

La aplicación muestra si el libro está disponible y permite reservarlo.

¿Qué tareas podrían realizarse en el cliente y cuáles deberían realizarse en el servidor?

Ver una posible solución

En el cliente podrían realizarse tareas como recoger el texto introducido en el buscador, mostrar los resultados, actualizar la interfaz o comprobar inicialmente que el usuario ha escrito algún término.

El servidor debería consultar la base de datos para comprobar si el libro existe, conocer su disponibilidad real, identificar al usuario y registrar correctamente la reserva.

El cliente y el servidor colaborarían mediante peticiones y respuestas para completar todo el proceso.
