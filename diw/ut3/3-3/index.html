3.3 Estructura de un sitio web y mapa de navegación

En el apartado anterior organizamos la información en grupos, categorías y niveles. El siguiente paso es transformar esa arquitectura en una estructura de páginas o vistas relacionadas entre sí. Esta estructura nos permite representar qué partes tendrá el producto y cómo podrá desplazarse el usuario entre ellas antes de diseñar todavía los menús concretos.

Para visualizar estas relaciones utilizaremos el mapa de navegación, una representación esquemática que muestra las páginas, secciones o vistas principales y las conexiones existentes entre ellas. Es una herramienta de planificación: ayuda a detectar huecos, recorridos innecesarios y estructuras demasiado complejas antes de comenzar la implementación.

📌 Importante

El mapa de navegación representa la estructura y las relaciones del producto. No es todavía el menú de navegación ni el diseño visual de las pantallas.

Página, sitio web y aplicación web

Antes de representar una estructura conviene distinguir tres conceptos que utilizamos con frecuencia en desarrollo web. Aunque en la práctica pueden combinarse, cada uno pone el foco en un nivel diferente.

📄 Página web

Documento o vista concreta accesible mediante una dirección o dentro de una aplicación.

🌐 Sitio web

Conjunto organizado de páginas y recursos relacionados que comparten una finalidad y una estructura común.

🧩 Aplicación web

Producto web orientado especialmente a realizar tareas, gestionar información e interactuar con el sistema.

En un sitio web solemos hablar de páginas, mientras que en aplicaciones web también es frecuente hablar de vistas o pantallas. A efectos de planificación, lo importante es identificar las unidades que el usuario podrá consultar y las relaciones existentes entre ellas.

💻 Ejemplo DAW

La web de un instituto puede contener páginas como Inicio, Estudios, Noticias y Contacto. Una aplicación de gestión académica, en cambio, puede incluir vistas como Panel, Mis asignaturas, Entregas, Mensajes y Perfil. En ambos casos necesitamos definir una estructura antes de diseñar la navegación.

Estructura de un sitio web

La estructura de un producto web describe qué páginas, secciones o vistas lo forman y cómo se organizan entre sí. Surge de la arquitectura de la información definida previamente: las categorías y niveles de contenido comienzan a convertirse en partes concretas del sitio o aplicación.

Una estructura bien planteada debe permitir que las personas comprendan dónde se encuentran y qué caminos tienen disponibles. Para ello conviene identificar una vista o página de entrada, las secciones principales, los niveles secundarios y las relaciones necesarias entre ellos.

Elemento estructural Función Ejemplo
Entrada Punto desde el que comienza uno de los recorridos principales. Inicio o panel principal.
Sección principal Agrupa contenidos o funciones relevantes. Asignaturas.
Subnivel Concreta la información de una sección. Asignatura → Actividades.
Vista de detalle Muestra información específica sobre un elemento. Detalle de una actividad.
⚠️ Atención

La estructura no debe copiar automáticamente la organización técnica del proyecto, las carpetas del servidor o las tablas de la base de datos. Debe responder a cómo necesita comprender y utilizar el producto el usuario.

Relaciones entre páginas y vistas

Una vez identificadas las páginas o vistas debemos determinar cómo se relacionan. Algunas dependen de una sección superior, otras forman una secuencia y otras necesitan conexiones directas porque el usuario puede pasar de una a otra durante una tarea.

Estas relaciones no se crean únicamente porque dos contenidos sean parecidos. Deben responder a recorridos reales: qué necesita consultar una persona antes, durante o después de realizar una acción.

Relación Descripción Ejemplo
Padre → hijo Una sección contiene o conduce a elementos más específicos. Asignaturas → Desarrollo Web.
Secuencial Las vistas forman pasos de un proceso. Carrito → Envío → Pago → Confirmación.
Relacionada Dos vistas necesitan una conexión directa por la tarea del usuario. Actividad → Calificación de la actividad.
📌 Idea clave

Definir relaciones significa pensar en recorridos: desde dónde llega el usuario, qué necesita consultar y a qué vista debe poder dirigirse después.

Estructuras lineal, jerárquica, en red y combinada

Las relaciones entre páginas pueden dar lugar a distintos modelos estructurales. Estos modelos son esquemas conceptuales: un producto real puede utilizar uno de ellos o combinar varios según sus necesidades.

➡️ Estructura lineal

Las vistas se recorren siguiendo un orden determinado. Es adecuada cuando existe una secuencia clara.

A → B → C → D

Ejemplo: proceso de compra o asistente de configuración.

🌳 Estructura jerárquica

Parte de un nivel general y se ramifica hacia contenidos cada vez más específicos.

Inicio ↓ Secciones ↓ Subsecciones ↓ Detalle

Ejemplo: catálogo de productos o portal informativo.

🕸️ Estructura en red

Las páginas mantienen múltiples conexiones entre sí y permiten recorridos menos predecibles.

A ↔ B ↕ ↕ C ↔ D

Ejemplo: una wiki con numerosos enlaces relacionados.

🔀 Estructura combinada

Integra varios modelos. Es la situación más habitual en sitios y aplicaciones de cierta complejidad.

Jerarquía principal + secuencias + enlaces relacionados

Ejemplo: una tienda online con catálogo jerárquico y proceso de compra lineal.

⚠️ Atención

Una estructura más conectada no es necesariamente mejor. Añadir relaciones sin una necesidad real puede aumentar la complejidad y dificultar que el usuario comprenda dónde se encuentra.

Mapa de navegación

El mapa de navegación es una representación esquemática de la estructura de un sitio o aplicación. Muestra sus páginas, secciones o vistas y las relaciones principales entre ellas. Puede elaborarse antes de los wireframes porque todavía se centra en qué partes existen y cómo se conectan, no en su aspecto visual.

No existe una única notación obligatoria para crear un mapa de navegación. Lo importante es que los elementos, niveles y conexiones resulten comprensibles para las personas que participan en el proyecto.

Al revisar un mapa podemos comprobar, entre otras cuestiones, si existen páginas aisladas, si hay niveles innecesarios, si un recorrido obliga a dar demasiados pasos o si faltan conexiones necesarias entre vistas.

📌 Tres preguntas de orientación

Al analizar la estructura conviene comprobar si el usuario puede responder con facilidad a tres preguntas: ¿dónde estoy?, ¿de dónde vengo? y ¿a dónde puedo ir?. Los sistemas de navegación que estudiaremos en el siguiente apartado deberán ayudar a responderlas.

Ejemplo aplicado a una aplicación web

Supongamos que vamos a diseñar StudyFlow, una aplicación para que el alumnado consulte asignaturas, actividades pendientes, calificaciones y mensajes. A partir de la arquitectura de la información podemos proponer una primera estructura de vistas.

Vista Contenido o función principal Relaciones relevantes
Panel Resumen de próximas entregas y avisos. Asignaturas, Entregas, Mensajes.
Asignaturas Listado de materias del estudiante. Detalle de asignatura.
Detalle de asignatura Actividades, recursos y progreso. Detalle de actividad.
Entregas Actividades pendientes y realizadas. Detalle de actividad.
Perfil Datos personales y preferencias. Configuración.
💻 De la arquitectura al mapa

En el 3.2 decidimos qué contenidos existen y cómo se agrupan. En este apartado los hemos convertido en vistas y relaciones. En el 3.4 decidiremos qué elementos de navegación permitirán recorrer esa estructura: navegación principal, secundaria, contextual, migas de pan y enlaces.

💭 Piensa

Una plataforma de formación contiene Inicio, Cursos, Lecciones, Perfil, Certificados y Configuración. El equipo propone que Inicio lleve a Cursos, Cursos a Lecciones y Lecciones a Certificados, pero para consultar el Perfil o la Configuración el usuario debe volver siempre a Inicio.

¿Qué problemas observas en esta estructura? ¿Qué relaciones añadirías antes de diseñar los menús?

Ver una posible solución

La propuesta mezcla una secuencia lógica de aprendizaje con accesos que no deberían depender de esa secuencia. Perfil y Configuración son funciones generales que pueden necesitarse desde distintas partes de la aplicación.

Mantendríamos la relación Cursos → Lecciones → Certificados cuando tenga sentido para el recorrido formativo, pero permitiríamos que Perfil y Configuración fueran accesibles desde varias vistas principales. El mapa debería reflejar estas relaciones antes de decidir cómo se implementarán mediante menús u otros elementos de navegación.
