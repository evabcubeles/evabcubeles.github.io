✏️ Resumen de la UT7

En esta unidad hemos aprendido a crear interfaces web que se adaptan a diferentes tamaños de pantalla sin perder legibilidad, funcionalidad ni coherencia visual.

Este resumen reúne los conceptos esenciales de los apartados 7.1 a 7.8 como guía rápida de repaso, con ejemplos breves de CSS, aplicaciones a StudyFlow y recomendaciones para comprobar nuestros diseños.

Visión global de la unidad

El diseño responsive combina una estructura flexible, reglas de adaptación y pruebas. No consiste en preparar una versión independiente para cada dispositivo.

📌 Idea fundamental

Una interfaz responsive debe adaptarse al espacio disponible y seguir siendo utilizable. Cambiar el número de columnas no basta si los textos, imágenes, menús o formularios dejan de funcionar correctamente.

Fundamentos del diseño responsive

📱Adaptación

La disposición se reorganiza según la anchura disponible y las necesidades del contenido.

🧩Flexibilidad

Los contenedores y elementos evitan depender de anchuras fijas innecesarias.

👆Usabilidad

La navegación y los controles deben seguir siendo comprensibles y utilizables.

⚠️ No confundas

Un diseño que se ve correctamente en un móvil concreto no está necesariamente verificado para todas las anchuras intermedias.

Viewport y unidades de medida

El viewport es el área disponible para visualizar la página. En móviles, la etiqueta viewport ayuda a que el navegador utilice la anchura del dispositivo como referencia inicial.

<meta name="viewport" content="width=device-width, initial-scale=1.0">
%Proporción respecto a la dimensión de referencia del elemento.
rem y emUnidades relativas al tamaño de fuente raíz o al tamaño de fuente de referencia, según la propiedad.
vw y vhUnidades relacionadas con el tamaño del viewport.
max-widthLimita el crecimiento de un elemento sin imponer siempre una anchura fija.
.contenedor { width: 90%; max-width: 1100px; margin-inline: auto; }

Media queries y puntos de ruptura

Las media queries aplican reglas CSS cuando se cumple una condición. Los breakpoints son los valores en los que necesitamos modificar la distribución.

.modulos { display: grid; grid-template-columns: 1fr; gap: 16px; }

@media (min-width: 768px) {
  .modulos { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}

@media (min-width: 992px) {
  .modulos { grid-template-columns: repeat(3, minmax(0, 1fr)); }
}
Por debajo de 768 pxUna columna.
Desde 768 pxDos columnas.
Desde 992 pxTres columnas.
En los límitesComprobar 767, 768, 769, 991, 992 y 993 px.
📌 Recuerda

Los breakpoints deben elegirse por cómo se comporta el contenido, no únicamente por los tamaños de modelos de teléfono o tableta.

Imágenes y contenido flexible

Las imágenes y los vídeos deben respetar el espacio disponible. Cuando sea necesario, podemos ofrecer recursos de diferentes tamaños o composiciones.

img, video { max-width: 100%; height: auto; }
max-width: 100%Evita que el recurso crezca por encima de la anchura disponible de su contenedor.
height: autoAyuda a conservar la proporción natural del recurso.
srcset y sizesPermiten al navegador seleccionar una imagen apropiada entre varias opciones.
<picture>Permite ofrecer fuentes alternativas según condiciones de visualización.
⚠️ Atención

Una imagen que cabe en el contenedor puede seguir siendo poco adecuada si contiene texto diminuto o si se recorta información importante.

Distribuciones flexibles con Flexbox y CSS Grid

Ambos sistemas, estudiados en la UT6, permiten crear interfaces adaptables. Flexbox resulta especialmente útil para distribuir elementos en un eje; Grid facilita cuadrículas de filas y columnas.

↔️Flexbox

Menús, grupos de botones y alineación de elementos.

🔲CSS Grid

Paneles de tarjetas, galerías y estructuras en columnas.

🧱Combinación

Grid para la distribución general y Flexbox dentro de las tarjetas.

.tarjetas { display: grid; grid-template-columns: repeat(auto-fit, minmax(min(100%, 240px), 1fr)); gap: 16px; }

.barra { display: flex; flex-wrap: wrap; gap: 12px; }

La combinación de auto-fit y minmax() permite que las tarjetas se ajusten automáticamente al espacio, sin definir necesariamente un breakpoint para cada cambio.

Mobile first y estrategias responsive

Con mobile first comenzamos por una presentación adecuada para pantallas estrechas y añadimos mejoras para espacios mayores mediante reglas min-width.

Primero lo esencialPriorizar contenido, lectura y navegación.
Después ampliarAprovechar el espacio extra para reorganizar componentes.
Diseño fluidoCombinar tamaños relativos y límites razonables.
ProgresividadEvitar cambios bruscos que dificulten el uso.
💻 Ejemplo DAW · StudyFlow

En móvil, los módulos DWEC, DIW y SASP se muestran en una columna; cuando hay espacio suficiente, el panel pasa a dos y después a tres columnas.

Frameworks responsive: Bootstrap 5

Bootstrap proporciona clases y componentes reutilizables para construir interfaces. Su sistema de cuadrícula utiliza 12 columnas virtuales y clases que cambian según el breakpoint.

Clase o conceptoFunción
.container / .container-fluidContenedor con anchura adaptable o fluida.
.row y .col-*Organización de filas y columnas.
.col-12Ocupa 12 de las 12 partes.
.col-md-6Ocupa 6 partes desde 768 px.
.col-lg-4Ocupa 4 partes desde 992 px.
.g-3Separación entre columnas y filas mediante gutters.
.img-fluidImagen adaptable al contenedor.
<div class="container">
  <div class="row g-3">
    <div class="col-12 col-md-6 col-lg-4">DWEC</div>
    <div class="col-12 col-md-6 col-lg-4">DIW</div>
    <div class="col-12 col-md-6 col-lg-4">SASP</div>
  </div>
</div>

En este ejemplo, la tercera tarjeta ocupa la mitad de la segunda fila entre 768 y 991 px; no se expande automáticamente a toda la anchura.

Pruebas y verificación del diseño responsive

Una página no está terminada solo porque utilice media queries o un framework. Debemos probar diferentes anchuras, revisar el contenido y comprobar la interacción.

🔍DevTools

Simular anchuras y orientaciones; inspeccionar estilos y elementos.

📐Breakpoints

Comprobar justo antes, en el valor exacto y justo después.

⌨️Interacción

Revisar botones, formularios, zoom y navegación por teclado.

const raiz = document.documentElement;
const exceso = raiz.scrollWidth - raiz.clientWidth;
console.log(exceso > 0 ? `Posible desbordamiento: ${exceso}px` : 'Sin desbordamiento horizontal global');

Esta comprobación ayuda a detectar desbordamiento horizontal global, pero no sustituye la inspección visual ni localiza automáticamente el elemento responsable.

⚠️ Error frecuente

Aplicar overflow-x: hidden al body puede esconder un problema sin corregir su causa y dejar contenido inaccesible.

Buenas prácticas de diseño responsive

📱Comenzar por móvil

Organizar primero el contenido esencial y después ampliar la distribución.

📏Evitar rigidez

Usar unidades relativas, límites de anchura y distribuciones flexibles.

🖼️Cuidar los recursos

Comprobar proporciones, legibilidad y comportamiento de imágenes y vídeos.

🧪Probar los límites

Revisar diferentes anchuras y valores próximos a los breakpoints.

👆Verificar el uso

Comprobar menús, controles, formularios y navegación por teclado.

🛠️Corregir la causa

Investigar desbordamientos y solapamientos antes de ocultarlos.

Ideas clave para recordar

📌 Repaso final de la UT7
  • El diseño responsive adapta distribución, contenido e interacción.
  • La etiqueta viewport es fundamental para la presentación inicial en móviles.
  • Las unidades relativas y max-width facilitan diseños fluidos.
  • Las @media modifican reglas CSS cuando se cumplen condiciones.
  • Las imágenes deben respetar sus contenedores y mantener proporciones.
  • Flexbox y Grid pueden combinarse para construir componentes adaptables.
  • Mobile first prioriza pantallas estrechas y amplía progresivamente.
  • Bootstrap 5 aporta una cuadrícula de 12 columnas y utilidades responsive.
  • Las pruebas deben incluir anchuras intermedias, límites de breakpoints, zoom e interacción.

En las actividades de la unidad aplicaremos estas técnicas para construir y comprobar interfaces adaptables en situaciones similares a las de un proyecto profesional.
