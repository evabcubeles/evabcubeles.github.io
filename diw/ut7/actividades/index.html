📝 Actividades de la UT7

En esta unidad hemos aprendido a crear interfaces web responsive mediante el viewport, unidades flexibles, media queries, imágenes adaptables, Flexbox, CSS Grid, mobile first y Bootstrap 5.

Ahora aplicaremos estos conocimientos a un proyecto profesional: adaptar StudyFlow a pantallas de diferentes anchuras, comprobar su funcionamiento y documentar las correcciones realizadas.

Las actividades incluyen un reto final y una autoevaluación interactiva de diez preguntas con corrección y explicaciones.

📌 Objetivo de las actividades

Desarrollar una interfaz responsive, justificar las decisiones de diseño y verificar que la distribución, el contenido y la interacción funcionan en distintas condiciones de visualización.

🧩 Reto final — Adapta StudyFlow a cualquier pantalla

En la UT6 construimos la estructura de StudyFlow con CSS Grid y Flexbox. En esta unidad vamos a convertir esa maquetación en una interfaz adaptable y comprobada, sin crear una página distinta para cada dispositivo.

El encargo

StudyFlow es una plataforma para organizar tareas, materiales y actividades académicas. Su versión de escritorio incluye cabecera, navegación, panel lateral, tarjetas de módulos, avisos y pie de página.

El equipo ha detectado problemas al utilizarla en pantallas estrechas: algunas columnas no caben, las tarjetas se comprimen, las imágenes ocupan demasiado espacio y la navegación resulta incómoda.

Tu responsabilidad es adaptar la interfaz y demostrar mediante pruebas que los problemas se han corregido.

Tu misión

Desarrolla una versión responsive de StudyFlow que incluya, como mínimo:

  1. Cabecera y navegación adaptables: nombre o logotipo y enlaces a Inicio, Mis tareas, Calendario y Recursos, accesibles también en pantallas estrechas.
  2. Zona principal de módulos: al menos tres tarjetas (DWEC, DIW y SASP), con título, descripción y enlace o botón de acceso.
  3. Panel lateral: categorías o accesos rápidos que se reorganicen de manera razonable cuando falte espacio.
  4. Panel informativo: avisos, fechas próximas o recordatorios que sigan siendo legibles.
  5. Recurso gráfico adaptable: una imagen o ilustración que mantenga su proporción y no provoque desbordamiento.
  6. Pie de página: información del proyecto, sin superposiciones ni cortes en distintas anchuras.
  7. Verificación: pruebas de anchuras, orientación cuando proceda, zoom, teclado y posibles desbordamientos.
⚠️ Importante

No basta con que la página «se vea pequeña» en móvil. Debes reorganizar los componentes cuando lo necesiten, mantener el contenido accesible y justificar por qué has elegido tus puntos de ruptura.

📋 Requisitos técnicos del proyecto

Tu solución deberá cumplir los siguientes requisitos:

  1. HTML semántico: utilizar correctamente header, nav, main, section, aside y footer cuando corresponda.
  2. Viewport: incluir <meta name="viewport" content="width=device-width, initial-scale=1.0">.
  3. Enfoque mobile first: definir primero la distribución de pantalla estrecha y ampliarla mediante al menos dos media queries con min-width.
  4. Distribución responsive: mostrar las tarjetas en una columna en móvil y reorganizarlas en dos o más columnas cuando exista espacio suficiente.
  5. Flexbox y CSS Grid: utilizar ambos sistemas en componentes adecuados, explicando su función.
  6. Medidas flexibles: combinar unidades relativas, max-width y, cuando proceda, minmax() o min-width: 0.
  7. Contenido multimedia: impedir que las imágenes sobresalgan de sus contenedores; explicar cuándo sería útil srcset, sizes o picture.
  8. Navegación e interacción: mantener enlaces y botones visibles, utilizables y accesibles con teclado.
  9. Pruebas: comprobar como mínimo 375, 767, 768, 991, 992 y 1200 px, y añadir otros valores si detectas problemas.
  10. Calidad del código: separar HTML y CSS, utilizar clases descriptivas y evitar soluciones que oculten errores con overflow-x: hidden en el body.

💡 Orientación para comenzar

Una posibilidad es definir una distribución de una columna para móviles y ampliar el panel de tarjetas con media queries. Los valores son orientativos: puedes escoger otros si justificas que responden mejor al contenido.

.modulos {
  display: grid;
  grid-template-columns: minmax(0, 1fr);
  gap: 16px;
}

@media (min-width: 768px) {
  .modulos {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (min-width: 992px) {
  .modulos {
    grid-template-columns: repeat(3, minmax(0, 1fr));
  }
}

Para los recursos gráficos puedes partir de:

img, video {
  max-width: 100%;
  height: auto;
}
💻 Ejemplo DAW

En móvil, las tarjetas DWEC, DIW y SASP pueden mostrarse en una columna y el panel lateral pasar debajo del contenido principal. En una pantalla amplia, el panel lateral puede recuperar su posición y las tarjetas distribuirse en varias columnas.

🧠 Decisiones que debes justificar

  • Por qué has elegido tus breakpoints y qué ocurre a ambos lados.
  • Qué componentes has resuelto con Flexbox y cuáles con Grid.
  • Cómo has adaptado la navegación, el panel lateral y las imágenes.
  • Qué problema concreto has encontrado durante las pruebas y cómo lo has solucionado; si no has encontrado ninguno, explica qué comprobaciones lo respaldan.
📦 Entrega del reto

Entrega un archivo comprimido con la web funcional y un breve informe PDF con decisiones de diseño, tabla de pruebas y capturas de pantalla.

studyflow-responsive/
├── index.html
├── css/
│   └── estilos.css
├── img/
│   └── recursos-utilizados
└── informe-pruebas.pdf

El informe debe incluir:

  • Breve descripción del diseño mobile first y sus breakpoints.
  • Justificación del uso de Flexbox y CSS Grid.
  • Tabla con las anchuras comprobadas y resultados observados.
  • Al menos tres capturas: móvil, anchura intermedia y escritorio.
  • Problemas encontrados, correcciones y resultado de la nueva prueba.

Se valorará la adaptación real del contenido, la corrección técnica del HTML y CSS, la interacción y la calidad de las pruebas y explicaciones.

✅ Autoevaluación de la UT7

Responde las diez preguntas. Cada una tiene una única respuesta correcta. Al corregir recibirás una explicación de cada respuesta.

1. ¿Qué finalidad tiene la etiqueta meta name="viewport" en una página responsive?

2. ¿Cuál es la idea principal del enfoque mobile first?

3. ¿Qué sucede con una regla @media (min-width: 768px)?

4. ¿Por qué conviene probar 767, 768 y 769 px?

5. ¿Qué efecto tiene max-width: 100%; height: auto; en una imagen con dimensiones naturales?

6. ¿Qué técnica es adecuada para distribuir tarjetas en columnas que cambian con el espacio disponible?

7. En Bootstrap 5, ¿qué representa col-12 col-md-6 col-lg-4?

8. ¿Qué relación existe entre srcset y sizes cuando se usan descriptores de anchura?

9. ¿Qué significa que scrollWidth supere clientWidth en el elemento raíz?

10. ¿Cuál es la mejor respuesta ante una tabla que provoca desplazamiento horizontal de toda la página en móvil?
