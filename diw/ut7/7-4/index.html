7.4 Estrategias mobile first y desktop first

En el apartado 7.3 aprendimos a utilizar las media queries para modificar una interfaz según la anchura del viewport. Ahora veremos dos estrategias para organizar esas reglas: mobile first y desktop first.

Ambas permiten crear páginas responsive. La diferencia principal es desde qué distribución comenzamos a escribir el CSS y cómo incorporamos los cambios para otros tamaños de pantalla.

📌 Importante

Mobile first comienza con los estilos para espacios estrechos y suele ampliar la distribución mediante min-width. Desktop first comienza con una distribución amplia y suele simplificarla mediante max-width. Son estrategias de organización, no tecnologías diferentes.

Qué significa mobile first y desktop first

Cuando diseñamos una interfaz responsive debemos decidir qué presentación será nuestra base, es decir, qué estilos se aplicarán sin necesidad de cumplir una media query. Después añadimos modificaciones para otras anchuras.

En mobile first, la base se plantea para un espacio reducido: los elementos se organizan en una columna y se prioriza una lectura clara. En desktop first, la base aprovecha inicialmente un espacio amplio: por ejemplo, un panel con varias columnas.

Estrategia mobile first

Con mobile first escribimos primero los estilos que deben funcionar en el espacio más estrecho. A medida que aumenta la anchura disponible, añadimos reglas para aprovecharla mejor.

En StudyFlow podemos comenzar mostrando las tarjetas de los módulos en una sola columna y ampliar después a dos o tres columnas.

CSS · Ejemplo mobile first
.modulos {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

/* Desde 600px: dos columnas */
@media (min-width: 600px) {
  .modulos {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

/* Desde 900px: tres columnas */
@media (min-width: 900px) {
  .modulos {
    grid-template-columns: repeat(3, minmax(0, 1fr));
  }
}

En este caso, hasta 599 px se mantiene una columna; desde 600 px aparecen dos y desde 900 px, tres. Las condiciones min-width se acumulan: a 1000 px se cumplen las dos media queries, pero la última regla aplicable define las tres columnas porque tiene la misma especificidad y aparece después.

💻 Ejemplo DAW

Si una persona consulta StudyFlow desde un móvil, encontrará inicialmente las tarjetas apiladas, sin necesidad de desplazar la página horizontalmente. En una pantalla más amplia, la misma información puede distribuirse en varias columnas.

Ventajas y precauciones

  • Ayuda a priorizar el contenido esencial desde el comienzo.
  • Facilita construir una base sencilla y añadir mejoras cuando existe más espacio.
  • No significa que todas las páginas deban verse idénticas en móviles ni que debamos ocultar información importante.
  • Exige comprobar también las anchuras grandes: un diseño que funciona en móvil no queda automáticamente resuelto en escritorio.

Estrategia desktop first

Con desktop first comenzamos definiendo una distribución para espacios amplios. Después añadimos media queries para reorganizar los componentes cuando el viewport se reduce.

Para comparar las dos estrategias utilizaremos las mismas tres tarjetas de StudyFlow y los mismos puntos de ruptura.

CSS · Ejemplo desktop first
.modulos {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 16px;
}

/* Hasta 899px: dos columnas */
@media (max-width: 899px) {
  .modulos {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

/* Hasta 599px: una columna */
@media (max-width: 599px) {
  .modulos {
    grid-template-columns: 1fr;
  }
}

En este segundo ejemplo, la base muestra tres columnas. A 899 px o menos se muestran dos y a 599 px o menos se muestra una. Las condiciones max-width también pueden coincidir: a 500 px se cumplen ambas, por lo que la regla de una columna debe aparecer después.

⚠️ Atención

La estrategia desktop first no consiste en reducir todo proporcionalmente. Los componentes deben reorganizarse para conservar la legibilidad, la accesibilidad y la facilidad de uso.

Comparación de ambas estrategias

Las dos soluciones anteriores producen la misma distribución final para cada intervalo de anchura. Lo que cambia es la forma de escribir y organizar el CSS.

En proyectos nuevos suele ser práctico comenzar con mobile first, especialmente cuando la interfaz debe funcionar bien en espacios reducidos. Sin embargo, no es una obligación: desktop first puede resultar adecuado al adaptar una aplicación existente concebida inicialmente para escritorio.

Orden, cascada y breakpoints

En el apartado anterior vimos que las media queries participan en la cascada CSS. Esto es especialmente importante al organizar las estrategias mobile first y desktop first.

En mobile first, las consultas min-width suelen ordenarse de menor a mayor anchura. En desktop first, las consultas max-width suelen ordenarse de mayor a menor. Así, cuando varias reglas de igual especificidad se cumplen, prevalece la modificación más específica para el intervalo deseado.

CSS · Orden habitual en mobile first 
/* Mobile first: de menor a mayor */
.tarjeta {
  padding: 12px;
}

@media (min-width: 600px) {
  .tarjeta {
    padding: 16px;
  }
}

@media (min-width: 900px) {
  .tarjeta {
    padding: 24px;
  }
}
CSS · Orden habitual en desktop first 
/* Desktop first: de mayor a menor */
.tarjeta {
  padding: 24px;
}

@media (max-width: 899px) {
  .tarjeta {
    padding: 16px;
  }
}

@media (max-width: 599px) {
  .tarjeta {
    padding: 12px;
  }
}

Los dos enfoques se muestran como alternativas independientes. No debemos copiarlos juntos como si fueran una única solución. Además, el orden de aparición solo decide el resultado cuando las reglas compiten con la misma prioridad y especificidad.

📌 Importante

Un breakpoint no es «de móvil» o «de escritorio» por sí mismo. Se elige cuando el contenido necesita cambiar de distribución. La estrategia determina cómo escribimos las reglas alrededor de ese punto.

Aplicación práctica a StudyFlow

Vamos a preparar una versión mobile first del panel de módulos. El HTML será el mismo en cualquier anchura; únicamente cambiaremos las columnas mediante CSS.

HTML · Tarjetas de StudyFlow
<section class="modulos" aria-label="Módulos del curso">
  <article class="modulo"><h2>DWEC</h2><p>Entorno Cliente</p></article>
  <article class="modulo"><h2>DIW</h2><p>Diseño de Interfaces</p></article>
  <article class="modulo"><h2>SASP</h2><p>Sostenibilidad</p></article>
</section>
CSS · CSS completo para StudyFlow
.modulos {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

.modulo {
  min-width: 0;
  padding: 16px;
  border: 1px solid #b9dfc6;
  border-radius: 10px;
}

@media (min-width: 600px) {
  .modulos {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (min-width: 900px) {
  .modulos {
    grid-template-columns: repeat(3, minmax(0, 1fr));
  }
}

Por ejemplo, al seleccionar 750 px, ambas estrategias muestran dos columnas. En mobile first, esto ocurre porque se cumple la condición min-width: 600px, pero todavía no se alcanza 900px. En desktop first, se cumple max-width: 899px, pero no max-width: 599px. Aunque las condiciones son diferentes, el resultado visual es equivalente.

Para comprobarlo en un proyecto real, cambia la anchura del viewport desde las herramientas de desarrollo del navegador. Comprueba los tamaños intermedios y verifica que el contenido continúa siendo legible.

Buenas prácticas y errores frecuentes

  • No confundir estrategia con resultado: mobile first y desktop first pueden producir la misma interfaz.
  • Definir una base coherente: evita declarar estilos generales que después debas anular constantemente.
  • Ordenar las media queries: comprueba qué condiciones coinciden y cuál es la última regla aplicable.
  • Elegir breakpoints según el contenido: no utilices valores únicamente porque sean populares.
  • Probar todos los tamaños: revisa pantallas estrechas, anchas y medidas intermedias.
📌 Idea clave

La estrategia responsive determina por dónde comenzamos a diseñar y cómo ampliamos o simplificamos las reglas CSS. La prioridad es que el contenido funcione correctamente en cualquier anchura.

En el apartado 7.5 aplicaremos estas decisiones a maquetaciones responsive más completas con Flexbox y CSS Grid.

💭 Piensa

Vas a crear desde cero el panel de módulos de StudyFlow. En un móvil quieres mostrar una columna, a partir de 600 px dos y desde 900 px tres. ¿Qué estrategia elegirías y cómo organizarías las reglas CSS? ¿Podrías conseguir el mismo resultado con la estrategia contraria?

Ver una posible solución

Podemos elegir mobile first: definir una columna como regla general y añadir una media query min-width: 600px para dos columnas y otra min-width: 900px para tres. Es una opción clara cuando empezamos el proyecto desde cero.

También podríamos usar desktop first: definir tres columnas como base y añadir max-width: 899px para dos y max-width: 599px para una. Ambas estrategias permiten obtener el mismo resultado.
