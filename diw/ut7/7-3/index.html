7.3 Media queries y puntos de ruptura

En el apartado 7.2 aprendimos a utilizar el viewport y las dimensiones flexibles para que los elementos aprovechen el espacio disponible. Sin embargo, hay situaciones en las que no basta con reducir su anchura: necesitamos cambiar la distribución o la presentación de determinados componentes.

En este apartado estudiaremos las media queries, su sintaxis, las condiciones que permiten evaluar y los puntos de ruptura (breakpoints). También aprenderemos a comprobar cuándo se aplican las reglas y a elegir cambios que respondan a las necesidades reales del contenido.

📌 Importante

Una media query no detecta si el usuario tiene un modelo concreto de móvil o tableta. Evalúa características del entorno de visualización, como la anchura del viewport, y aplica estilos cuando se cumple una condición.

Qué son las media queries

Una media query es una condición escrita en CSS que permite aplicar un conjunto de reglas solo cuando se cumplen determinadas características del dispositivo o del entorno de visualización.

Por ejemplo, StudyFlow puede mostrar tres tarjetas en una fila cuando hay espacio suficiente y colocarlas una debajo de otra cuando la ventana se estrecha. El contenido HTML permanece igual; lo que cambia es su presentación.

CSS · Primera media query
.modulos {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 16px;
}

@media (max-width: 700px) {
  .modulos {
    grid-template-columns: 1fr;
  }
}

En este ejemplo, la regla general distribuye las tarjetas en tres columnas. Cuando la anchura del viewport es de 700 px o menos, la media query sustituye esa distribución por una sola columna. No es necesario modificar el HTML ni utilizar JavaScript.

Sintaxis y funcionamiento

La sintaxis habitual utiliza @media, una condición entre paréntesis y un bloque de declaraciones CSS. Si la condición se cumple, las reglas incluidas participan en la cascada; si no se cumple, no se aplican.

CSS · Estructura básica
@media (max-width: 768px) {
  .menu {
    flex-direction: column;
  }
}
ElementoSignificado
@mediaInicia una regla condicional de CSS.
(max-width: 768px)Comprueba si la anchura del viewport es de 768 píxeles CSS o menos.
{ ... }Contiene las reglas que participan en la cascada cuando se cumple la condición.
.menuSelecciona el componente al que se quiere aplicar el cambio.

La condición max-width incluye el valor indicado: se cumple tanto a 768 px como a 767 px. Por su parte, min-width se cumple desde el valor indicado en adelante.

CSS · Comparación de condiciones
/* Se cumple hasta 768px, incluido */
@media (max-width: 768px) {
  .aviso { display: block; }
}

/* Se cumple desde 769px, incluido */
@media (min-width: 769px) {
  .aviso { display: none; }
}
⚠️ Atención

Las condiciones min-width y max-width se refieren aquí a la anchura del viewport, no a la anchura del elemento seleccionado. Para responder al tamaño de un contenedor concreto existen las container queries, que se estudiarán cuando corresponda.

Condiciones y operadores

Las media queries pueden evaluar distintas características. En diseño responsive, la más habitual es width, aunque también existen consultas relacionadas con la orientación o con las preferencias de las personas usuarias.

CondiciónQué evalúaEjemplo de uso
min-widthAnchura mínima del viewport.Activar una distribución con más columnas.
max-widthAnchura máxima del viewport.Simplificar un menú en espacios estrechos.
orientationRelación entre anchura y altura del viewport.Ajustar un componente en orientación horizontal.
prefers-reduced-motionPreferencia del usuario por reducir movimiento.Reducir animaciones no esenciales.
CSS · Combinar condiciones con and
@media (min-width: 600px) and (max-width: 999px) {
  .panel-lateral {
    width: 220px;
  }
}

El operador and exige que se cumplan ambas condiciones. En el ejemplo, la regla se aplica entre 600 y 999 px, ambos incluidos. También es posible separar consultas con una coma para expresar alternativas: basta con que se cumpla una de ellas.

CSS · Alternativas con coma
@media (max-width: 600px), (orientation: portrait) {
  .barra-herramientas {
    flex-wrap: wrap;
  }
}

En esta segunda consulta, la barra puede reorganizarse si el viewport tiene 600 px o menos o si su orientación es vertical. Conviene usar este tipo de condiciones cuando exista una necesidad concreta y no por añadir complejidad al CSS.

Sintaxis moderna de comparación

CSS también permite escribir consultas de rango con operadores de comparación. Por ejemplo, (width <= 700px) expresa la misma condición que (max-width: 700px). Ambas formas son válidas en navegadores modernos.

CSS · Sintaxis tradicional y moderna
/* Sintaxis tradicional */
@media (max-width: 700px) {
  .modulos { grid-template-columns: 1fr; }
}

/* Condición equivalente con sintaxis moderna */
@media (width <= 700px) {
  .modulos { grid-template-columns: 1fr; }
}

Estos dos bloques se muestran como alternativas equivalentes; no es necesario duplicarlos en una hoja de estilos real.

Puntos de ruptura

Un punto de ruptura o breakpoint es un valor a partir del cual decidimos modificar la presentación de la interfaz. Por ejemplo, cuando tres tarjetas ya no caben con una anchura legible, podemos pasar a dos columnas y, más adelante, a una.

Los valores de los breakpoints no son universales. No existe una anchura exacta que identifique a todos los móviles o a todas las tabletas. Deben elegirse observando cuándo el contenido empieza a necesitar otra distribución.

CSS · Tres distribuciones posibles
.modulos {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 16px;
}

@media (max-width: 900px) {
  .modulos {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (max-width: 600px) {
  .modulos {
    grid-template-columns: 1fr;
  }
}
Anchura del viewportDistribución resultante
Más de 900 pxTres columnas.
Más de 600 px y hasta 900 pxDos columnas.
600 px o menosUna columna.

En el ejemplo, 900 px y 600 px son decisiones de diseño, no categorías obligatorias de dispositivos. Podemos cambiarlos si las tarjetas contienen textos más largos o si el espacio disponible es distinto.

💻 Ejemplo DAW

Si en StudyFlow los títulos de los módulos comienzan a partirse de forma incómoda a 850 px, tiene sentido cambiar a dos columnas antes de llegar a ese ancho. La referencia debe ser el comportamiento del contenido, no una lista de modelos de teléfono.

Cascada y orden de las reglas

Las reglas incluidas en una media query no tienen prioridad automáticamente sobre las reglas generales. Siguen participando en la cascada CSS: importan el origen, la importancia, la especificidad y el orden de aparición.

Cuando dos reglas tienen la misma prioridad y especificidad, y ambas son aplicables, suele prevalecer la que aparece después. Por eso es importante ordenar de manera coherente las media queries.

CSS · Orden correcto de reglas
.tarjeta {
  padding: 24px;
}

/* Misma especificidad y aparece después */
@media (max-width: 600px) {
  .tarjeta {
    padding: 12px;
  }
}

Con 500 px de viewport, la tarjeta tendrá padding: 12px. Si se colocara el bloque general después de la media query, con la misma especificidad, podría volver a aplicarse 24px.

⚠️ Atención

Si utilizas varias condiciones max-width, recuerda que pueden cumplirse simultáneamente. Por ejemplo, a 500 px se cumplen tanto max-width: 900px como max-width: 600px. El orden de las reglas debe permitir que el diseño más estrecho prevalezca donde corresponda.

Buenas prácticas y errores frecuentes

  • Elegir breakpoints por el contenido: modifica la distribución cuando deje de ser cómoda, no porque un dispositivo tenga una anchura conocida.
  • Mantener una base flexible: combina las media queries con porcentajes, max-width y tamaños relativos vistos en el apartado 7.2.
  • Evitar reglas contradictorias: revisa el orden de los bloques y qué condiciones se cumplen al mismo tiempo.
  • No ocultar información esencial: adaptar la interfaz no debería impedir acceder a funciones importantes.
  • Probar anchuras intermedias: comprueba también los tamaños entre dos breakpoints, no solo los extremos.
📌 Idea clave

Las media queries permiten cambiar estilos de forma condicional. Los breakpoints son decisiones de diseño que deben responder a las necesidades del contenido y trabajar junto con las dimensiones flexibles.

💭 Piensa

En StudyFlow, las tres tarjetas se muestran correctamente a 1100 px, pero a 820 px sus textos quedan demasiado comprimidos y a 520 px dos columnas siguen siendo difíciles de leer. ¿Qué dos breakpoints propondrías y qué distribución aplicarías en cada intervalo? Explica por qué.

Ver una posible solución

Podemos establecer un breakpoint en 900px para pasar de tres a dos columnas y otro en 600px para pasar a una sola. Así, por encima de 900 px se muestran tres tarjetas, entre 601 y 900 px se muestran dos y a 600 px o menos se muestra una.

Estos valores son orientativos: lo importante es probar el contenido y ajustar los puntos de ruptura donde las tarjetas dejen de ser legibles.
