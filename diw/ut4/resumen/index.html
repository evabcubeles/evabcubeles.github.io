✏️ Resumen de la UT4

En esta unidad hemos estudiado cómo construir la estructura y organizar el contenido de una interfaz web mediante HTML, utilizando los elementos adecuados según el significado y la función de la información.

Este resumen reúne las ideas esenciales de los apartados 4.1 a 4.9 para que puedas utilizarlo como guía rápida de repaso de estructura, texto, enlaces, imágenes, tablas, formularios, semántica y validación HTML.

4.1 HTML y la estructura de una interfaz web

HTML describe la estructura y el significado del contenido de una página. CSS se ocupa principalmente de la presentación visual y JavaScript del comportamiento e interactividad.

Elemento Unidad que forma parte de un documento HTML y representa un tipo de contenido o estructura. Puede estar delimitado por etiquetas y contener texto u otros elementos.
EtiquetaMarca que identifica el tipo de elemento, como <p>, <a> o <main>.
AtributoAporta información adicional al elemento, como href, src, alt o id.
Estructura básica<!DOCTYPE html>, <html>, <head> y <body> forman la base del documento.
📌 Recuerda

HTML debe utilizarse para describir qué es cada contenido y cómo se organiza, no para decidir únicamente cómo queremos que se vea.

4.2 Texto y organización del contenido

El contenido textual debe organizarse con una jerarquía clara y con elementos que expresen correctamente su función.

📰Encabezados

<h1> a <h6> estructuran títulos y niveles de contenido.

📄Párrafos

<p> agrupa párrafos y <br> introduce un salto cuando realmente forma parte del contenido.

❗Énfasis

<strong> expresa importancia y <em> énfasis.

📋Listas

<ul>, <ol> y <dl> representan diferentes tipos de listas.

💻Otros elementos

<small>, <sub>, <sup>, <code> y <pre> describen contenidos específicos.

🧭Jerarquía

La estructura de encabezados y bloques debe reflejar la organización lógica del contenido.

⚠️ No confundas

La apariencia visual de un texto no determina su significado. No debemos elegir un encabezado, <strong> u otro elemento únicamente porque nos guste su estilo predeterminado.

4.3 Enlaces y navegación mediante HTML

El elemento <a> conecta páginas, secciones y otros recursos mediante el atributo href.

Rutas absolutasIdentifican un recurso mediante una dirección completa.
Rutas relativasLocalizan recursos tomando como referencia la ubicación del documento actual.
FragmentosUn enlace como href="#contacto" puede dirigirse a un elemento con id="contacto".
Otros destinosLos enlaces también pueden apuntar a archivos o utilizar esquemas como mailto: y tel:.
📌 Recuerda

Cuando target="_blank" abre un destino en una pestaña nueva, conviene acompañarlo de rel="noopener" o una relación equivalente adecuada.

4.4 Imágenes y contenido gráfico en HTML

HTML incorpora imágenes mediante <img>. En esta unidad nos centramos en su integración y significado; el tratamiento y optimización de recursos gráficos se estudiará en la UT8.

srcIndica la ruta del recurso gráfico.
alt Proporciona una alternativa textual adecuada a la función de la imagen cuando esta no es puramente decorativa.
DecorativasCuando una imagen es puramente decorativa, normalmente se utiliza alt="".
Figura<figure> y <figcaption> permiten tratar un contenido y su leyenda como una unidad.
⚠️ Importante

alt="" no es lo mismo que omitir el atributo alt: el valor vacío comunica explícitamente que la imagen es decorativa.

4.5 Tablas HTML

Las tablas se utilizan cuando existe una relación significativa entre datos organizados en filas y columnas, no como herramienta de maquetación.

🗂️Estructura

<table> contiene filas <tr> y celdas de datos <td>.

🏷️Encabezados

<th> identifica encabezados y scope puede expresar su relación con filas o columnas.

🧩Organización

<thead>, <tbody> y <tfoot> estructuran grupos de filas cuando resulta útil.

📝Título

<caption> proporciona el título o descripción identificativa de la tabla.

↔️Combinación

colspan y rowspan permiten que una celda abarque varias columnas o filas.

🚫No maquetar

La distribución visual de la interfaz debe resolverse con CSS, no con tablas.

4.6 Formularios HTML

Los formularios permiten recoger datos mediante controles que deben estar correctamente identificados y organizados.

<form>Define el formulario y puede establecer destino y método mediante action y method.
<label>Describe un control y debe asociarse correctamente con él; placeholder no sustituye a una etiqueta.
Controles<input>, <select>, <textarea> y <button> permiten introducir o enviar diferentes tipos de información.
Agrupación<fieldset> y <legend> permiten agrupar controles relacionados.
⚠️ Recuerda

La validación incorporada en HTML mejora la experiencia, pero no sustituye la validación que debe realizar el servidor. Además, utilizar POST no cifra por sí mismo la información: la protección de la comunicación depende, entre otros aspectos, de HTTPS.

4.7 HTML semántico y estructura de una página

HTML semántico consiste en seleccionar elementos que describen la función del contenido dentro del documento.

🔝<header>

Contenido introductorio o cabecera de una página o sección.

🧭<nav>

Sección que agrupa enlaces de navegación importantes.

📄<main>

Contenido principal de la página.

📑<section>

Sección temática del documento, normalmente identificada por un encabezado.

📰<article>

Unidad independiente o autocontenida que puede tener sentido por sí misma.

↗️<aside>

Contenido relacionado de forma indirecta o complementaria con el contenido cercano.

🔻<footer>

Pie de una página o sección.

📦<div>

Contenedor genérico válido cuando no existe un elemento semántico más apropiado.

📌 Recuerda

Semántica no significa utilizar el mayor número posible de etiquetas diferentes, sino elegir el elemento que mejor representa la función real del contenido.

4.8 Otros elementos semánticos y de contenido

HTML dispone de elementos especializados que permiten describir con mayor precisión determinados contenidos.

<figure> y <figcaption>Representan una unidad autocontenida y, cuando procede, su leyenda.
<details> y <summary>Crean un bloque desplegable de forma nativa.
<time>Representa fechas u horas; datetime proporciona una representación procesable.
<mark>Marca un fragmento relevante en el contexto actual, por ejemplo una coincidencia de búsqueda.
Citas<blockquote>, <q> y <cite> describen diferentes aspectos relacionados con citas y obras.
<abbr> y <address>Representan abreviaturas e información de contacto vinculada al contenido correspondiente.

4.9 Buenas prácticas y validación del HTML

Un documento no es correcto simplemente porque el navegador consiga mostrarlo. Debemos escribir código legible, coherente y válido, y utilizar herramientas de comprobación durante el desarrollo.

EstructuraAnidar correctamente los elementos, respetar sus reglas y mantener identificadores id únicos.
LegibilidadIndentar y mantener criterios de formato coherentes facilita comprender y mantener el código.
SeparaciónHTML describe contenido y estructura; CSS se encarga de la presentación visual.
ValidaciónHerramientas como Nu Html Checker ayudan a detectar errores y advertencias en el marcado.
⚠️ Elementos antiguos

<frame> y <frameset> son obsoletos. <iframe> es un elemento diferente que sigue formando parte de HTML para incrustar determinados contenidos cuando corresponde.

📌 Recuerda

Un documento válido no es automáticamente accesible, usable ni adecuado para sus usuarios. La validación HTML es una comprobación importante, pero no sustituye otras evaluaciones.

Ideas clave de la UT4

📌 Si tuvieras que recordar solo estas ideas…
  • HTML estructura y da significado al contenido; CSS define principalmente su presentación y JavaScript su comportamiento e interactividad.
  • Los elementos deben elegirse por lo que representa su contenido, no por su apariencia predeterminada.
  • Una buena jerarquía de encabezados, párrafos y listas facilita organizar el contenido de forma lógica.
  • Los enlaces utilizan <a> y href; comprender las rutas absolutas, relativas y los fragmentos es esencial para conectar recursos.
  • Las imágenes deben incorporarse con un alt adecuado según su función; una imagen decorativa puede utilizar alt="".
  • Las tablas son para datos tabulares, no para distribuir visualmente una página.
  • Los formularios deben utilizar controles y etiquetas correctamente asociados, y la validación del navegador no sustituye la validación del servidor.
  • Elementos como <header>, <nav>, <main>, <section>, <article>, <aside> y <footer> ayudan a expresar la estructura semántica de una página.
  • Los elementos semánticos especializados deben utilizarse cuando describen realmente el contenido, no para acumular etiquetas.
  • Un HTML de calidad debe ser válido, legible, coherente y mantenible; validar ayuda a detectar problemas, pero no garantiza por sí solo accesibilidad o usabilidad.
