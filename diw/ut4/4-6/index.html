4.6 Formularios HTML

Los formularios son uno de los principales mecanismos de interacción entre una persona y una aplicación web. Permiten introducir y enviar información mediante campos de texto, listas, botones, casillas de verificación y otros controles.

En HTML, un formulario no se limita a colocar campos en una página. Debemos definir correctamente qué información solicita cada control, cómo se identifica y cómo se envían sus datos. En este apartado estudiaremos la estructura HTML de los formularios; su presentación visual se trabajará posteriormente con CSS y la validación o tratamiento avanzado de los datos se abordará en los módulos y unidades correspondientes.

📌 Importante

Un formulario debe construirse con elementos HTML que expresen la función de cada control. La apariencia visual no debe sustituir a una estructura correcta.

El elemento <form>

El elemento <form> agrupa los controles que forman parte de un formulario y permite indicar cómo se enviarán los datos. Dentro de él podemos incluir etiquetas, campos de entrada, listas, áreas de texto, botones y otros elementos.

HTML 
<form action="/registro" method="post">
  <label for="nombre">Nombre:</label>
  <input type="text" id="nombre" name="nombre">

  <button type="submit">Enviar</button>
</form>

En este ejemplo, action indica el destino al que se enviarán los datos y method establece el método HTTP utilizado. El atributo name del control identifica el dato que se enviará.

⚠️ Atención

El atributo id identifica un elemento dentro del documento, mientras que name identifica el dato durante el envío del formulario. Aunque en muchos ejemplos tienen el mismo valor, cumplen funciones diferentes.

Etiquetas y asociación con los controles

El elemento <label> permite proporcionar una etiqueta de texto a un control. Una forma habitual de asociarlos consiste en utilizar el atributo for de <label> con el mismo valor que el id del control.

HTML 
<label for="correo">Correo electrónico:</label>
<input type="email" id="correo" name="correo">

Al activar la etiqueta, el navegador puede trasladar el foco al control asociado. Además, esta relación expresa de forma explícita qué texto describe a cada campo.

📌 Importante

El atributo placeholder puede mostrar una pista o un ejemplo dentro de un campo, pero no debe utilizarse como sustituto de una etiqueta. La etiqueta identifica el dato solicitado; el placeholder aporta información complementaria.

Campos de entrada con <input>

El elemento <input> permite crear distintos tipos de controles. Su comportamiento depende principalmente del valor del atributo type.

Tipo Uso habitual Ejemplo
textTexto breveNombre o ciudad
emailDirección de correo electrónicoalumno@ejemplo.com
passwordTexto que no se muestra directamente en pantallaContraseña
numberValores numéricosNúmero de unidades
dateFechaFecha de entrega
timeHoraHora de una cita
urlDirección webURL de un proyecto
HTML 
<label for="usuario">Usuario:</label>
<input type="text" id="usuario" name="usuario" required>

<label for="email">Correo:</label>
<input type="email" id="email" name="email">

<label for="fecha">Fecha de entrega:</label>
<input type="date" id="fecha" name="fecha">

Elegir el tipo de campo adecuado permite al navegador conocer mejor qué dato se espera y ofrecer controles adaptados al dispositivo. Algunos tipos también incorporan comprobaciones básicas del formato.

Casillas de verificación y botones de opción

Las casillas de verificación (checkbox) se utilizan cuando pueden seleccionarse varias opciones de forma independiente.

HTML 
<input type="checkbox" id="html" name="tecnologias" value="html">
<label for="html">HTML</label>

<input type="checkbox" id="css" name="tecnologias" value="css">
<label for="css">CSS</label>

Los botones de opción (radio) se utilizan cuando debe elegirse una sola opción dentro de un conjunto. Para que el navegador los trate como un mismo grupo deben compartir el mismo atributo name.

HTML 
<input type="radio" id="presencial" name="modalidad" value="presencial">
<label for="presencial">Presencial</label>

<input type="radio" id="distancia" name="modalidad" value="distancia">
<label for="distancia">A distancia</label>
📌 Importante

En controles checkbox y radio, el atributo value determina el valor asociado a la opción cuando esta se envía.

Listas desplegables

El elemento <select> permite ofrecer una lista de opciones. Cada alternativa se representa mediante <option>, cuyo atributo value puede indicar el valor que se enviará.

HTML 
<label for="modulo">Módulo:</label>
<select id="modulo" name="modulo">
  <option value="">Selecciona un módulo</option>
  <option value="diw">Diseño de Interfaces Web</option>
  <option value="dwec">Desarrollo Web en Entorno Cliente</option>
</select>

También existen atributos como multiple, que permiten seleccionar más de una opción cuando el contexto del formulario lo requiere.

Áreas de texto

Cuando necesitamos introducir texto de varias líneas utilizamos <textarea>. A diferencia de <input>, este elemento dispone de etiqueta de apertura y cierre.

HTML 
<label for="comentario">Comentario:</label>
<textarea id="comentario" name="comentario" rows="5" cols="40"></textarea>

Los atributos rows y cols permiten proporcionar un tamaño inicial al control. Su presentación final puede ajustarse posteriormente mediante CSS.

Botones

El elemento <button> crea un botón y permite incluir contenido textual en su interior. El atributo type determina su comportamiento.

Valor de typeFunción
submitEnvía el formulario.
resetRestablece los controles a sus valores iniciales.
buttonNo realiza una acción de formulario por sí mismo; puede utilizarse con JavaScript.
HTML 
<button type="submit">Guardar</button>
<button type="reset">Restablecer</button>
<button type="button">Mostrar ayuda</button>
⚠️ Atención

Dentro de un formulario, un <button> sin atributo type actúa normalmente como botón de envío. Es una buena práctica indicar el tipo de forma explícita para evitar comportamientos inesperados.

Selección de archivos

El tipo file permite que la persona usuaria seleccione uno o varios archivos de su dispositivo. El navegador controla la interfaz concreta utilizada para realizar la selección.

HTML 
<form action="/entrega" method="post" enctype="multipart/form-data">
  <label for="archivo">Adjunta tu proyecto:</label>
  <input type="file" id="archivo" name="archivo">

  <button type="submit">Enviar entrega</button>
</form>

Cuando un formulario envía archivos mediante POST, debe utilizar enctype="multipart/form-data" para codificar correctamente ese contenido.

Agrupación de campos

Los elementos <fieldset> y <legend> permiten agrupar controles relacionados y proporcionar un título al conjunto. Son especialmente útiles cuando varias opciones forman una única pregunta o bloque lógico.

HTML 
<fieldset>
  <legend>Modalidad preferida</legend>

  <input type="radio" id="modalidad-presencial"
         name="modalidad" value="presencial">
  <label for="modalidad-presencial">Presencial</label>

  <input type="radio" id="modalidad-distancia"
         name="modalidad" value="distancia">
  <label for="modalidad-distancia">A distancia</label>
</fieldset>

Atributos básicos de los formularios

Los formularios y sus controles disponen de numerosos atributos. En esta unidad nos centraremos en los más habituales para construir una estructura HTML clara y funcional.

AtributoFunción básica
actionIndica el destino que procesará los datos enviados.
methodIndica el método HTTP de envío, habitualmente GET o POST.
nameIdentifica el dato de un control durante el envío.
valueDefine el valor asociado a determinados controles.
requiredIndica que un control debe completarse antes del envío.
placeholderMuestra una pista breve dentro de determinados campos.
autocompletePermite proporcionar indicaciones sobre el autocompletado del campo.
disabledDesactiva un control y evita su interacción y envío.
readonlyImpide modificar determinados controles, pero conserva su valor para el envío.

GET y POST

Con method="get", los datos enviados se incorporan normalmente a la URL como parámetros de consulta. Es apropiado, por ejemplo, para búsquedas o filtros que no modifican información en el servidor. Con method="post", los datos se incluyen en el cuerpo de la petición y suele utilizarse para operaciones que envían información para ser procesada o que pueden producir cambios.

⚠️ Atención

Utilizar POST no cifra automáticamente los datos ni convierte un formulario en seguro. La protección de la comunicación depende, entre otros aspectos, del uso de HTTPS y de las medidas implementadas en el servidor.

Validación básica del navegador

HTML incorpora mecanismos de validación básica. Atributos como required, min, max, minlength, maxlength o pattern, junto con tipos como email, permiten expresar determinadas restricciones.

HTML 
<label for="nota">Nota (0-10):</label>
<input type="number" id="nota" name="nota"
       min="0" max="10" required>
📌 Importante

La validación realizada por el navegador mejora la interacción, pero no sustituye a la validación de los datos en el servidor. Los datos recibidos por una aplicación deben comprobarse siempre antes de utilizarlos.

💻 Ejemplo DAW: formulario de entrega de StudyFlow

En una plataforma educativa podríamos utilizar un formulario para que el alumnado indique el título de una actividad, seleccione el módulo, añada un comentario y adjunte el archivo de la entrega. Cada control tendría una etiqueta y un name adecuados, mientras que el formulario utilizaría method="post" y multipart/form-data al incluir un archivo.

💭 Piensa

Un formulario muestra dentro de un campo el texto Introduce tu correo mediante placeholder, pero no incluye ningún <label>. Además, el campo tiene id="correo" pero no dispone de atributo name.

¿Qué dos problemas observas y cómo los corregirías?

Ver una posible solución

El placeholder no sustituye a la etiqueta. Deberíamos incorporar un <label for="correo"> asociado al id="correo".

Además, si queremos que el valor del campo forme parte de los datos enviados, debemos asignarle un atributo name, por ejemplo name="correo".
