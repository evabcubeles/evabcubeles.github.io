4.7 HTML semántico y estructura de una página

Una página web no es únicamente una sucesión de elementos colocados unos detrás de otros. Sus contenidos desempeñan funciones diferentes: algunos forman la navegación, otros constituyen el contenido principal, agrupan una parte temática o aportan información complementaria.

HTML dispone de elementos que permiten describir esas funciones mediante la propia estructura del documento. Elegirlos correctamente hace que el código exprese mejor qué representa cada parte de la interfaz.

📌 Importante

La semántica describe el significado y la función del contenido, no su apariencia ni su posición visual. Un elemento no se convierte en <aside> por estar a la derecha ni en <header> por aparecer en la parte superior.

Qué significa HTML semántico

Un elemento es semántico cuando su nombre aporta información sobre el papel que desempeña su contenido. Por ejemplo, <nav> identifica una zona de navegación y <main> el contenido principal del documento.

Esto contrasta con elementos genéricos como <div>, que permiten agrupar contenido pero no indican por sí mismos qué función cumple ese grupo.

HTML
<div class="menu-principal">...</div>

<nav>...</nav>

Ambas estructuras pueden contener enlaces y recibir estilos mediante CSS, pero la segunda expresa directamente que ese bloque corresponde a una zona de navegación.

💻 Ejemplo DAW

En StudyFlow podemos distinguir la cabecera de la aplicación, la navegación principal, el contenido de la asignatura, información complementaria y el pie. HTML semántico permite representar esas funciones sin depender de cómo se distribuyan después mediante CSS.

<header>

El elemento <header> representa contenido introductorio o de cabecera de una página o de una sección. Puede contener, por ejemplo, un título, un logotipo, información introductoria o elementos relacionados con la identificación del contenido.

HTML
<header>
  <h1>StudyFlow</h1>
  <p>Organiza tus módulos y entregas</p>
</header>
⚠️ Atención

<header> no significa simplemente «parte superior de la pantalla». Además, un documento puede contener varios <header>: por ejemplo, uno general y otros dentro de determinados <article> o <section>.

<nav>

<nav> representa una sección destinada a proporcionar enlaces de navegación. Es apropiado para bloques importantes como el menú principal, la navegación entre secciones o un índice de contenidos.

HTML
<nav aria-label="Navegación principal">
  <a href="/inicio">Inicio</a>
  <a href="/modulos">Módulos</a>
  <a href="/entregas">Entregas</a>
</nav>

No es necesario envolver en <nav> cualquier conjunto pequeño de enlaces. Debe reservarse para bloques cuya función de navegación sea relevante dentro de la página.

<main>

El elemento <main> identifica el contenido principal del documento: aquello que constituye su finalidad central y que es específico de esa página.

Elementos repetidos entre páginas, como la navegación global o un pie general, normalmente quedan fuera de <main>.

HTML
<main>
  <h1>Entregas pendientes</h1>
  <p>Consulta las actividades que todavía debes entregar.</p>
</main>
📌 Importante

En la estructura habitual de una página debe existir un único <main> visible que represente su contenido principal. <main> no debe utilizarse como un contenedor genérico para cualquier bloque.

<section>

<section> representa una sección temática del documento. Se utiliza cuando un conjunto de contenidos forma una unidad con un propósito reconocible dentro de la página y, normalmente, puede identificarse mediante un encabezado.

HTML
<section>
  <h2>Próximas entregas</h2>
  <p>Consulta las actividades previstas para esta semana.</p>
</section>
⚠️ Atención

No debemos sustituir automáticamente cada <div> por un <section>. Si el bloque solo existe para aplicar estilos o facilitar la maquetación y no constituye una sección temática, un contenedor genérico puede ser más adecuado.

<article>

<article> representa contenido que forma una unidad independiente o autocontenida dentro del documento y que podría tener sentido por sí mismo fuera del contexto inmediato de la página. Puede utilizarse, por ejemplo, para una noticia, una publicación, una entrada de blog, una reseña o una tarjeta de contenido con identidad propia.

HTML
<article>
  <h2>Proyecto de interfaz responsive</h2>
  <p>Diseña y desarrolla la interfaz propuesta para el proyecto.</p>
</article>

La diferencia con <section> no depende de su aspecto. Como orientación, podemos preguntarnos si el contenido constituye una pieza con identidad propia. Si simplemente organiza una parte temática de un contenido mayor, <section> suele describir mejor su función.

<aside>

<aside> representa contenido relacionado de forma indirecta o complementaria con el contenido que lo rodea. Puede contener información adicional, recursos relacionados, aclaraciones o bloques complementarios.

HTML
<aside>
  <h2>Recursos relacionados</h2>
  <ul>
    <li><a href="guia-html.html">Guía de HTML</a></li>
    <li><a href="ejemplos.html">Ejemplos resueltos</a></li>
  </ul>
</aside>
⚠️ Atención

<aside> no significa «barra lateral». Puede mostrarse a la derecha, a la izquierda o en cualquier otra posición mediante CSS. Lo que determina su uso es la relación semántica de su contenido, no su ubicación visual.

<footer>

<footer> representa el pie de una página o de una sección. Suele contener información relacionada con el contenido al que pertenece, como autoría, derechos, enlaces relacionados o datos complementarios.

HTML
<footer>
  <p>StudyFlow · Proyecto de 2.º DAW</p>
</footer>

Al igual que ocurre con <header>, puede haber más de un <footer> en un documento cuando diferentes secciones o artículos disponen de su propio pie.

<div> y elementos semánticos

El elemento <div> es un contenedor genérico. No está obsoleto ni es incorrecto utilizarlo: resulta adecuado cuando necesitamos agrupar elementos y no existe un elemento semántico que describa mejor la función de ese grupo.

Situación Elemento orientativo
Contenido introductorio o de cabecera <header>
Navegación principal <nav>
Contenido principal de la página <main>
Sección temática <section>
Pieza de contenido autocontenida <article>
Contenido complementario <aside>
Pie de una página o sección <footer>
Agrupación sin significado específico <div>
📌 Idea clave

No se trata de eliminar los <div>, sino de utilizar un elemento más específico cuando su significado corresponde realmente al contenido.

Cómo elegir el elemento adecuado

Para decidir qué elemento utilizar debemos pensar primero en la función del contenido y solo después en su presentación. Algunas preguntas pueden orientarnos:

  • ¿Es el contenido principal y específico de esta página? → <main>.
  • ¿Su finalidad principal es proporcionar navegación? → <nav>.
  • ¿Forma una sección temática dentro de un contenido mayor? → <section>.
  • ¿Es una pieza de contenido con identidad propia? → <article>.
  • ¿Es información complementaria respecto al contenido principal? → <aside>.
  • ¿Es contenido introductorio o un pie de una página o sección? → <header> o <footer>.
  • ¿Solo necesitamos agrupar elementos y ninguna semántica específica encaja? → <div>.
HTML · Estructura de StudyFlow
<header>
  <h1>StudyFlow</h1>
</header>

<nav aria-label="Navegación principal">
  <a href="/modulos">Módulos</a>
  <a href="/entregas">Entregas</a>
</nav>

<main>
  <section>
    <h2>Próximas entregas</h2>

    <article>
      <h3>Prototipo de interfaz</h3>
      <p>Entrega: 25 de octubre</p>
    </article>
  </section>

  <aside>
    <h2>Recursos relacionados</h2>
    <p>Consulta la guía de la actividad.</p>
  </aside>
</main>

<footer>
  <p>StudyFlow · 2.º DAW</p>
</footer>
💻 Ejemplo DAW

La estructura anterior no determina si el <aside> aparecerá a la derecha ni si los <article> se mostrarán como tarjetas. Esas decisiones corresponden a CSS. HTML describe qué es cada bloque; CSS decidirá cómo se presenta.

💭 Piensa

Un alumno crea toda una página utilizando únicamente elementos <div>: uno para la cabecera, otro para el menú, otro para el contenido principal y otro para el pie. La página se visualiza correctamente después de aplicar CSS.

¿Es suficiente que visualmente funcione? ¿Qué elementos HTML podrían expresar mejor la función de esos bloques?

Ver una posible solución

Que la página se visualice correctamente no significa que su estructura HTML exprese adecuadamente la función de cada bloque. Aunque <div> es válido como contenedor genérico, en este caso existen elementos semánticos más específicos.

Podríamos utilizar <header> para la cabecera, <nav> para el menú de navegación, <main> para el contenido principal y <footer> para el pie. Los <div> seguirían siendo apropiados para agrupaciones que no tengan un significado semántico específico.
