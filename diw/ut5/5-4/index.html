5.4 Cascada, especificidad y herencia

En una misma página es habitual que varias reglas CSS puedan afectar al mismo elemento y, en ocasiones, intenten asignar valores diferentes a una misma propiedad. El navegador necesita entonces decidir qué declaración debe aplicar.

Para comprender ese proceso debemos distinguir tres conceptos fundamentales: cascada, especificidad y herencia. Están relacionados, pero no significan lo mismo.

📌 Importante

La cascada determina qué declaración gana cuando existen declaraciones que compiten por una misma propiedad. La especificidad es uno de los criterios que utiliza esa cascada. La herencia, en cambio, permite que determinadas propiedades reciban el valor calculado del elemento padre.

La cascada en CSS

La palabra Cascading de Cascading Style Sheets hace referencia al mecanismo que utiliza CSS para resolver conflictos entre declaraciones. Un elemento puede recibir estilos procedentes de distintas reglas y el navegador debe determinar cuál prevalece para cada propiedad.

HTML
<p class="aviso">Entrega disponible hasta el viernes.</p>
CSS
p {
  color: #4b5563;
}

.aviso {
  color: #b42318;
}

Las dos reglas coinciden con el mismo párrafo y ambas establecen la propiedad color. En este caso prevalece .aviso porque su selector tiene mayor especificidad que el selector de tipo p.

De forma simplificada, para las hojas de estilo habituales que escribiremos en nuestros proyectos, cuando varias declaraciones aplicables compiten por una propiedad debemos fijarnos especialmente en la importancia de la declaración, la especificidad y el orden en el código.

⚠️ Atención

No debemos interpretar la cascada como “la última regla siempre gana”. Una declaración posterior solo puede imponerse por el orden cuando las declaraciones que compiten han llegado empatadas a ese criterio. Antes pueden intervenir otros factores, como !important o la especificidad.

Especificidad de los selectores

La especificidad expresa qué selector es más concreto. Cuando las declaraciones que compiten tienen la misma importancia, una declaración asociada a un selector más específico puede prevalecer sobre otra asociada a un selector menos específico.

Para empezar a razonar sobre ella podemos comparar los selectores mediante estas categorías, de mayor a menor peso:

CategoríaEjemplosPeso relativo
Estilos en líneastyle="color: ..."Muy alto dentro de los estilos normales de autor.
Identificadores#cabeceraMayor que clases, atributos y tipos.
Clases, atributos y pseudoclases.tarjeta, [required], :hoverMayor que los selectores de tipo y pseudoelementos.
Tipos y pseudoelementosp, article, ::beforeMenor que las categorías anteriores.

Una forma didáctica de representar la especificidad de un selector es mediante tres componentes: ID – clase – tipo. Se cuenta cuántos identificadores, cuántas clases/atributos/ pseudoclases y cuántos tipos/pseudoelementos aparecen en el selector. Los componentes se comparan de izquierda a derecha; no deben interpretarse como una suma aritmética.

SelectorRepresentaciónExplicación
p0-0-1Un selector de tipo.
.aviso0-1-0Una clase.
article .aviso0-1-1Una clase y un selector de tipo.
#panel .aviso1-1-0Un identificador y una clase.
CSS
p {
  color: #4b5563;
}

.mensaje {
  color: #1f6f43;
}

#aviso-principal {
  color: #b42318;
}

Si un mismo párrafo tuviera la clase mensaje y el identificador aviso-principal, las tres reglas podrían coincidir, pero la regla con #aviso-principal tendría mayor especificidad.

📌 Idea clave

La especificidad pertenece al selector completo. No debemos pensar simplemente que “un ID siempre gana” sin considerar antes el resto de criterios de la cascada. Además, utilizar selectores innecesariamente específicos dificulta después la reutilización y el mantenimiento de los estilos.

Orden de las declaraciones

Cuando dos declaraciones que compiten tienen la misma importancia y la misma especificidad, el orden permite resolver el empate: prevalece la declaración que aparece después en el orden de la cascada.

CSS
.tarjeta {
  border-color: #d8dde3;
}

.tarjeta {
  border-color: #1f6f43;
}

Ambas reglas utilizan exactamente el mismo selector, por lo que tienen la misma especificidad. En este caso el borde será #1f6f43 porque esa declaración aparece después.

El orden también importa cuando utilizamos varias hojas de estilo. Si las declaraciones llegan empatadas a este criterio, una regla incluida posteriormente puede sustituir el valor de una regla equivalente cargada antes.

⚠️ Atención

Colocar una regla al final del archivo no garantiza que vaya a sobrescribir cualquier estilo anterior. Si la regla anterior tiene mayor prioridad en la cascada o mayor especificidad, cambiar únicamente el orden puede no ser suficiente.

Herencia de propiedades

La herencia es un mecanismo distinto de la cascada. Algunas propiedades pueden transmitir su valor calculado desde un elemento padre a sus descendientes cuando estos no tienen establecido otro valor aplicable para esa propiedad.

HTML
<section class="panel">
  <h2>Próximas entregas</h2>
  <p>Consulta las actividades pendientes.</p>
</section>
CSS
.panel {
  color: #374151;
  font-family: Arial, sans-serif;
}

Propiedades relacionadas con el texto, como color o font-family, suelen heredarse. Por ello el título y el párrafo pueden recibir esos valores a partir de .panel sin repetir las declaraciones en cada elemento.

Otras propiedades, especialmente muchas relacionadas con la caja y la disposición de los elementos, no se heredan de forma predeterminada. Por ejemplo, asignar un border al elemento padre no hace que todos sus hijos reciban ese mismo borde.

ValorComportamiento
inheritFuerza a la propiedad a tomar el valor calculado del elemento padre.
initialUtiliza el valor inicial definido para esa propiedad.
unsetActúa como inherit si la propiedad se hereda normalmente y como initial si no se hereda.
CSS
.panel {
  color: #374151;
}

.panel a {
  color: inherit;
}
⚠️ Atención

Que una propiedad sea heredable no significa que el valor del padre vaya a imponerse siempre. Si el elemento hijo recibe una declaración aplicable para esa propiedad, la cascada determinará el valor que finalmente le corresponde.

Uso de !important

CSS permite marcar una declaración con !important para aumentar su prioridad dentro de la cascada. Se escribe después del valor y antes del punto y coma.

CSS
.aviso {
  color: #b42318 !important;
}

Una declaración importante tiene prioridad sobre las declaraciones normales del mismo origen. Si varias declaraciones importantes compiten entre sí, todavía deben resolverse mediante los demás criterios de la cascada, entre ellos la especificidad y el orden.

⚠️ Atención

No utilices !important como solución habitual para conseguir que “un estilo funcione”. Su abuso dificulta comprender por qué se aplica cada regla y puede provocar una cadena de declaraciones !important cada vez más difíciles de sobrescribir. Es preferible revisar primero los selectores, la especificidad y el orden de las reglas.

💻 Ejemplo DAW

Si una tarjeta de StudyFlow no muestra el color esperado, antes de añadir !important conviene inspeccionar el elemento con las herramientas de desarrollo del navegador. Allí podremos comprobar qué reglas coinciden, cuáles han quedado sobrescritas y qué declaración está determinando el valor final.

💭 Piensa

Observa estas reglas CSS aplicadas al mismo elemento:

HTML
<p id="mensaje" class="aviso">Entrega pendiente.</p>
CSS
p {
  color: #4b5563;
}

.aviso {
  color: #1f6f43;
}

#mensaje {
  color: #b42318;
}

¿Qué color se aplicará al texto? ¿Cambiaría el resultado si moviéramos la regla p al final de la hoja de estilos?

Ver solución

Se aplicará #b42318, correspondiente a #mensaje, porque el selector de identificador tiene mayor especificidad que el selector de clase y el selector de tipo. Mover la regla p al final no cambiaría el resultado: el orden solo resuelve el empate cuando las declaraciones que compiten tienen la misma prioridad y especificidad.
